## 阅读与审阅结论

原文的方向是：**审核绑定具体输入，但审核不产生新的业务权限；后续每个消费入口均须验证固定资源与当前授权。** 这一主线保留，不改为“模型说 approved 就可以启动”。[^P03]

需要补全的不是一个 `approved` 字段，而是以下可以独立验证的事实：

```text
主会话提交了哪个决定？
    ↓
调度器是否完整登记了这个决定及其输入？
    ↓
它是否仍是该审核范围的当前决定，且未被撤销？
    ↓
固定资源、当前绑定、环境和前置条件是否一致？
    ↓
此主体是否仍被允许执行这一动作，预算和调度条件是否成立？
    ↓
是否只为这一次转换产生了可追踪、不可重复派发的准入记录？
```

| 原文已经确立 | 本版补齐的实现缺口 | 不应由补充内容暗示的能力 |
|---|---|---|
| 调度器登记不可变审核 | 字段 Schema、登记幂等、文件与事务提交边界 | JSON 中的 reviewer 字段是真实身份凭据 |
| 新记录只追加替代关系 | 稳定审核范围、head generation、比较并更新（CAS） | 同时存在两个“当前通过”也可按时间随意选择 |
| 通用 `input_refs` | 从受信提取器生成完整闭包、资源类别基数、反向索引 | 调用者少报依赖就可以缩小审核范围 |
| 配置语义与环境分别锁定 | `exact` 环境锁、当前资源绑定代数、准入再次核验 | 相同配置哈希可以永久复用任意机器环境 |
| 业务授权独立 | 动作交集、撤销 epoch、未知授权拒绝 | 审核登记自动批准新权限或费用 |
| prepare/run 共用校验 | 统一接口、检查次序、消费回执和在途处理 | prepare 通过即获得无限期 run 通行证 |
| 崩溃后只消费完整记录 | 孤儿文件、提交后响应丢失、索引恢复和回退流程 | 目录中出现一个通过文件就代表登记成功 |

**来源标记约定**：标注“原文保留”的内容继承原文；“新增建议”“参考实现”是本次补充；R 编号脚注为外部官方技术依据；测试数据统一标记 `fixture_only` 或明确称为合成样例。本文没有实际项目源码取证结论。

## 1. 目标与非目标

### 1.1 目标（原文保留并细化）

把主模型审核结论绑定到具体待审对象、合同双文件、规则、配置、检查、基线和必要环境证据；使审核后的相关输入漂移可以在发布、prepare、run 和其他受影响转换前被拒绝。提供通用审核基础，后续草稿、插件锁和检查定义通过 `ResourceRef` 接入，不让 03 导入插件执行代码。[^P03]

完成 03 的最低交付应包括：可解释的审核记录；可靠区分已提交与未提交内容的账本；统一校验接口；可追踪的替代与撤销；对相关输入精确失效的算法；正反例、并发和恢复证据。真实 04/05 尚未接线时，使用明确标记的公共环境 fixture，不伪造实测值。

### 1.2 非目标（原文保留）

不替代现有 G0–G6、固定候选验收、独立复审或业务设计判断。不改变现有 attempt、verdict 和 integration 的语义。不通过文件字段、同账户命令或模型自述提供密码学身份认证，不宣称操作系统隔离。

审核通过不扩大授权；已有授权不表示已审核。主模型已有授权且所有前置条件成立时可正常推进，不因每写一条审核记录再次询问用户。确实缺少的授权应由原有授权流程解决，不能由登记接口自批。

### 1.3 安全不变量（新增建议）

| 编号 | 必须成立的约束 |
|---|---|
| I03-01 | 一条记录只表达当时对固定对象的决定，不表达永久可执行状态。 |
| I03-02 | 有效审核、业务授权、当前策略、预算和调度状态必须同时满足；任一未知不得补成通过。 |
| I03-03 | 每个稳定审核范围最多有一个当前 head；非通过的新决定也会阻止旧通过决定继续用于新动作。 |
| I03-04 | 记录、替代事实、撤销事实和历史输入只追加，不回填已审核合同，不修改旧 verdict。 |
| I03-05 | 同一幂等键不能关联不同请求；原响应丢失后的重试只找回原登记结果，不产生第二次审核或运行。 |
| I03-06 | 校验必须覆盖实际使用的输入闭包，不能信任 planner 提交的“相关文件清单”。 |
| I03-07 | 原始字节完整性、当前绑定是否仍被允许、环境实际匹配是三类不同检查。 |
| I03-08 | 当前授权撤销优先于历史允许；旧锁不能冻结已撤销的权限。 |
| I03-09 | `prepare` 的成功、审核文件存在、run 退出 0、verdict PASS、INTEGRATED 互不等价。 |
| I03-10 | “准入已提交”与“进程确已创建”分开记录；未知启动结果不得直接重放。 |
| I03-11 | 无关 profile、其他任务的事件或进度游标变化不应被当作当前审核的语义漂移。 |
| I03-12 | 同账户无隔离环境只能报告流程控制能力，不能把同样可被写入的哈希、SQL 触发器或文件权限称为防篡改根。 |

### 1.4 威胁与信任边界

本模块应防止误用、普通 planner/executor 从受支持入口绕过审核、输入版本串用、并发重复登记、故障恢复误批准以及当前策略变化未被检查。对于拥有相同操作系统账户、可任意改调度器或数据库的进程，这些控制不能提供强隔离；对此不作超出原文的保证。

需要更强保证时，应单独设计受保护服务账户、明确认证的 IPC、操作系统权限隔离或外部签名/不可篡改记录服务，并完成专门验收。给 JSON 增加一个 `signature` 字段不是已经实现上述能力；密钥的持有、验证和撤销必须有独立信任根。

## 2. 依赖与输入输出

### 2.1 输入、来源与必需性

| 输入 | 可信提供方 | 03 的检查 | 缺失时 |
|---|---|---|---|
| 主模型审阅决定 | supervisor 受控提交上下文 | 来源与登记权限、对象、结论、范围、理由 | 不生成正式通过记录 |
| 待审对象 `subject_ref` | 01 资源解析器及对象所属模块 | 家族、版本、定位、完整字节哈希 | 拒绝登记或消费 |
| 合同 Markdown/JSON | 合同解析器 | 两文件均锁定；共同字段一致；范围与版本合法 | 不允许只审一个文件继续 |
| 配置语义快照 | 02 封存后的实际文件 | 固定引用、所选依赖、模型与参数语义 | 不临时重建近似值 |
| 基线 | 01 基线记录/现有仓库核验接口 | 完整 Git OID、对象类型和实际 worktree 基线 | 不以当前 HEAD 猜替代值 |
| 规则、检查、锁策略 | 受信注册表 | 实际内容、解析版本、依赖闭包 | 已要求的资源缺失则拒绝 |
| 环境记录 | 04/05；独立验收时为 fixture | 配置绑定、平台、入口链、能力与新鲜性 | 环境未知不能用于真实 run |
| 既有业务授权 | 原有授权系统/明确授权来源 | 主体、动作、范围、模型、目标、费用、时效及撤销 | 允许记录审核事实，但阻止无授权动作 |
| 当前资源绑定及策略状态 | 调度器/资源管理和策略入口 | 每个相关资源的当前版本与单调 generation | 不用缓存成功替代读取失败 |
| 插件锁 | 06 实现并在对象中实际声明后提供 | 当作资源读取，不执行插件 | 尚未要求时不虚构空锁；已要求时缺失必须拒绝 |

`ResourceRef={kind,id,sha256}` 继续复用 01；文件资源另有仓库相对 `path`。`base_sha` 是 Git commit 标识，不能直接塞进资源 SHA-256 字段；可以由一个包含 Git 信息的基线资源承载，再对该资源文件计算 SHA-256。[^P01]

### 2.2 输出与禁止混用的类型

| 输出 | 语义 | 不能用作 |
|---|---|---|
| `ApprovalRecord` | 不可变、可复算的审核决定 | 新权限授予、实时授权结果 |
| `RegistrationReceipt` | 记录已完整发布并关联 head 的提交事实 | 长期可执行凭据 |
| `InputLockReceipt` | 登记时相关资源的精确引用及绑定 generation | 仅凭路径或 mtime 的缓存键 |
| `ValidationResult` | 某一动作在某一观察点的校验结果与阻断原因 | 进程创建完成证明 |
| `TransitionAdmission` | 针对固定动作、run 和守卫版本的一次性准入事实 | 可跨任务复用的 bearer token |
| `RevocationEvent` | 对某条审核追加的撤销事实 | 删除旧记录的指令 |
| 依赖反向索引 | 加速定位受影响审核 | 唯一的正确性依据或可自行产生批准的文件扫描结果 |

02 的 `EnvironmentPlan` 只是待检查计划，不是 `EnvironmentRecord`。配置解析返回的 `RESOLVED_UNAPPROVED` 也不是 03 审核结论。03 应消费固定资源，而不重新接管 02 的配置展开。[^P02E]

### 2.3 模块责任分配

| 模块 | 本模块依赖它提供什么 | 03 不应代做什么 |
|---|---|---|
| 01 | 标识、严格 JSON、ResourceRef、路径和字节核验 | 另造不兼容的资源哈希算法 |
| 02 | 有效配置语义、所选依赖与环境计划 | 临时解析同名 profile 或选择替代模型 |
| 04/05 | 实际 CLI/环境预检和固定输入消费能力 | 猜测真实 Pi 协议或跨平台入口行为 |
| 06 | 已登记插件锁及其静态资源依赖 | 执行插件才能知道是否允许执行 |
| 07 | 预算预留、任务领取、取消、run 生命周期 | 根据 `retryable=true` 自动花费或重新运行 |
| 09 | 草稿/合同发布对象与稳定逻辑身份 | 依赖 PlanningBundle 实现后才开发通用审核 |
| 10 | 项目状态索引、展示和事件游标 | 把 brief 已读游标当审核锁 |

### 2.4 版本轴

本版建议 `ApprovalRecord.record_type="approval-record"`、`schema_version=1`，表示**新审核资源家族的第一版**；不等于合同 schema v1，也不表示可以进入旧执行分支。`Code-Kit v2`、合同 schema、配置 schema、审核记录 schema、序列化 profile、数据库迁移版本分别登记。

未知审核家族/版本应明确拒绝，不能只看 `schema_version` 数字决定路由。v2 路由来源在独立发布/调度记录中固定，避免编辑一个标签后绕回 v1。

## 3. 现状与复用点

### 3.1 原文陈述与本次证据限制

以下是**原文对现状的描述**，并非本次读取项目源码或运行旧测试得到的事实。[^P03]

| 原文位置/行为 | 可以复用的方向 | 正式实施前需补取的证据 |
|---|---|---|
| `validate_plan` 校验双格式合同 | 03 复用共同字段及范围校验，不建第二套宽松解析器 | 实际函数签名、异常映射、共同字段清单与旧 fixtures |
| `record_candidate`、`evaluate_gates` | 候选与门禁保持原职责 | 当前候选固定方式、G0–G6 调用顺序 |
| prepare/run 已复制合同并哈希 | 固定输入读取与运行快照 | 复制后的实际消费路径和检查后重新读取风险 |
| `.agent/runs/` 是原始证据 | 延续只读保留要求 | 写入路径、权限、清理策略及恢复流程 |
| verdict/review 面向 attempt 结果 | 保留其含义，与规划审核分表/分目录 | 当前 Schema 和兼容边界 |
| 基线、工作区指纹、保护路径已有基础 | 为新门禁提供只读事实接口 | 实际 HEAD、脏工作区、worktree 与保护列表 |

### 3.2 新增对象不能与旧结果混淆

`ApprovalRecord` 表达“允许在既有授权内推进哪个固定对象”；attempt verdict 表达“固定候选是否通过对应验收”；独立复审表达另一个审查结论。它们可以通过资源引用关联，但不能复用一个布尔字段，也不能用执行成功倒推过去已经批准。

新增审核模块、资源解析器、可信 Schema 和受控入口在正式成为可信核心时，应一并纳入保护范围。普通 executor 不能通过扩大合同 Scope 获得这些路径的写权限。

## 4. 接口和行为约束

### 4.1 审核记录

#### 4.1.1 记录只保存事实，不保存可变有效性

原文要求 `.agent/approvals/` 由调度器受控 supervisor 入口登记，记录 ID 稳定唯一。正式记录保持不可变，后续“已替代”“已撤销”“输入漂移”由追加事件及当前校验结果表达，不把旧文件中的 `decision` 改写。[^P03]

本版建议将决策枚举固定为：

| `decision` | 含义 | `reviewed_actions` |
|---|---|---|
| `APPROVED` | 审核认可所列动作范围；仍受授权和条件约束 | 至少一项，显式列出 |
| `CHANGES_REQUESTED` | 对象需要修改后再审 | 空数组 |
| `BLOCKED` | 当前材料不足或存在不能推进的阻断 | 空数组 |

不设置 `APPROVED_WITH_WARNINGS` 作为隐式放行通道；可执行条件用结构化 `conditions`，不可执行的建议写入 rationale。未注册的决定枚举拒绝。

#### 4.1.2 字段合同（新增建议）

| 字段 | 类型/是否必填 | 约束与来源 |
|---|---|---|
| `record_type` | 字符串，必填 | 固定 `approval-record` |
| `schema_version` | 整数，必填 | 本家族建议为 1；布尔值不能充当整数 |
| `approval_id` | 稳定 ID，必填 | 调度器生成；不可用任务标题或可变文件名替代 |
| `request_id` | 稳定 ID，必填 | 原预算根；重规划或换审核记录不重置 |
| `purpose` | 枚举，必填 | `planning/execution/integration/configuration/generic`；用途与动作映射必须登记 |
| `subject_ref` | ResourceRef，必填 | 审核对象；逻辑 ID 在同一版本链内保持稳定 |
| `input_refs` | ResourceRef 数组，必填 | 受信解析器计算的完整依赖闭包；不含 subject 自身 |
| `lock_policy_ref` | ResourceRef，必填 | 锁定验证与环境策略；必须同时位于 `input_refs` |
| `decision` | 枚举，必填 | 主模型审阅后的明确结论 |
| `reviewed_actions` | 无重复数组，必填 | 是“审核覆盖动作”，不是“授予的权限” |
| `reviewer` | 对象，必填 | `mode=current_session`、主会话 ID；由受控上下文注入 |
| `recorded_at` | UTC 时间，必填 | 调度器登记时间；不是排序/冲突裁决依据 |
| `not_before` | UTC 时间或 null，必填 | null 表示不早于 recorded_at；非 null 不得早于 recorded_at |
| `expires_at` | UTC 时间或 null，必填 | 非 null 必须晚于生效起点；null 仅在锁策略允许时表示没有额外时间上限 |
| `authorization_refs` | ResourceRef 数组，必填 | 当前已知授权来源；允许为空以记录审阅事实，但无授权动作必须阻塞 |
| `rationale` | 非空字符串，必填 | 决策理由及未覆盖边界；限制长度、不得含凭据 |
| `conditions` | 结构化条件数组，必填 | 空数组明确表示无附加条件，不是跳过其他必需门禁 |
| `supersedes` | 旧审核 ID 或 null，必填 | 只允许替代同范围的当前 head；不可自指 |

附录 A 给出完整 JSON Schema；Schema 只完成结构检查，不完成身份、授权、依赖闭包、文件字节或状态转换校验。Draft 2020-12 的 `format` 需按校验库启用断言；本版测试使用显式 `FormatChecker`。[^R1]

本版保守上限：单个记录 1 MiB、JSON 深度 64、执行依赖闭包最多 1024 个节点、授权引用最多 64 个、附加条件最多 64 个、rationale 最多 8192 字符。这些是建议值，不是项目实测容量或产品承诺。超限应形成分包/分层设计，而非静默截断输入。

#### 4.1.3 稳定审核范围与 head

本版建议的审核范围键为：

```text
scope_key = stable_tuple(
    repository_namespace,
    request_id,
    subject_ref.kind,
    subject_ref.id,
    purpose
)
```

单仓库账本可以由数据库位置隐含 `repository_namespace`；跨仓库服务必须显式加入。**键中不能包含 subject 的内容哈希、plan_version 或 approval_id**，否则每次修订都会创建一个新范围，旧通过决定就无法被正确替代。

前提是 `subject_ref.id` 表示稳定逻辑对象。若 09 采用“每个版本一个新资源 ID”，应通过受信 registry 将它们映射到同一个 `logical_subject_id`，再生成 scope。不得由 planner 自选一个新 ID 来逃避旧 BLOCKED 决定。现有 ID 制度未取证前，不能直接把本参考键当生产最终方案。

`heads` 保存 `approval_id + generation`。generation 由受控事务单调增加；首次登记为 1；替代和对当前 head 的撤销均推进 generation。不用记录时间选择“最新”；不把 generation 回退到旧值；不自动提升前一条通过记录。

`planning` 可以覆盖 `publish`，`execution` 可以覆盖 `prepare/run/resume`，`integration` 覆盖 `integrate`，`configuration` 覆盖 `activate`。这些是本版拟议动作名，应映射到真实入口。`generic` 在未登记用途映射时不能覆盖任何可执行动作。

#### 4.1.4 通用资源闭包与双格式合同

执行审核建议以不可变 `contract-bundle` 作为 `subject_ref`。它至少绑定 Markdown、JSON、配置语义、基线、规则、检查定义和锁策略；要求实际运行时再包含必要环境记录。此 bundle 是 03 的最小通用聚合资源，不要求 09 PlanningBundle 已实现。

```text
contract-bundle（不可变 subject）
 ├─ contract-md（完整原始字节）
 ├─ contract-json（完整原始字节）
 ├─ config-snapshot ── 所选 adapter/Schema/相关策略依赖
 ├─ baseline ── 完整 Git commit 身份与必要工作区证据
 ├─ rule / check-definition / lock-policy
 ├─ environment-record（exact 运行锁策略要求时）
 └─ plugin-lock（对象已声明、06 已提供时）
               ↓
ApprovalRecord（引用 subject + 完整闭包 + 授权来源）
               ↓
独立登记/发布回执（引用审核记录，绝不回填 subject）
```

正式资源提取器按**已登记的类型与版本**解析依赖字段。合同共同字段校验应复用实际 `validate_plan` 或其等价受信封装，明确覆盖 request/task、plan_version、基线、范围、配置引用、检查、授权/预算相关字段；具体字段清单必须从实际合同 Schema 取证，不能仅凭本文示例代替。

Markdown 与 JSON 都按各自实际字节锁定。共同字段一致只是附加语义检查，不能只对“解析后的公共字段”做哈希而忽略剩余正文。被合同引用的说明性附件是否影响审核，必须由 Schema 分类；未知类别保守拒绝或纳入，不能任意忽略。

#### 4.1.5 引用排序、重复、冲突与字节规则

`input_refs` 视为集合，先进行重复/冲突检查，再按 `(kind,id,sha256,path-or-empty)` 排序。授权引用也按同一规则排序。`reviewed_actions` 排序且拒绝重复；原始文件和命令参数等有序内容不排序。

同一闭包内不允许同一个 `(kind,id)` 指向两个不同版本或不同 locator。共享子依赖可以在图遍历中去重；调用者提供的最终列表中重复记录则拒绝，避免输入和解释不一致。不同版本确需同时存在的资源必须使用不同的稳定逻辑实例 ID，不能用冲突引用表达。

本版新生成审核文件建议采用与 01 相同的 Python 表达式，命名为独立的 `approval-json-python-v1` 输出 profile：

```python
raw = (json.dumps(value, ensure_ascii=False, sort_keys=True,
                  separators=(",", ":"), allow_nan=False) + "\n").encode("utf-8")
record_sha256 = hashlib.sha256(raw).hexdigest()
```

这是**对新生成审核记录的显式格式约定**，不是把外部 Markdown/JSON 或历史记录重写后再验哈希。输出 UTF-8、无 BOM、末尾一个 LF；字符串不做 Unicode 归一化；不内嵌自己的哈希。记录 hash 放在独立引用或登记回执中。

读取时先严格 UTF-8、重复键、非有限数和数值范围检查，再做 Schema。Python 默认 JSON 行为不能替代严格入口；重复键可能被覆盖，非有限数也需显式拒绝。[^R2]

#### 4.1.6 条件不能只是自然语言提醒

本版最小条件结构：

| 字段 | 规则 |
|---|---|
| `condition_id` | 记录内唯一 ID |
| `kind` | 仅 `check_passed` 或 `human_ack`；其他类型须先注册 |
| `definition_ref` | 完整条件定义资源，必须在 input_refs 中 |
| `applies_to` | 非空动作集合，必须是 reviewed_actions 的子集 |

条件验证器由调度器受信注册，不执行条件正文里的任意代码。`check_passed` 消费受信检查结果；`human_ack` 消费能追溯到获授权主体明确确认的来源证据，不接受 planner 生成的 `true`。

条件证据至少绑定审核 ID、subject 摘要、定义摘要、动作、产生主体、实际检查输入、时间/时效，以及条件定义要求的配置、基线、环境等事实。相同检查名不代表相同检查定义；旧候选或旧环境的 PASS 不能复用到新输入。附录参考类型仅模拟其中的最小绑定，不是正式条件证明 Schema。

评估状态建议为 `SATISFIED/UNSATISFIED/UNKNOWN/EXPIRED/UNSUPPORTED`；只有 SATISFIED 可继续。条件变化本身要产生新审核；条件的运行时满足证据作为独立资源关联消费记录，不修改旧审核文件。

#### 4.1.7 审核结论、有效性与可执行性分开

```text
APPROVED 是不变的历史结论。
CURRENT / SUPERSEDED / REVOKED 是账本关系的投影。
INTACT / DRIFTED / MISSING / CORRUPT 是输入核验结果。
AUTHORIZED / DENIED / UNKNOWN 是当前业务授权判定。
ELIGIBLE_AT_OBSERVATION 只是动作条件在该观察点成立。
ADMITTED 是某次受控转换已提交，不表示进程已经创建。
```

有效区间采用 `[not_before-or-recorded_at, expires_at)`；正好等于 expires_at 时已过期。UTC 时间由受信时钟获得，不信任提交者传入的“当前时间”。时钟回拨或无法确定新鲜性时应阻止受影响准入并记录故障，不把时间戳当分布式严格顺序。

### 4.2 谁可以登记审核

#### 4.2.1 主模型提交与调度器登记分离

原文保留：主模型审阅后经 supervisor 入口提交决定；调度器检查输入存在、版本和哈希再登记。planner 的 `approved:true`、executor 报告、插件描述、源码注释都不是审核记录。普通 planner/executor 的请求路径不能直接调用审核转换接口。[^P03]

建议把提交过程分成两种类型：

```text
ReviewSubmission：主会话提交的审阅内容；尚未登记、没有执行效力。
ApprovalRecord：调度器完成验证、注入来源和时间、封存并登记后的正式记录。
```

`approval_id`、`reviewer`、`recorded_at`、登记序号和审核范围归属由调度器生成或从可信上下文取得。外部提交中出现 `recorded_by=supervisor`、`actor=main`、`approved=true` 不改变调用身份；不能把一个普通 CLI 的 `--supervisor` 开关作为安全边界。

#### 4.2.2 入口权限矩阵

| 调用来源 | 读取可见审核 | 提交未登记审阅材料 | 登记/替代决定 | 撤销审核 | 消费动作准入 |
|---|---|---|---|---|---|
| 主会话 supervisor | 按项目可见性 | 可以 | 已有登记权限内可以 | 已有撤销权限内可以 | 仍须校验对应动作授权 |
| planner | 自己任务所需范围 | 可以提出草稿与建议 | 不可以 | 不可以 | 不能靠草稿的通过字段获得许可 |
| executor | 当前任务最小必要范围 | 可以提交运行结果 | 不可以 | 不可以 | 只能经调度器已授权入口 |
| 插件/源码内容 | 被动数据 | 不构成调用身份 | 不可以 | 不可以 | 不可以 |
| 恢复维护入口 | 明确维护授权内 | 恢复诊断 | 不根据文件扫描补造审核 | 只按明确恢复/撤销规则 | 恢复未完成时默认阻塞 |

即使同一主模型同时承担规划与监督角色，也应记录“何时切换到审核入口、审核了哪个固定版本”。这证明流程上的检查分离，不证明主体是密码学上独立的第二个人或第二个模型。

#### 4.2.3 审核权限与业务权限交集

对于动作 `a`，概念上的准入条件为：

```text
Eligible(a) =
    record_committed_and_intact
    AND current_head_matches
    AND not_revoked_or_stale
    AND decision_is_APPROVED
    AND a_in_reviewed_actions
    AND required_conditions_satisfied
    AND fixed_inputs_match
    AND current_bindings_match
    AND current_environment_matches
    AND live_business_authorization_covers(a)
    AND current_policy_allows(a)
```

真正发生会产生副作用的动作，还必须通过 07 的预算、领取和并发调度守卫。`Eligible` 不是 `can_spawn` 的同义词。

业务授权至少核对 request、主体/会话、role、动作、scope、保护路径、模型与 provider/账户、外发 endpoint/数据范围、预算根/费用权限、期限和撤销。不同授权能否组合必须由授权系统明确规定；不能任意拼接“允许路径 A”的授权与“允许模型 B”的授权推导出未被授予的组合权限。

审核记录只引用既有授权来源；业务授权系统仍需核验来源真实性、当前状态和范围。空授权引用可以保留审阅事实，但不允许产生对应运行。读取历史记录本身也要检查可见性，避免通过猜审核 ID 读取其他项目的说明或数据。

默认拒绝以及在每个相关请求上验证权限，符合 OWASP 对授权控制的基本建议；本文的审核/业务授权双层划分是项目设计补充，不是 OWASP 定义的 Code-Kit 协议。[^R3]

#### 4.2.4 登记接口建议

以下是拟议的内部接口，不表示仓库已有命令或 HTTP 路由。

| 接口 | 关键入参 | 成功结果 | 副作用 |
|---|---|---|---|
| `submit_review` | 固定 subject、决定、动作、条件、理由、授权来源、expected head、幂等键 | 已登记审核引用与提交回执 | 文件封存与账本事务 |
| `validate_for_action` | 已发布审核引用、动作、上下文、固定资源、当前守卫 | 可解释的观察结果；无启动许可 | 可追加诊断，不改审核 |
| `authorize_transition` | 固定动作、operation_id、run_id、审核、资源、环境、授权/预算守卫 | 有期限的一次性准入记录 | 与调度状态协调提交 |
| `revoke_approval` | 当前审核、expected generation、理由、撤销权限来源、幂等键 | 撤销事件 | 推进 head generation；不删记录 |
| `lookup_registration` | 原主体/范围内的幂等键 | 原登记结果与当前有效性另列 | 无新审核，无新运行 |
| `explain_invalidation` | 审核 ID 与可见范围 | 变更资源、依赖路径、修复方向 | 只读 |

输入记录不可承载任意服务端文件路径、Python 类、shell 片段或远程 Schema URL。受信 resolver/validator 必须由宿主注册；03 不下载未知 Schema、不执行插件来验证权限。

#### 4.2.5 登记幂等：范围、指纹与响应丢失

建议幂等命名空间包含 `(repository_namespace, request_id, authenticated_session, operation_kind)`；键为调用者在一次逻辑提交内稳定保留的高熵或稳定操作 ID，不能仅用任务标题。不得跨主体返回其原始登记内容。

请求指纹包含规范化的**提交内容**、expected head generation、supersedes 和固定输入引用，排除调度器新生成的 approval_id、recorded_at 等响应字段。使用具名、有版本的序列化 profile；不是直接拼接可能歧义的字符串。

| 情况 | 必须行为 |
|---|---|
| 首次请求，键未存在 | 校验、提交一条记录和 head 更新 |
| 同键、同请求，原事务已提交 | 返回原 approval_id，标记 replayed；不创建新记录 |
| 同键、不同请求 | `E_IDEMPOTENCY_CONFLICT`；不覆盖旧内容 |
| 首次请求尚未完成 | 等待受控锁或返回有限可重试状态；不能生成第二个 head |
| 提交成功但响应丢失 | 同键查询原提交；不因超时推断失败重做 |
| 原记录后来被替代/撤销 | 返回原登记事实，同时明确当前不能消费；不能用幂等重试复活它 |
| 账本无法确定是否提交 | `UNKNOWN_COMMIT`/存储错误；只允许同键对账，不盲目生成新审核或执行 |

“查回已提交结果”不是“再次批准”。不能让响应中的 `replayed=true` 变成启动器跳过当前权限检查的理由。

#### 4.2.6 存储方案与单一提交权威（新增建议）

原文规定受控目录、不可变记录与完整写入后发布，但未指定数据库。本版建议**单机、本地文件系统、单仓库账本**的最小方案：

```text
.agent/approvals/
  ledger.sqlite3             # 登记、替代、撤销、幂等、准入的事务权威
  records/<approval_id>.json # 完整、不可覆盖的审核文件
  staging/                   # 尚未提交文件；绝不是批准来源
  exports/                   # 可选脱敏导出，不作当前 head 权威
```

SQLite 中保留审核的精确 payload 字节、SHA-256、文件定位和登记关系，便于核对与授权后的字节恢复。正式消费同时要求：**事务已经提交、记录文件存在且与已登记字节一致、引用及当前守卫合法**。目录扫描本身不产生登记事实。

关键区分：账本中的登记日志、替代/撤销和幂等关系是持久事实；head 与依赖反向索引可从完整可信的提交事实重建，但不能在丢失这些事实时仅从 JSON 文件猜一个 head。文件与数据库不是天然的同一事务。

建议本地首版使用 `journal_mode=DELETE`、`synchronous=EXTRA`、每连接启用 `foreign_keys=ON`，短事务采用 `BEGIN IMMEDIATE`。SQLite 官方说明同一数据库同时只有一个写事务；IMMEDIATE 可以在开始时遇到 BUSY，必须处理而非当成功。EXTRA 在 DELETE 模式补充提交相关的目录同步，但最终持久性仍依赖实际 VFS、文件系统与硬件行为。[^R4][^R5][^R6]

不默认把数据库放在网络共享、同步盘或跨主机共享目录。未来使用 WAL 需单独验收其同主机/共享内存限制和备份方式；不能把本地通过直接推广至 SMB/NFS 或云同步文件夹。[^R7]

> **版本核对提示**：截至本次查阅，SQLite 官方记录了 WAL-reset 缺陷及其修复版本：3.51.3 及后续版本，另有 3.44.6、3.50.7 回移修复。未来切换 WAL 时，应核对实际链接的 SQLite 版本与修复情况，不能只看 Python 版本。本次参考环境为 SQLite 3.46.1，使用 DELETE 模式；未测试或声称该环境具备 WAL 修复。[^R7]

这只是本版存储决策建议；如果项目已经采用其他事务存储，可保留接口不变量并替换底层。不能为“使用 SQLite”本身宣称已解决强身份、跨主机一致性或实际进程 exactly-once。

#### 4.2.7 文件发布与登记事务

推荐生产顺序如下；附录原型为了简化，在短事务内完成本地小文件封存，不能据此推导生产大文件也应长期占写锁。

```text
1. 从可信会话接受 ReviewSubmission，做严格结构与权限检查。
2. 解析固定输入，计算完整闭包；构造不可变 ApprovalRecord 字节。
3. 在受控目录写临时文件；flush/fsync；核对字节和完整 SHA-256。
4. 以不覆盖已存在异内容的方式发布 records/<approval_id>.json。
5. BEGIN IMMEDIATE：
   a. 再查幂等键；已提交则返回原结果。
   b. 检查 expected head、supersedes、当前资源绑定及授权/策略守卫版本。
   c. INSERT 不可变审核字节及文件引用。
   d. INSERT/UPDATE head（带 expected generation 的 CAS）。
   e. INSERT 输入锁、幂等映射、REGISTERED 事件及必要 outbox。
   f. COMMIT。
6. 提交成功后返回审核引用；任何后续消费仍重新校验。
```

如果在步骤 4 后、步骤 5 提交前崩溃，只有孤儿文件，没有有效审核。如果数据库提交后文件丢失或损坏，消费必须拒绝；可以在维护授权下从可信备份或账本精确 payload 恢复**原字节**并核验，而不是重新生成“语义等价”文件。

`os.replace` 的成功原子性不等于断电后的持久性，也不能替代“不覆盖不同内容”的约束。参考实现采用临时文件加不覆盖式硬链接发布，仅用于本地私有临时目录；跨平台能力、目录同步和恶意路径竞争仍须由 01/05 实现及故障验收。[^R8]

数据库触发器可防止正常代码路径误 UPDATE/DELETE 历史记录；拥有数据库文件写权的同账户进程仍可能绕过它，因此它不是 WORM 或数字签名系统。

### 4.3 输入锁与状态转换

#### 4.3.1 三组状态必须分开

| 对象 | 建议状态 | 状态性质 |
|---|---|---|
| 登记工作流 | `RECEIVED → VALIDATED → FILE_SEALED → COMMITTED`，失败进入 REJECTED/ORPHANED/UNKNOWN_COMMIT | 调度处理状态，不放进不可变审核作为可变字段 |
| 审核当前关系 | `CURRENT / SUPERSEDED / REVOKED`；内容问题另报 INVALID/CORRUPT | 由提交事实和当前验证推导 |
| 动作转换 | `ADMITTED → HANDOFF_ACCEPTED → STARTED`；也可 CANCELLED/EXPIRED/START_UNKNOWN | 由 03/04/07 配合管理，不等于 attempt verdict |

只允许从 COMMITTED 记录开始消费。FILE_SEALED 不是批准；APPROVED 但 SUPERSEDED 或 REVOKED 也不是可执行审核。

#### 4.3.2 替代、撤销与 CAS

| 动作 | 前置条件 | 同事务变化 | 不允许的处理 |
|---|---|---|---|
| 首次登记 | scope 无 head；expected generation=0；supersedes=null | 新记录、head=新 ID/generation=1、幂等映射、事件 | 随意覆盖并发已建立 head |
| 替代登记 | expected generation 和当前 ID 都匹配；新旧同 scope | 新记录、head 指向新 ID、generation+1 | 只验证旧记录存在，不验证它仍是 head |
| 新 BLOCKED/CHANGES_REQUESTED | 同上 | 同样替代旧 head | 保留旧 APPROVED 为可执行备用 |
| 撤销当前审核 | 具备撤销权限；head/generation 匹配 | 追加撤销事实；head ID 保留；generation+1 | 改旧 decision、删除 head 后回退旧批准 |
| 再审已撤销范围 | 对当前 head 和最新 generation 重新提交 | 新记录 supersedes 被撤销 head | 清掉撤销事件后复用旧文件 |
| 查询重复登记 | 同主体命名空间、同请求指纹 | 无新增 | 重新生成时间更晚的“同一决定” |

用于替代的关键 SQL：

```sql
BEGIN IMMEDIATE;
-- 在本事务检查请求幂等、同 scope、输入及权限等完整守卫后执行：
UPDATE heads
SET approval_id = :new_approval_id, generation = generation + 1
WHERE scope_key = :scope_key
  AND approval_id = :expected_approval_id
  AND generation = :expected_generation;
-- 必须检查 rowcount = 1；否则整体 ROLLBACK，返回 E_HEAD_CONFLICT。
-- 审核 INSERT、REGISTERED 事件、输入锁、幂等映射必须在同一事务。
COMMIT;
```

这里的 SQL 是事务片段，不是省略前置检查后可直接使用的完整登记接口。首次登记用唯一 scope 主键保证并发只产生一个 head。不要使用 `INSERT OR REPLACE` 覆盖不可变审核或 head 关联事实。

锁顺序建议为：调度协调锁/相关守卫快照 → 数据库事务 → scope/head → request 授权/预算守卫 → 输入绑定 → 准入记录。07 若已有相反锁顺序，必须先统一再接线；不能通过延长 timeout 掩盖死锁。耗时模型调用、网络预检、用户确认不能持有账本事务。

#### 4.3.3 输入锁不是只比较文件哈希

本版补充三层锁：

| 层 | 锁定内容 | 失败示例 |
|---|---|---|
| 字节锁 | subject、input_refs、授权来源的实际完整字节 | 相同 path 文件被改写 |
| 语义绑定锁 | 相关逻辑资源当前所指版本及单调 `binding_generation` | profile 从 A 变 B，再变回 A；内容摘要回到旧值但经历了新发布 |
| 当前准入守卫 | 授权/策略 epoch、环境事实、预算预留、controller generation | 审核后权限撤销、旧协调器继续用缓存凭据 |

登记时的 `InputLockReceipt` 独立保存 `(kind,id,sha256,path,binding_generation)`，与审核登记在同一事务提交，不回填原审核。generation 来自可信资源绑定管理，不从 mtime、文件修改次数或调用者字段猜测。

本版建议：经过受控发布的相关语义绑定变更，即使随后回到原哈希，也不能自动恢复旧审核；重新审核形成新记录。字节损坏后的**精确备份恢复**则与语义发布不同，可在维护流程中恢复完整性，但仍须确认账本、绑定、撤销及当前授权未过期。区别必须记入恢复事件。

这是一项比“当前 hash 相同即可”更明确的新增 ABA 防护建议。尚无受控绑定 registry 的项目应如实记录只能检测当前字节漂移、不能证明期间未发生变化；不得声称已实现该不变量。

#### 4.3.4 闭包构造算法

```text
输入：固定 subject_ref；受信 kind/version → dependencies 提取器注册表。
输出：按固定键排序的全部传递依赖，不含 subject 本身。

visit(ref):
  校验资源类型、版本、ID 与合法定位；固定并核验实际字节。
  若 ref 在 active 集合：返回 E_RESOURCE_CYCLE。
  若相同 (kind,id) 已对应另一版本/位置：返回 E_RESOURCE_CONFLICT。
  若完整 ref 已在 visited：结束本分支（共享依赖去重）。
  检查节点数、总字节、深度上限。
  将 ref 加入 active；读取该类型登记的依赖字段。
  递归访问每个子依赖。
  从 active 移除，加入 visited；非根加入输出。

最后：检查目的要求的资源类别及基数；比较最终闭包与 input_refs 完全一致。
```

资源提取器只能读取登记的静态结构；既不能信任 planner 给出的边集合，也不能执行插件“计算依赖”。依赖影响行为的规则自身也是依赖，例如锁策略版本、合同 Schema、02 的语义投影规则和所选 adapter 描述符。

对于非文件资源，01 的 resolver 应提供等价的固定内容表示与明确哈希域；不能给 Git OID 左补零后冒充文件 SHA-256。附录原型只支持文件类合成资源，生产扩展需要增加注册类型和验证器。

#### 4.3.5 公共校验顺序

| 阶段 | 检查 | 典型失败 |
|---|---|---|
| V01 | 调用上下文、路由家族、可见范围、动作合法 | 来源不允许、版本路由不匹配 |
| V02 | 账本提交存在；审核文件与已登记 payload/hash 一致 | MISSING、CORRUPT、未提交孤儿 |
| V03 | 严格 Schema 与字段关系 | 未知字段、无效时间、未知类型 |
| V04 | request/subject/purpose 匹配；当前 head/generation；未撤销 | 跨请求串用、被替代、已撤销 |
| V05 | 决策、审核覆盖动作、时间区间 | BLOCKED、未覆盖动作、过期 |
| V06 | subject 与完整依赖；MD/JSON 一致；必要类别基数 | 漏依赖、共同字段不符、哈希漂移 |
| V07 | 固定基线与实际执行 worktree；当前绑定 generation | 基线不符、ABA、当前绑定不可读 |
| V08 | 02 的当前配置/策略合法性及固定语义一致 | 配置加载失败、所选模型撤销 |
| V09 | 实际环境与锁策略；凭据/账户/endpoint 绑定 | 只有环境计划、入口被换、目标账户改变 |
| V10 | 附加条件的受信证据与适用范围 | UNKNOWN、过期、证据绑定其他对象 |
| V11 | 当前业务授权、撤销与独立策略 | 无授权、权限收紧、许可未知 |
| V12 | 07 的预算预留、任务领取、run 唯一性、取消状态 | 超额、领取失效、已经取消 |
| V13 | 在准入提交点再比较所有相关版本；产生一次性回执 | 并发漂移、旧 coordinator、CAS 失败 |

阶段顺序是诊断与实现框架。为了尽早停止高风险动作，可以先做轻量授权检查，但不能因此省去后续完整校验。多故障输入可能有多个拒绝原因；单故障 fixture 应稳定得到指定错误，不必承诺所有实现对多重损坏返回同一第一错误。

#### 4.3.6 prepare 与 run 必须消费同一套固定对象

`prepare` 返回的准备结果至少绑定 request、task、plan_version、subject_ref、approval_ref、固定 input refs、所用环境记录、准备时守卫版本和准备产物。它不是永久 permit。

```text
prepare：公共验证 → 合同/输入固定拷贝或受控 pin → 记录 PreparedContext。
run：核对 PreparedContext 与请求 → 再次公共验证 → 07 预算/领取 → 准入事务。
启动器：消费该次准入 → 使用同一固定输入对象 → 记录实际 handoff/进程证据。
```

run 不得重新读取当前同名 profile 来替换已审核模型、参数或工具策略。检查后的对象应按固定 bytes、对象版本或可证明一致的句柄消费；不能“校验 A，启动时再按可变路径读取 B”。

02 增强版同时要求：当前配置加载失败不能用缓存成功兜底。03 可以调用 02 的当前状态检查并比较生成的语义候选是否仍匹配，**但执行参数仍来自锁定对象**；当前状态检查的成功不授权替换锁定输入。未选 profile 的合法无关修改不改变闭包；未选条目导致整份配置静态非法则阻止新启动，但不要将其错误地报告成所选模型内容漂移。[^P02E]

#### 4.3.7 环境锁：首版仅采用 exact

本版默认且参考实现支持的锁模式为 `exact`：运行绑定具体 `environment-record`，并核对当前实际环境。record 未变而 executable 内容改变也必须被实际预检识别。

| 变化 | 配置语义 | exact 模式行为 |
|---|---|---|
| 机器可执行路径变化 | 可能不变 | 新预检、新环境记录，重新审核相应锁定输入 |
| 同路径 CLI 升级或 wrapper 脚本变化 | 可能不变 | 原环境锁不匹配；不能只比较版本字符串 |
| 固定参数、模型、adapter 合同变化 | 改变 | 配置与环境均重新核验；旧审核不能复用 |
| 账户、租户、endpoint 或工具能力改变 | 可能改变语义/授权绑定 | 按实际范围变化重新授权/审核，不能当纯路径变化 |
| 未选 profile 合法修改 | 不变 | 不因该修改单独刷新当前环境审核 |
| 环境记录只是 fixture 或 EnvironmentPlan | 不是实测 | 不允许真实模型调用或执行 |

未来可以增加“约束内环境迁移”模式，但须在**被审核的锁策略中**明确允许的平台、入口身份/指纹、能力、账户、时效、预检主体和迁移证明。未实现该模式前，不能因为路径是非语义字段就默认为可自由迁移。

04/05 还应覆盖解释器 → 脚本 → 模块/插件等入口链。仅对 `python` 可执行文件做指纹，不能证明后续脚本内容被锁定；CLI 自报的模型名也不是对远端权重的密码学证明。本文不扩张 02 已说明的保证边界。[^P02E]

#### 4.3.8 授权撤销与准入的线性化点

建议以**受控调度准入事务提交**作为“此转换已被接纳”的线性化点。该事务绑定：审核 head/generation、资源 binding generation、相关授权/策略 epoch、controller generation、request/task/run/action、subject/config/environment 引用及 07 的预算/领取守卫。

撤销路径必须与该事务读取的守卫状态共享可比较的提交顺序。若授权源在外部服务，不能只取一个缓存 `allowed=true` 就声称与本地事务原子；需要受信的版本化许可、有效期限、消费/撤销协议，或受控协调器提供相应一致性。如果暂无该能力，应报告撤销观察窗口和残余风险。

```text
场景 A：撤销先提交 → 后续准入读到新 epoch/拒绝，不能启动。
场景 B：准入先提交、handoff 前撤销 → handoff 再核验，取消旧准入。
场景 C：handoff 已接纳后撤销 → 记录实际顺序；阻止后续受影响动作，按 07 请求取消。
场景 D：无法判断 handoff 是否已产生副作用 → START_UNKNOWN；禁止盲目重发。
```

数据库事务与操作系统创建进程、网络请求发送不是天然原子操作。即使 handoff 做第二次校验，仍有平台能力相关的竞态窗口。旧进程已开始执行或已发出的请求不能被审核账本“撤回”；不能承诺撤销后零条在途外发。

#### 4.3.9 一次性准入、重试和旧协调器隔离

准入必须绑定单次 `operation_id` 和 `run_id`，不得跨 role/request/action 复用。一个 run/action 只有一个首次消费关系；同键重试返回已存在的状态，不重新创建进程。真正重试另建 run_id，但仍属于原 request 预算根，由 07 决定是否允许。

本地实现可以用不透明引用加服务端状态，未必需要 JWT。将 permit 放进文件、argv、环境变量或模型输出并不能证明调用者身份。将来采用密码学 token 也仍要校验当前撤销和一次性消费。

`controller_generation` 在明确的协调器重启/主控交接时推进，不在每次数据库连接创建时推进。旧 generation 的未消费凭据失效；已经开始的进程保留原运行证据并按恢复协议核对。多协调器部署需要真实 fencing 支持，不能假设一个内存锁可以隔离另一台主机。

若准入之后授权 epoch 变化，即使权限经历 `允许→撤销→再次允许`，旧凭据也不恢复有效。当前批准仍可在新授权状态下重新验证，并在调度规则允许时申请新的转换；已失效凭据本身不重新激活。

#### 4.3.10 崩溃窗口与处理

| 窗口 | 恢复后可见事实 | 正确处理 |
|---|---|---|
| 文件未写完 | staging/临时文件 | 标记未完成；不可消费 |
| 文件封存，数据库未提交 | 完整孤儿 JSON | 不自动导入为批准；原幂等请求可在重验证后补交 |
| 登记事务中途失败 | 旧 head 保持；新文件可能存在 | 整体回滚；保留故障与孤儿 |
| 数据库提交，响应丢失 | 原幂等映射存在 | 返回原登记结果，并单独重新判断当前有效性 |
| 数据库提交，审核文件缺失 | 已登记 payload 可核验，路径不可读 | 拒绝消费；维护授权下恢复精确原字节 |
| 准入已提交、尚未 handoff | ADMITTED | 检查期限、epoch、controller 与取消状态；重新核验后消费或取消 |
| handoff 已提交、进程状态不明 | HANDOFF_ACCEPTED，但无可靠 STARTED 证据 | START_UNKNOWN；核对进程身份与 run 证据，不盲目重发 |
| 进程已启动、STARTED 记录丢失 | 可能有 PID/进程启动时间/run 关联 | 04/07 恢复确认；PID 单独不足以排除复用 |
| 审核替代/撤销的通知未送达 | 账本事实已提交，索引可能旧 | 直接校验仍应拒绝；outbox 可重发，不等通知才生效 |
| 数据库或资源库回退到旧备份 | 可能丢失后来撤销与绑定变更 | 进入恢复隔离；核对可信高水位与当前授权，不能直接恢复新派遣 |

#### 4.3.11 运行开始后的漂移

原文保留：当次运行快照与证据保留；不修改已有进程参数；取消、恢复按调度规则并留证。新派遣和后续受影响转换重新验证。[^P03]

在途处理至少区分：尚未创建进程可直接取消准入；已经运行则由 07 发起取消并记录实际生效时间；已经结束则保留真实结果，但候选登记、独立检查、集成等后续动作不得自动沿用失效的上游审核。历史 run 不是因为后来撤销就被重写为“当时从未启动”。

候选验收必须针对固定候选及其检查定义。03 的 execution 审核不自动包含 `integrate`；提交/集成权限依旧独立，G0–G6 也不因此跳过。

### 4.4 精确失效

#### 4.4.1 什么会失效，什么只是重新观察

| 变化 | 对原审核的影响 | 后续动作 |
|---|---|---|
| 已锁合同 MD/JSON 字节变化 | 完整性不成立 | 拒绝旧引用；发布新版本并审核 |
| 合同的相关需求、规则、基线、检查改变 | 相关语义绑定失效 | 重新构造闭包和审核 |
| 所选 profile 模型/参数/策略变化 | 固定语义不再匹配当前选择 | 不重新跟随名称；生成新候选 |
| 未选 profile 的合法内容变化 | 不属于闭包 | 不误使当前审核失效 |
| 未选 profile 使当前全配置静态非法 | 可能不改旧审核历史结论，但当前运行前提失败 | 报配置错误、拒绝新启动，不用缓存成功兜底 |
| 当前审核被替代或撤销 | 不再是可消费的当前决定 | 不回退旧通过；重新审阅或等待明确授权 |
| 业务权限/模型资格撤销 | 当前动作不获授权 | 拒绝准入；历史审核不改写 |
| 授权允许范围重新变化 | 旧动作准入 epoch 失效 | 重新判定；必要时新审核/新准入 |
| 环境位置、入口内容或能力变化 | exact 环境锁不匹配 | 预检并重新绑定/审核 |
| 实际引入或改变插件锁 | 闭包变化 | 经通用资源接口重新审核 |
| 进度事件、其他任务审核、brief 读取游标变化 | 不属于锁定行为输入 | 不触发连带失效 |
| 相同内容迁移到新位置 | 不自动证明 locator 合法或同一来源 | 受控定位迁移；exact 模式按变更处理 |
| 临时文件/未经发布的编辑 | 不直接改写已封存资源 | 仍按当前源码/配置入口规则判断；不可伪装成已发布输入 |
| 绑定 A→B→A | 摘要恢复，但受控 generation 已变化 | 本版建议重新审核，不自动恢复旧批准 |

旧合同若已经锁定整份配置原文件，则继续执行其更严格规则，不用新版本的依赖裁剪悄悄放宽它。细粒度失效必须在新合同/锁策略中明确采用。[^P02E]

#### 4.4.2 反向依赖索引

建议键为 `(resource_kind, logical_id, sha256)`，值为引用该版本的已提交审核 ID；另存当前绑定 generation 和路径用于诊断。对 subject、完整 input_refs 和授权来源都建索引。

```text
on_binding_change(kind, logical_id, old_ref, new_ref, new_generation):
  在受控发布事务记录绑定变更与 generation。
  查找引用该逻辑资源的审核；将原因作为追加事件/outbox 发布。
  通知项目索引更新展示，不修改审核文件。
  消费入口仍直接比较当前绑定和完整字节，不依赖通知是否到达。
```

索引延迟或故障最多影响通知及时性，不得产生漏检放行。索引可重建，但必须从已提交、完整可信的记录和绑定历史重建；不能从未提交孤儿文件推断有效审核。

共享策略若尚无可靠字段级依赖，应保守绑定完整的相关共享策略对象。更细粒度投影需要版本化规则与测试，不能仅以“看起来无关”排除一个授权字段。

#### 4.4.3 缓存规则

不可变资源的解析结果可以按 `(kind, schema/profile version, sha256)` 缓存；缓存也必须保证命中的字节就是被审核内容。当前授权、head、绑定 generation、环境新鲜性、取消和预算状态不可当成永不过期常量。

准入缓存键至少包含相关 head generation、资源绑定向量、授权/策略 epoch、controller generation、subject/config/environment 引用与 action/context；这些值变化需重新验证。全局账本 seq 只适合审计游标，不应直接使所有任务的审核连带失效。

路径、mtime、文件大小、profile 名称或 brief hash 都不能替代完整字节与作用域核验。读取失败时不使用 last-known-good 成功结果自动放行。

#### 4.4.4 结构化诊断与错误类别

延续 01 的 `code/message/details/retryable`，`retryable=true` 只表示技术上可能重试，不代表允许新的模型调用或预算支出。新增 `remediation`、`related_approval_ids` 等字段须经公共错误 Schema 登记，不能随意扩充顶层协议。[^P01]

| 错误类/示例 code | 含义 | 建议处理 |
|---|---|---|
| `E_SUPERVISOR_REQUIRED` | 普通调用来源尝试登记 | 拒绝；不提示如何伪造来源 |
| `E_APPROVAL_SCHEMA` / `E_RESOURCE_KIND` | 未知字段、版本或资源家族 | 修正/登记协议后重新提交 |
| `E_IDEMPOTENCY_CONFLICT` | 同键不同内容 | 保留旧结果；新的逻辑提交使用新键 |
| `E_HEAD_CONFLICT` | 审核期间 head 已变化 | 重新读取 head 和输入；主模型决定是否再审 |
| `E_APPROVAL_MISSING/CORRUPT` | 未登记、缺失或损坏 | 拒绝；对账/维护恢复，不推定通过 |
| `E_APPROVAL_SUPERSEDED/REVOKED` | 旧决定不可消费 | 使用新的明确审核，不回退 |
| `E_DEPENDENCY_CLOSURE/REQUIRED` | 依赖漏报、额外输入或缺必需类别 | 由受信解析器重建待审对象 |
| `E_RESOURCE_HASH/MISSING` | 资源字节不符或不可读 | 停止消费；查明变更/精确恢复 |
| `E_CONTRACT_PAIR` | MD/JSON 共同字段不一致 | 修订双文件并生成新版本 |
| `E_INPUT_DRIFT/E_BINDING_STALE` | 当前语义或 binding generation 改变 | 重新审核相关对象 |
| `E_ENVIRONMENT_MISMATCH` | 实际环境不符合 exact 锁 | 预检；新环境绑定需审核 |
| `E_CONDITION_UNMET` | 条件证据未满足/未知/不适用 | 提供受信、精确绑定的证据 |
| `E_AUTHORIZATION` | 当前权限不足或未知 | 按既有授权路径解决；不自动加权限 |
| `E_ADMISSION_STALE/ALREADY_USED` | 旧或已消费准入 | 对账；不重复启动 |
| `E_CONTROLLER_FENCED` | 旧协调器 generation | 由当前协调器恢复，不沿用旧凭据 |
| `E_LEDGER_BUSY/IO/UNKNOWN_COMMIT` | 存储竞争或不确定提交 | 有限退避或同键对账；默认不产生副作用 |

附录原型将部分底层 SQLite 异常直接交给测试断言，没有完成生产错误映射；正式接线必须按上表转成公共诊断并脱敏。禁止在 message/details 中回显完整环境、密钥、请求正文或不属于当前主体的资源内容。

推荐漂移诊断至少包含：哪个 resource kind/id、期望摘要、观察摘要或缺失原因、从 subject 到该依赖的路径、受影响动作、需要重新审阅的对象。哈希只能在允许的可见范围内暴露；低熵敏感内容不应以普通 SHA-256 当成安全脱敏。

### 6.3 只读核验与对账 SQL

以下查询适用于附录参考表结构，用来说明检查判据。生产表变更后必须同步修改，不可在未核实的真实账本上直接执行修复 SQL。

```sql
PRAGMA integrity_check;
PRAGMA foreign_key_check;

-- 当前 head 引用不存在的审核：期望 0 行。
SELECT h.scope_key, h.approval_id
FROM heads h LEFT JOIN approvals a ON a.approval_id=h.approval_id
WHERE a.approval_id IS NULL;

-- head 与审核范围不一致：期望 0 行。
SELECT h.scope_key, a.scope_key, h.approval_id
FROM heads h JOIN approvals a ON a.approval_id=h.approval_id
WHERE h.scope_key<>a.scope_key;

-- 同一 run/action 的重复准入：期望 0 行。
SELECT run_id, action, COUNT(*) AS n
FROM admissions GROUP BY run_id,action HAVING COUNT(*)>1;

-- 当前已撤销 head 可以存在，展示必须为不可消费；不能因此恢复上一条。
SELECT h.scope_key,h.approval_id,h.generation,r.recorded_at
FROM heads h JOIN revocations r ON r.approval_id=h.approval_id;
```

数据库 `integrity_check=ok` 不能证明全部授权当前有效、记录文件存在、资源 hash 正确或未从旧备份回退；还需逐个核验完整字节、提交关系、绑定和可信恢复高水位。

### 6.4 备份与恢复操作原则

SQLite 官方提供在线备份 API，Python 标准库暴露 `Connection.backup`。备份应覆盖数据库及其引用资源，并生成清单；生产不能在数据库活跃时简单复制主文件后就假定一致。使用 WAL 时更不能忽略 WAL 文件。[^R9][^R10][^R7]

建议过程：冻结或协调相关资源发布/清理 → 获取一致数据库备份 → 从该备份枚举资源 → 复制不可变文件并核验 SHA-256 → 记录账本高水位与当前授权/绑定检查点 → 在独立目录演练恢复。需要保护备份免遭相同故障或未经授权修改。

若仅备份审核 JSON 而缺少后续撤销记录，恢复会有误放行风险。恢复时必须先停止新派遣，核实最后可信提交高水位；无法确认是否丢失撤销时，默认不恢复运行权限，并对所需对象重新审阅/核准当前状态。

### 8.1 v1/v2 显式分派（原文保留）

v1 按原有门禁执行，说明其保证边界，不给历史 attempt 补写虚构 v2 审核。v2 草稿不能通过改 schema 标签绕回 v1；版本来源、发布路径和实际输入必须可追溯。升级/回退不删除账本，不重算历史合同、原始运行证据或旧 verdict 哈希。[^P03]

新入口遇到缺审核、坏 Schema 或未知版本时拒绝；不尝试用旧入口“兼容运行成功”。回退必须是已获授权的独立操作，使用明确旧入口与旧配置，同时继续尊重当前已撤销权限。

### 8.2 恢复运行手册

| 步骤 | 操作 | 成功判据 | 失败升级路径 |
|---|---|---|---|
| R1 隔离 | 停止新的受影响派遣；记录在途 run 与 coordinator 状态 | 无新副作用动作被提交 | 调度控制不可用时按现有应急机制升级 |
| R2 保全 | 保存数据库、相关日志/辅助文件、审核文件、临时文件与来源信息 | 有独立、只读可核验副本 | 禁止先“清理损坏文件”再取证 |
| R3 查提交事实 | 检查幂等键、REGISTERED/REVOKED 事件、head 与 generation | 能判断已提交/未提交/未知 | 无法判断则 UNKNOWN_COMMIT，不补批准 |
| R4 校验内容 | DB 完整性/FK；记录 payload/file/hash；全部 input refs | 记录与资源完整一致 | 缺失仅从可信原字节恢复，否则重审 |
| R5 核验当前性 | 授权/策略 epoch、binding generation、撤销高水位 | 未丢失后续限制，当前范围可解释 | 旧备份或无法确认时继续隔离 |
| R6 处理孤儿 | 将未提交文件标孤儿；按原幂等请求重验证后补交或保留 | 不出现扫描即批准 | 无来源则不自动导入 |
| R7 处理准入 | 旧 controller 凭据失效；对账 ADMITTED/HANDOFF/实际进程 | 每个 run 有唯一可解释状态 | START_UNKNOWN 由 04/07 升级对账 |
| R8 恢复服务 | 独立检查恢复报告与当前授权；记录解除隔离事件 | 新动作从公共门禁重新进入 | 不以一次自测通过恢复全部任务 |

### 8.3 恢复原字节与重新审阅的区别

已登记 payload/可信备份存在且能逐字节证明一致时，恢复丢失文件属于存储修复，应保留恢复来源、原摘要、修复时间和维护授权。它不能顺便改 rationale、时间、路径字段或 `supersedes`。

记录无法恢复、来源无法确认、输入已变化或撤销历史不明时，应重新审阅具体输入并生成新记录。不能用已经执行成功、文件名像审批单或一个旧 `approved:true` 恢复授权。

### 8.4 回退与保留

先停止新的 v2 动作，记录原因和影响范围；保留账本与新版本所有证据；按 07 处理在途 run；核对已批准的旧入口/配置和当前策略；在明确兼容路径中验证旧行为后恢复。

不删除 `.agent/approvals/`，不改写原 `.agent/runs/`，不把新审核内容反向补入旧合同。孤儿/失败临时文件的清理必须满足明确保留期、引用检查、权限与自己的目录归属；本模块不擅自定义“失败就全删”。

import math
import os

import sqlite3

from contextlib import contextmanager
from dataclasses import dataclass
from datetime import datetime, timezone
from pathlib import Path
from typing import Any, Callable, Iterator
from jsonschema import Draft202012Validator, FormatChecker

HERE = Path(__file__).parent
SCHEMA = json.loads((HERE / 'approval-record.schema.json').read_text())
VALIDATOR = Draft202012Validator(SCHEMA, format_checker=FormatChecker())
ID = re.compile(r'^[a-z0-9][a-z0-9._:-]{0,127}$')
PURPOSE_ACTIONS = {
    'planning': {'publish'}, 'execution': {'prepare', 'run', 'resume'},
    'integration': {'integrate'}, 'configuration': {'activate'}, 'generic': set(),

class Rejected(Exception):
    def __init__(self, code: str, detail: str = '') -> None:
        self.code, self.detail = code, detail

def fail(code: str, detail: str = '') -> None:
    raise Rejected(code, detail)

def stable_bytes(value: Any) -> bytes:
    return (json.dumps(value, ensure_ascii=False, sort_keys=True,
                       separators=(',', ':'), allow_nan=False)+'\n').encode('utf-8')

def digest(data: bytes) -> str:
    return hashlib.sha256(data).hexdigest()

def strict_json(data: bytes) -> Any:
    if not isinstance(data, bytes): fail('E_JSON_INPUT_TYPE')
    if len(data) > 1024 * 1024: fail('E_JSON_LIMIT')
    if data.startswith(b'\xef\xbb\xbf'): fail('E_JSON_BOM')
    try: text = data.decode('utf-8', errors='strict')
    except UnicodeDecodeError: fail('E_JSON_ENCODING')
    depth = 0; in_string = False; escape = False
    for ch in text:
        if in_string:
            if escape: escape = False
            elif ch == '\\': escape = True
            elif ch == '"': in_string = False
        elif ch == '"': in_string = True
        elif ch in '[{':
            depth += 1
            if depth > 64: fail('E_JSON_LIMIT')
        elif ch in ']}': depth -= 1
    def pairs(items):
        out = {}
        for k, v in items:
            if k in out: fail('E_JSON_DUPLICATE_KEY')
            out[k] = v
        return out
    def integer(s):
        if len(s.lstrip('-')) > 16: fail('E_JSON_NUMBER')
        n = int(s)
        if abs(n) > 9007199254740991: fail('E_JSON_NUMBER')
        return n
    def real(s):
        f = float(s)
        if not math.isfinite(f): fail('E_JSON_NUMBER')
        return f
    try:
        value = json.loads(text, object_pairs_hook=pairs, parse_int=integer,
                           parse_float=real, parse_constant=lambda _: fail('E_JSON_NUMBER'))
    except (ValueError, RecursionError): fail('E_JSON_SYNTAX')
    def walk(v):
        if isinstance(v, str) and any(0xD800 <= ord(c) <= 0xDFFF for c in v):
            fail('E_JSON_UNICODE')
        if isinstance(v, dict):
            for k, x in v.items(): walk(k); walk(x)
        if isinstance(v, list):
            for x in v: walk(x)
    walk(value)
    return value

def ref_key(ref: dict) -> tuple:
    return (ref['kind'], ref['id'], ref['sha256'], ref.get('path', ''))

def path_check(path: str) -> None:

    if (not path or '\\' in path or ':' in path or path.startswith('/')

    for p in path.split('/'):

def validate_record(record: dict) -> None:

        if 'path' not in ref: fail('E_RESOURCE_PATH')  # fixture registry: all kinds are files
        path_check(ref['path'])
    if record['input_refs'] != sorted(record['input_refs'], key=ref_key):
        fail('E_INPUT_ORDER')
    if record['authorization_refs'] != sorted(record['authorization_refs'], key=ref_key):
        fail('E_INPUT_ORDER')
    if record['reviewed_actions'] != sorted(record['reviewed_actions']): fail('E_INPUT_ORDER')
    if not set(record['reviewed_actions']) <= PURPOSE_ACTIONS[record['purpose']]:
        fail('E_APPROVAL_ACTION')
    if record['purpose'] == 'execution' and record['subject_ref']['kind'] != 'contract-bundle':
        fail('E_APPROVAL_SUBJECT')

    s = record['subject_ref']
    return stable_bytes([record['request_id'],s['kind'],s['id'],record['purpose']]).decode().strip()

def closure(root: dict, children: Callable[[dict], list[dict]]) -> list[dict]:
    active, done, logical, out = set(), set(), {}, []
    def visit(r: dict, depth: int):
        k, logical_k = ref_key(r), (r['kind'],r['id'])
        if k in active: fail('E_RESOURCE_CYCLE')
        if logical_k in logical and logical[logical_k] != k: fail('E_RESOURCE_CONFLICT')
        if k in done: return
        if depth > 64 or len(logical) >= 1024: fail('E_RESOURCE_LIMIT')
        logical[logical_k] = k; active.add(k)
        for child in children(r): visit(child, depth+1)
        active.remove(k); done.add(k)
        if k != ref_key(root): out.append(r)
    visit(root, 0)
    return sorted(out, key=ref_key)

class FixtureResources:
    """In-memory, test-only resolver; edges/current bindings are trusted fixture input."""
    def __init__(self):
        self.data: dict[str, bytes] = {}
        self.edges: dict[tuple, list[dict]] = {}
        self.current: dict[tuple, dict] = {}
        self.generations: dict[tuple, int] = {}
    def add(self, kind: str, identity: str, body: Any, children=None) -> dict:
        raw = body if isinstance(body, bytes) else stable_bytes(body)
        h = digest(raw)
        ref = {'kind':kind,'id':identity,'sha256':h,
               'path':f'fixtures/{kind}/{identity}/{h}.bin'}
        self.data[ref['path']] = raw
        self.edges[ref_key(ref)] = copy.deepcopy(children or [])
        logical = (kind,identity)
        if self.current.get(logical) != ref:
            self.generations[logical] = self.generations.get(logical,0)+1
        self.current[logical] = copy.deepcopy(ref)
        return ref
    def read(self, ref: dict) -> bytes:
        if ref['path'] not in self.data: fail('E_RESOURCE_MISSING', ref['id'])
        raw = self.data[ref['path']]
        if digest(raw) != ref['sha256']: fail('E_RESOURCE_HASH', ref['id'])
        return raw
    def verify(self, record: dict, *, current: bool = True) -> None:
        def children(r):
            self.read(r)
            return self.edges.get(ref_key(r), [])
        expected = closure(record['subject_ref'], children)
        if expected != record['input_refs']: fail('E_DEPENDENCY_CLOSURE')
        refs = [record['subject_ref'],*expected,*record['authorization_refs']]
        for ref in refs:
            self.read(ref)
            if current and self.current.get((ref['kind'],ref['id'])) != ref:
                fail('E_INPUT_DRIFT', ref['id'])
        kinds = {r['kind'] for r in expected}
        if record['purpose'] == 'execution':
            required = {'contract-md','contract-json','config-snapshot','baseline',
                        'rule','check-definition','lock-policy','environment-record'}
            if not required <= kinds: fail('E_DEPENDENCY_REQUIRED')
            # Synthetic MD/JSON format only; production must call the actual contract validator.
            bykind = {k:[r for r in expected if r['kind']==k] for k in required}
            if any(len(bykind[k]) != 1 for k in required): fail('E_DEPENDENCY_CARDINALITY')
            j = strict_json(self.read(bykind['contract-json'][0]))
            m = self.read(bykind['contract-md'][0])
            expected_md = b'# Synthetic contract\n```json\n'+stable_bytes(j)+b'```\n'
            if m != expected_md: fail('E_CONTRACT_PAIR')
            if j.get('request_id') != record['request_id']: fail('E_REQUEST_MISMATCH')
        if strict_json(self.read(record['lock_policy_ref'])).get('mode') != 'exact':
            fail('E_LOCK_POLICY')

class FixtureActor:

class Ledger:
    """Small local-ledger prototype. Public service must supply real authenticated context."""
    def __init__(self, root: Path):
        self.root = root
        root.mkdir(parents=True, exist_ok=True)
        (root/'records').mkdir(exist_ok=True)
        self.db = sqlite3.connect(root/'ledger.sqlite3', timeout=0.2, isolation_level=None)
        self.db.row_factory = sqlite3.Row
        self.db.execute('PRAGMA foreign_keys=ON')
        self.db.execute('PRAGMA journal_mode=DELETE')
        self.db.execute('PRAGMA synchronous=EXTRA')
        self.db.executescript((HERE/'ledger.sql').read_text())
    def close(self): self.db.close()
    @contextmanager
    def transaction(self) -> Iterator[None]:
        try:
            self.db.execute('BEGIN IMMEDIATE')
            yield
            self.db.execute('COMMIT')
        except BaseException:
            if self.db.in_transaction: self.db.execute('ROLLBACK')
            raise
    def _actor(self, actor, record=None):
        if not isinstance(actor, FixtureActor) or not actor.supervisor: fail('E_SUPERVISOR_REQUIRED')
        if record and record['reviewer']['session_id'] != actor.session_id: fail('E_REVIEWER_MISMATCH')
    def _head(self, key):
        return self.db.execute('SELECT * FROM heads WHERE scope_key=?',(key,)).fetchone()
    def _event(self, kind, identity, body):
        self.db.execute('INSERT INTO journal(event_type,approval_id,body) VALUES(?,?,?)',
                        (kind,identity,stable_bytes(body)))
    def _seal(self, identity: str, data: bytes) -> str:
        """Test-only private directory; hard-link publication refuses overwrite.
        Directory fsync is attempted on POSIX, without claiming power-loss proof.
        No production protection against malicious same-account path races.
        """
        path = self.root/'records'/f'{identity}.json'
        fd, temporary = tempfile.mkstemp(dir=path.parent, prefix='.pending-')
        try:
            with os.fdopen(fd,'wb') as f:
                f.write(data); f.flush(); os.fsync(f.fileno())
            try: os.link(temporary, path)
            except FileExistsError:
                if path.is_symlink() or path.read_bytes() != data: fail('E_APPROVAL_ID_CONFLICT')
            if os.name == 'posix':
                dfd = os.open(path.parent, os.O_RDONLY)
                try: os.fsync(dfd)
                finally: os.close(dfd)
        finally:
            if os.path.exists(temporary): os.unlink(temporary)
        return path.relative_to(self.root).as_posix()
    def register(self, record: dict, resources: FixtureResources, actor: FixtureActor,
                 key: str, expected_generation: int, *, fault: str = '') -> dict:
        self._actor(actor); validate_record(record); self._actor(actor, record)
        if not ID.fullmatch(key): fail('E_IDEMPOTENCY_KEY')
        if type(expected_generation) is not int or expected_generation < 0: fail('E_HEAD_EXPECTATION')
        semantic = {k:v for k,v in record.items() if k not in {'approval_id','recorded_at'}}
        fp = digest(stable_bytes([semantic, expected_generation]))
        ns = stable_bytes([record['request_id'],actor.session_id,'register']).decode()
        with self.transaction():
            prior = self.db.execute('SELECT * FROM registrations WHERE namespace=? AND idempotency_key=?',
                                    (ns,key)).fetchone()
            if prior:
                if prior['request_sha256'] != fp: fail('E_IDEMPOTENCY_CONFLICT')
                return {'approval_id':prior['approval_id'],'replayed':True,'must_revalidate':True}
            h = self._head(scope_key(record)); gen = h['generation'] if h else 0
            previous = h['approval_id'] if h else None
            if gen != expected_generation or previous != record['supersedes']: fail('E_HEAD_CONFLICT')
            resources.verify(record)
            raw = stable_bytes(record)
            path = self._seal(record['approval_id'],raw)
            if fault == 'after_file': fail('E_TEST_FAULT')
            self.db.execute('INSERT INTO approvals VALUES(?,?,?,?,?,?,?,?)',
                (record['approval_id'],scope_key(record),record['request_id'],raw,digest(raw),path,
                 record['supersedes'],record['recorded_at']))
            if h:
                changed = self.db.execute('UPDATE heads SET approval_id=?,generation=generation+1 '
                    'WHERE scope_key=? AND generation=? AND approval_id=?',
                    (record['approval_id'],scope_key(record),gen,previous)).rowcount
                if changed != 1: fail('E_HEAD_CONFLICT')
            else:
                self.db.execute('INSERT INTO heads VALUES(?,?,1)',(scope_key(record),record['approval_id']))
            self.db.execute('INSERT INTO registrations VALUES(?,?,?,?)',(ns,key,fp,record['approval_id']))
            for r in [record['subject_ref'],*record['input_refs'],*record['authorization_refs']]:
                self.db.execute('INSERT INTO dependencies VALUES(?,?,?,?,?,?)',
                    (record['approval_id'],r['kind'],r['id'],r['sha256'],r.get('path'),
                     resources.generations[(r['kind'],r['id'])]))
            self._event('REGISTERED',record['approval_id'],{'generation':gen+1})
            if fault == 'before_commit': fail('E_TEST_FAULT')
        return {'approval_id':record['approval_id'],'replayed':False,'must_revalidate':True}
    def _load(self, identity):
        row = self.db.execute('SELECT * FROM approvals WHERE approval_id=?',(identity,)).fetchone()
        if not row: fail('E_APPROVAL_MISSING')
        data = bytes(row['payload'])
        if digest(data) != row['sha256']: fail('E_APPROVAL_CORRUPT')
        path = self.root/row['relative_path']
        if path.is_symlink() or not path.is_file(): fail('E_APPROVAL_FILE_MISSING')
        if path.read_bytes() != data: fail('E_APPROVAL_CORRUPT')
        record = strict_json(data); validate_record(record)
        if record['approval_id'] != identity or scope_key(record) != row['scope_key']:
            fail('E_APPROVAL_CORRUPT')
        return record
    def _validate(self, identity, action, resources, now, environment_ref, evidence):
        record = self._load(identity); h = self._head(scope_key(record))
        if not h or h['approval_id'] != identity: fail('E_APPROVAL_SUPERSEDED')
        if self.db.execute('SELECT 1 FROM revocations WHERE approval_id=?',(identity,)).fetchone():
            fail('E_APPROVAL_REVOKED')
        if record['decision'] != 'APPROVED': fail('E_APPROVAL_DECISION')
        if action not in record['reviewed_actions']: fail('E_APPROVAL_ACTION')
        t = stamp(now)
        start = stamp(record['not_before'] or record['recorded_at'])
        if t < start: fail('E_APPROVAL_NOT_YET_VALID')
        if record['expires_at'] and t >= stamp(record['expires_at']): fail('E_APPROVAL_EXPIRED')
        resources.verify(record)
        bindings = self.db.execute('SELECT * FROM dependencies WHERE approval_id=?',(identity,)).fetchall()
        for binding in bindings:
            if resources.generations.get((binding['kind'],binding['logical_id'])) != binding['binding_generation']:
                fail('E_BINDING_STALE', binding['logical_id'])
        expected_envs = [r for r in record['input_refs'] if r['kind']=='environment-record']
        if action in {'prepare','run','resume'} and (len(expected_envs)!=1 or environment_ref!=expected_envs[0]):
            fail('E_ENVIRONMENT_MISMATCH')
        for c in record['conditions']:
            if action not in c['applies_to']: continue
            e = evidence.get(c['condition_id'])
            expected_status = 'PASS' if c['kind']=='check_passed' else 'ACKNOWLEDGED'
            if (not isinstance(e,FixtureConditionEvidence) or e.approval_id!=identity
                or e.subject_sha256!=record['subject_ref']['sha256']
                or e.definition_sha256!=c['definition_ref']['sha256']
                or e.action!=action or e.status!=expected_status): fail('E_CONDITION_UNMET')
        auth = self.db.execute('SELECT * FROM fixture_authorization WHERE request_id=?',
                               (record['request_id'],)).fetchone()
        if not record['authorization_refs'] or not auth or not auth['allowed']: fail('E_AUTHORIZATION')
        return record, h, auth
    def validate(self, identity, action, resources, *, now, environment_ref=None, evidence=None):
        with self.transaction():
            self._validate(identity,action,resources,now,environment_ref,evidence or {})
        return {'status':'ELIGIBLE_AT_OBSERVATION','launchable':False}
    def set_fixture_authorization(self, request_id: str, allowed: bool):
        if type(allowed) is not bool: fail('E_FIXTURE_AUTH_TYPE')
        with self.transaction():
            self.db.execute('INSERT INTO fixture_authorization VALUES(?,1,?) '
                'ON CONFLICT(request_id) DO UPDATE SET epoch=epoch+1,allowed=excluded.allowed',
                (request_id,int(allowed)))
    def revoke(self, identity, actor, expected_generation, reason, now):
        self._actor(actor)
        if not isinstance(reason,str) or not reason.strip(): fail('E_REVOCATION_REASON')
        with self.transaction():
            record = self._load(identity); h = self._head(scope_key(record))
            if not h or h['approval_id']!=identity or h['generation']!=expected_generation:
                fail('E_HEAD_CONFLICT')
            if self.db.execute('SELECT 1 FROM revocations WHERE approval_id=?',(identity,)).fetchone():
                fail('E_APPROVAL_REVOKED')
            self.db.execute('INSERT INTO revocations VALUES(?,?,?)',(identity,reason,now))
            self.db.execute('UPDATE heads SET generation=generation+1 WHERE scope_key=?', (scope_key(record),))
            self._event('REVOKED',identity,{'reason':reason,'recorded_at':now})
    def admit(self, identity, action, resources, *, operation_id, run_id, now,
              environment_ref=None, evidence=None):
        for s in (operation_id,run_id):
            if not isinstance(s,str) or not ID.fullmatch(s): fail('E_OPERATION_ID')
        fp = digest(stable_bytes([identity,action,run_id,environment_ref]))
        with self.transaction():
            prior=self.db.execute('SELECT * FROM admissions WHERE operation_id=?',(operation_id,)).fetchone()
            if prior:
                if prior['request_sha256']!=fp: fail('E_IDEMPOTENCY_CONFLICT')
                return {'operation_id':operation_id,'state':prior['state'],'replayed':True,'launchable':False}
            r,h,a = self._validate(identity,action,resources,now,environment_ref,evidence or {})
            controller = self.db.execute('SELECT generation FROM controller WHERE singleton=1').fetchone()[0]
            try:
                self.db.execute('INSERT INTO admissions VALUES(?,?,?,?,?,?,?,?,?,?)',
                    (operation_id,fp,identity,r['request_id'],action,run_id,h['generation'],a['epoch'],controller,'ADMITTED'))
            except sqlite3.IntegrityError: fail('E_RUN_ACTION_EXISTS')
            self._event('ADMITTED',identity,{'operation_id':operation_id,'run_id':run_id})
        return {'operation_id':operation_id,'state':'ADMITTED','replayed':False,'launchable':False}
    def handoff(self, operation_id, resources, *, now, environment_ref=None, evidence=None):
        """One-time local state transition ONLY. It does not create a process."""
        with self.transaction():
            row=self.db.execute('SELECT * FROM admissions WHERE operation_id=?',(operation_id,)).fetchone()
            if not row: fail('E_ADMISSION_MISSING')
            if row['state']!='ADMITTED': fail('E_ADMISSION_ALREADY_USED')
            controller=self.db.execute('SELECT generation FROM controller WHERE singleton=1').fetchone()[0]
            if controller!=row['controller_generation']: fail('E_CONTROLLER_FENCED')
            r,h,a=self._validate(row['approval_id'],row['action'],resources,now,environment_ref,evidence or {})
            if h['generation']!=row['head_generation'] or a['epoch']!=row['auth_epoch']:
                fail('E_ADMISSION_STALE')
            self.db.execute("UPDATE admissions SET state='HANDOFF' WHERE operation_id=? AND state='ADMITTED'",(operation_id,))
            self._event('HANDOFF',row['approval_id'],{'operation_id':operation_id})
        return {'state':'HANDOFF','process_started':False,'fixture_only':True}
    def fence_controller(self):
        with self.transaction(): self.db.execute('UPDATE controller SET generation=generation+1 WHERE singleton=1')

"""Extract only the named offline reference files from the enhanced Markdown.
Usage: python extract_reference.py DOCUMENT.md NEW_OUTPUT_DIRECTORY
Does not run extracted code or touch a project repository.
"""
from __future__ import annotations
import argparse
import re
from pathlib import Path

EXPECTED = {
    'approval-record.schema.json','auxiliary-records.schema.json','approval-record.fixture.json',
    'ledger.sql','approval_reference.py','fixtures.py','test_approvals.py',
    'golden-vectors.json','auxiliary-fixtures.json','resource-fixtures.json',
    'verify_vectors.py','extract_reference.py',
}

def extract(document: Path, destination: Path) -> list[Path]:
    if destination.exists() and any(destination.iterdir()):
        raise ValueError('Destination must be a new or empty directory; refusing overwrite.')
    text=document.read_bytes().decode('utf-8',errors='strict')
    pattern=re.compile(r'^<!-- file: ([a-zA-Z0-9_.-]+) -->\n```[a-zA-Z0-9_-]+\n(.*?)\n```\s*$',re.M|re.S)
    found={}
    for match in pattern.finditer(text):
        name,body=match.groups()
        if name in found:raise ValueError(f'Duplicate named block: {name}')
        if name not in EXPECTED:raise ValueError(f'Unexpected named block: {name}')
        found[name]=body+'\n'
    if set(found)!=EXPECTED:
        raise ValueError(f'Missing blocks: {sorted(EXPECTED-set(found))}')
    destination.mkdir(parents=True,exist_ok=True)
    paths=[]
    for name in sorted(found):
        path=destination/name
        with path.open('xb') as stream:stream.write(found[name].encode('utf-8'))
        paths.append(path)
    return paths

if __name__=='__main__':
    parser=argparse.ArgumentParser(description=__doc__)
    parser.add_argument('document',type=Path)
    parser.add_argument('destination',type=Path)
    args=parser.parse_args()
    for path in extract(args.document,args.destination):print(path.name)
