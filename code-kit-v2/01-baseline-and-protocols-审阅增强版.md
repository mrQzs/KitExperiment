## 1. 目标与非目标

### 1.1 目标（原文保留并细化）

为后续十二个模块建立可复现的现有行为基准、公共标识和资源引用约定，使配置、审核、适配器、插件和项目状态能够独立实现。

本模块的完成应意味着：一个实施者可以定位被测代码与实际输入，另一个实施者可以复用同一协议识别资源、事件和错误，审阅者可以追溯每项判断依据，同时旧合同和历史证据没有被悄悄换一种方式解释。

| 目标产物 | 最低可用标准 |
|---|---|
| 基线报告 | 精确关联代码版本、实际输入、工具链、命令、退出信息、结果及限制 |
| 公共协议 | 字段有类型、作用域、必填规则、校验顺序和稳定错误 |
| 资源引用 | 内容变更可检出；引用来源可信度与字节一致性分别判断 |
| 兼容 fixtures | 来源、脱敏、预期判断、平台适用性和历史能力边界明确 |
| 兼容矩阵 | 区分读取、验证、运行、审核、集成能力，未知版本不降级 |
| 验收映射 | 每个结论可追到输入、命令或断言；未运行不等于通过 |

### 1.2 非目标（原文保留）

本模块不改模型选择、不接入新 CLI、不启动模型，也不重写现有调度器。不实现插件加载、审核决策、预算扣减、合同发布、项目生命周期归约或集成动作。

协议解析器尤其不得有以下副作用：根据模型输出安装依赖；执行资源中的命令；读取未获准的机器路径；自动消费凭据；遇到 `retryable=true` 就调用模型；为补足未知用量而执行额外模型任务。

### 1.3 版本轴与协议家族

原文记录：目标架构名为 Code-Kit v2；现有脚本 `TOOL_VERSION = 2.2.2`；已有合同 `schema_version = 1`。三者不可互相推导。

| 版本轴 | 示例/来源 | 决定什么 | 不决定什么 |
|---|---|---|---|
| 架构名称 | Code-Kit v2，原文名称 | 目标模块组织 | 已实现能力或测试结果 |
| 工具发布版本 | `2.2.2`，待仓库确认 | 某次软件发布 | 所有 Schema 的版本 |
| 合同 Schema | 原文合同 v1 | 合同字段与解释规则 | 事件、配置、插件的版本 |
| 公共协议家族 | 本文建议 `codekit-public` | 公共记录的分派命名空间 | 自动取代旧合同 |
| 公共记录版本 | 本文样例使用 `schema_version=1` | 该公共家族的首版建议 | 表示旧合同 v1 已迁移 |
| 适配器修订 | 由 04 锁定 | 原始流到标准事件的解释版本 | 修改历史原始证据 |
| 序列化 profile | 建议 `codekit-config-json-py-v1` | 核心语义快照的字节规则 | 任意 JSON 文本的语义等价 |

协议路由至少依据“**受信入口要求的资源类型/记录类型 + Schema 家族 + 版本**”。不能仅看到 `schema_version: 1` 就把配置当合同、把事件当审核记录。Schema 注册表属于可信核心，不由模型或插件在运行时任意改写。

### 2.2 基线身份不能只有 HEAD

建议基线身份由以下独立事实构成：

```text
BaselineIdentity =
  repository_identity
  + full_head_oid
  + git_storage_object_format
  + worktree_input_manifest_ref
  + environment_facts_ref
  + baseline_capture_started_at
  + baseline_capture_finished_at
```

这里的 `+` 表示组成关系，不是直接拼接字符串产生新哈希。若需要整体摘要，必须先定义具体的 Manifest 文件和序列化规则。

`worktree_input_manifest` 至少列出实际会被检查或测试读取的已跟踪文件、暂存/未暂存变化、相关未跟踪文件，以及由配置发现的其他输入。只记录 `git diff` 不能替代未跟踪文件清单；只记录文件名也不能固定其字节。

对可能改变行为的忽略文件、子模块、解释器启动配置、依赖锁、Git 行尾/过滤设置，应记录“已纳入、受控禁用或未知”。没有纳入完整输入闭包时，报告可说明观察结果，但不能宣称可严格复现。

**前后双采样规则**：取证前与测试结束后比较 HEAD、输入清单与关键输入哈希。发生非预期变化时，保留测试日志，标记 `baseline_consistent=false`；此结果不能作为当前输入版本的通过证明。无需删除结果或用重跑覆盖第一次记录。

### 2.3 输出物与独立记录

| 输出 | 建议内容 | 不应包含 |
|---|---|---|
| 基线报告 | 输入引用、环境摘要、命令结果、旧行为映射、未运行项 | 自身哈希、凭据、猜测性 PASS |
| 证据目录 | 分离的 stdout/stderr、来源元数据、脱敏记录 | 未经授权保留的真实密钥 |
| fixture manifest | 来源类别、源版本、文件哈希、用途、预期结果 | 伪造的厂商输出或不存在的提交 |
| 公共 Schema 与参考实现 | 数据结构、纯校验逻辑、边界说明 | 调度、执行授权或扣款实现 |
| 兼容矩阵 | 类型/版本/平台/读取与执行能力 | 不带条件的“全面兼容” |
| 验收映射 | 旧场景、新断言、责任模块、证据引用 | 只凭测试名称认定覆盖 |

报告本体不内嵌本体摘要。可由外层 `bundle-manifest.json` 引用报告；更外层审核再引用该 Manifest，始终保持摘要依赖为有向无环图。

### 2.4 结果状态与证据类型分开

本节新增状态只用于**基线检查报告**，不是改名后的旧 attempt 状态或 verdict。

| `execution_status` | 定义 | 可以解释为通过吗 |
|---|---|---|
| `PASS` | 命令/断言真实执行，结果满足明确期望，证据完整且基线一致 | 可以，但仅限该检查范围 |
| `FAIL` | 检查真实执行，观察结果不满足预期 | 不可以 |
| `ERROR` | 启动、采集、解析或测试框架出错，未形成可信检查结论 | 不可以 |
| `BLOCKED` | 缺授权、输入、工具或前置条件而未能执行 | 不可以 |
| `NOT_RUN` | 尚未执行，且没有用 BLOCKED 更准确解释 | 不可以 |
| `UNSUPPORTED` | 当前平台/实现不具备该项能力，并有确认依据 | 不可以代替其他平台通过 |

另设 `evidence_basis = measured | source_inspected | source_reported | proposed | unknown`。例如“原文声称存在超时测试”只能是 `source_reported`；查看测试源码但没有运行，只能是 `source_inspected`，不能配上运行型 `PASS`。

“不适用”由 `applicability` 和理由表达。某项安全能力是宣称支持范围的必要条件时，不能通过标记不适用绕过。存在任何必需项 FAIL/ERROR/BLOCKED/NOT_RUN 时，不得生成“该平台全量通过”的结论。

### 3.2 回归映射的最低记录单位

```text
legacy_behavior_id
source_location + full_source_revision
input_fixture_ref
legacy_command_or_test_id
legacy_observation
comparison_projection_revision
new_consumer_module
acceptance_ids
platform_scope
evidence_basis + execution_status
notes_and_limitations
```

“比较投影”指在两次结果中明确选哪些字段比较、哪些环境字段允许不同。只能删除已经说明理由的机器定位或时间字段，不能删除 verdict、检查结果、门禁失败原因、模型证据缺失状态、候选树或费用未知状态以制造一致。

### 3.3 必须核实、不得补猜的旧行为

| 待核验项 | 为什么会影响兼容 |
|---|---|
| `attempt` 的起始值、递增条件与恢复复用规则 | 把恢复错当重试会改变审计和预算归属 |

| 缺失模型、思考级别、token、费用的旧输出 | 不能在迁移时替换为成功或零值 |
| 取消、超时、已有锁、候选漂移与补丁不完整的旧结果 | 影响恢复是否重复执行与安全退出 |

## 4. 接口和行为约束

### 4.1 标识、状态与路径

#### 4.1.1 公共标识字段

原文字段语义保留；以下格式和范围是**新协议建议**，不直接套到历史原文件上。

| 字段 | 新协议类型/建议格式 | 作用域与分配方 | 空值与变更规则 |
|---|---|---|---|
| `request_id` | `req-` 加 32 位小写十六进制随机标识 | 一次用户目标；可信核心分配 | 不可为空；拆任务、返工、换角色不重置 |
| `task_id` | 1–64 字符；`^[a-z0-9]+(?:-[a-z0-9]+)*$` | request 内唯一；合同/规划层管理 | 无任务归属的 planner 运行可为空；不作授权凭证 |
| `plan_version` | 正整数，不接收字符串、布尔值或小数形式 | 同一任务的合同版本 | 发布/派遣后内容变化必须新版本；尚无合同时可为空 |
| `run_id` | `run-` 加 32 位小写十六进制随机标识 | 每次 planner/executor/observer 调用 | 新调用必新值；只是重新读取/连接旧运行时不新建 |
| `attempt` | 新封装允许非负整数或空值 | 原有任务尝试序号，语义沿用旧实现 | 首次基数待核验；不得为了新 Schema 把历史编号整体平移 |
| `base_sha` | 完整 Git commit OID | 所属仓库及对象格式内 | 必须验证对象存在且类型正确 |
| `candidate_tree` | 完整 Git tree OID | 所属仓库及对象格式内 | 不接受 commit/tag 冒充 tree |
| `platform` | `linux`、`macos`、`windows` | 适配层由受信环境事实映射 | 未知系统显式不支持，不猜为 linux |

新生成的 request/run 标识建议使用 UUID4 的十六进制形式并加前缀，分配时仍需检查持久化唯一性。已有 request 必须从可信记录恢复，不能因为客户端重连而重新产生预算根。业务代码不得依据标识的可猜测性授予权限。

新协议整数默认采用 `0..2^53-1`，正整数字段下界为 1；超出范围拒绝，而不是截断。这是跨消费者一致性的设计限制，不是宣称 JSON 只能表示该范围。原始厂商证据和 v1 文件不因此被重写。RFC 8259 对数值互操作范围有相关讨论，但具体字段上限由本项目决定。[^R2]

#### 4.1.2 重试、恢复和重放不能混淆

| 动作 | request_id | run_id | attempt | 是否可能产生新用量 |
|---|---|---|---|---|
| 网络断开后查询同一运行 | 保持 | 保持 | 保持 | 不因查询本身产生模型用量 |
| 重放同一批已记录事件 | 保持 | 保持 | 保持 | 不得重复累计 |
| 原执行失败后再次启动 executor | 保持 | 新建 | 按旧规则前进 | 可能，须由 07 重新检查预算 |
| 对同一目标进行 observer 调用 | 保持 | 新建 | 关联被观察尝试或为空，由合同规定 | 可能，按 observer 独立记录 |
| 同一目标因返工发布新合同 | 保持 | 真正调用时新建 | 沿用调度器规则 | 可能，不重置 request 预算 |
| 用户另行提出独立目标 | 新建 | 真正调用时新建 | 独立任务序号 | 属于另一个预算根 |

“HTTP 重试”“CLI 再次执行”和“模型调用重试”不是同一概念。01 只提供标识约束，07 决定是否允许创建新的执行尝试。

#### 4.1.4 运行、验收、审核、集成各自独立

原文要求：既有 attempt 状态与 verdict 名称保持不变。规划状态与 DAG 节点状态属于独立状态机。

建议视图分别提供 `process_observation`、`legacy_attempt_state`、`contract_approval_ref`、`legacy_verdict`、`integration_observation`。旧枚举原样保留；01 不定义它们的新状态转换。

| 观察 | 能证明 | 不能证明 |
|---|---|---|
| `wait` 命令返回 0 | 按旧入口规则完成一次查询/等待动作 | 任务结束、验收通过或已集成 |
| 子进程退出码为 0 | 进程报告正常退出 | 协议流完整、门禁全部通过 |
| 已存在审核记录 | 某主体对某些输入作出过审核 | 当前字节仍与审核输入相同、审核尚有效 |
| 旧 verdict 为 PASS | 对应旧验收规则下的结果 | 已经集成或后续输入没有漂移 |
| 状态为 INTEGRATED | 项目层记录了集成结果 | 可倒推之前每项证据都完整 |

不得提供一个未经定义的 `success=true` 覆盖以上所有含义。聚合状态应携带来源和规则版本；某维度未知时该维度保持未知。

#### 4.1.5 业务路径与环境定位严格分域

**原文保留**：业务路径使用仓库相对正斜杠格式；拒绝绝对路径、`..`、NUL 和解析后越界的 symlink/junction。仓库外 worktree、机器可执行路径只存于受信环境事实中，不接受模型通过业务字段指定。

**新增可移植词法 profile**：不自动修复输入；拒绝反斜杠、盘符/UNC/设备路径、空分段、`.` 分段、末尾斜杠、控制字符、Windows 保留设备名、分段末尾点/空格，以及 `:<>"|?*` 等不具备统一语义的字符。总长建议不超过 4096 个 UTF-8 字节，单分段不超过 255 个 UTF-8 字节；这只是协议上限，不保证每个文件系统均可创建该路径。

Microsoft 官方文档明确列有保留字符和设备名，包括带扩展名的 `NUL.txt` 与部分上标数字设备名。这里据此采用跨平台统一拒绝策略，而不是等待不同系统各自解释。[^R6]

| 输入 | 新 profile 处理 | 原因 |
|---|---|---|
| `src/main.py`、`文档/说明.md` | 进入下一层校验 | 合法词法不等于允许访问 |
| `/etc/passwd`、`C:/temp/a`、`C:a` | 拒绝 | 绝对/驱动器相关路径 |
| `../a`、`a/../b`、`./a`、`a//b` | 拒绝 | 父目录、歧义或非规范分段 |
| `a\b`、`//server/share/a` | 拒绝 | 反斜杠或 UNC |
| `a:stream`、`NUL.txt`、`COM¹.log` | 拒绝 | 特殊流/保留设备语义 |
| `a/space `、`a./b` | 拒绝 | 跨平台映射不一致 |
| `inside/link/file` | 词法通过后检查物理对象 | 链接可能指向根外 |

路径不是 URL，不在文件层执行百分号解码、环境变量展开、`~` 展开或 shell 展开。传输层确实使用 URL 时，应在明确的单一位置完成解码，再交给路径校验；后续不得再次解码。大小写与 Unicode 形式不擅自归一化；跨平台实际名称碰撞应被检出并阻断，而不是覆盖其中一个文件。

#### 4.1.6 路径检查的四层模型

```text
受信 root capability
        ↓
词法检查：原始业务字符串，不先 normalize 掩盖非法分段
        ↓
物理检查：实际祖先/目标、symlink、junction、文件类型、root 归属
        ↓
授权检查：合同具体范围、保护文件、操作类型
        ↓
安全访问：使用受控句柄读取/创建；封存并校验实际消费的字节
```

`PurePath.is_relative_to()` 是字符串层操作，不访问文件系统，也不特别处理 `..`；不能单独作为物理越界检查。`Path.resolve()` 可用于静态解析，但其返回值不是能抵御后续路径替换的访问凭证。[^R4]

生产访问必须针对威胁模型另行实现：父目录由谁写入、是否允许链接、是否允许并发改名、是否读取普通文件、是否可能被替换为设备/FIFO、如何固定实际打开的对象。路径通过后再用原始字符串 `open()`，会重新引入检查与使用之间的竞态。

建议在受控工作区采用按目录句柄逐级访问、禁止不受信链接与重解析点、将消费内容复制/封存到受保护证据区等策略。仅设置叶子文件的“不跟随链接”选项不能证明所有父目录安全。Windows 的 junction/reparse-point 与 POSIX 的符号链接须分别验收；平台未完成安全访问实现时，不开放对应的高风险写入能力。

还需考虑 hard link、挂载点和同一路径上的并发内容写入：路径归属检查不等于文件独占。对于写入操作，不能只以“路径在根内”为由覆盖已有共享对象；对于读取后的执行或审核，应消费已固定的相同字节，而不是重新读取可变文件。

#### 4.1.7 不存在的目标路径与新文件创建

现有文件检查可要求目标存在；新文件创建不能简单使用 `resolve(strict=False)` 作为安全证明。应在受信目录句柄下核验已有祖先，逐级创建所需目录，并按预期使用独占创建或受控替换；目标意外存在时返回冲突，不覆盖未知数据。

附录 B 只提供**词法检查与静态解析参考函数**，故意不提供“安全写文件万能函数”。它不能替代本节的生产访问边界，也不能用静态 symlink 测试通过来宣称消除了 TOCTOU 竞态。

### 4.2 资源引用和哈希

#### 4.2.1 ResourceRef 契约

**原文保留**：公共 `ResourceRef` 必含 `kind`、`id`、`sha256`；文件资源增加 `path`。SHA-256 是引用内容完整字节的 64 位小写十六进制摘要。

| 字段 | 新增具体约束 | 关键解释 |
|---|---|---|
| `kind` | 注册类型；建议 `^[a-z][a-z0-9-]{0,63}$` | 具体资源 Schema 决定类型语义与是否要求 path |
| `id` | 建议 `^[a-z0-9][a-z0-9._:-]{0,127}$` | 逻辑身份，不是物理文件路径或授权标识 |
| `sha256` | `^[0-9a-f]{64}$` | 不接受短摘要、大写、`sha256:` 前缀或占位字符串 |
| `path` | 文件资源必填，按 4.1 校验 | 只作定位；不能代替字节校验 |

`kind` 注册表应包含 schema、是否文件资源、允许的载荷表示、语义校验器及所属模块。结构校验通过但 `kind` 未注册时拒绝；01 不为所有未来插件预留一个“任意内容都可信”的通用类型。

同一逻辑 ID 内容变化应生成新摘要，并由新版本记录引用。旧引用不能被后台替换到新内容。同内容复制到另一位置仍需校验上下文和来源；哈希相同本身不证明发布主体、授权或审核有效性。

#### 4.2.2 可复算的合成引用示例

以下字节由本版合成，**不是 Pi 或其他厂商输出**。文件内容严格为一行 UTF-8，最后恰好一个 LF：

```text
{"fixture":"synthetic","ok":true}
```

对应文件资源引用示例：

```json
{
  "kind": "fixture",
  "id": "synthetic-protocol-sample-1",
  "sha256": "0036dde35a13e287320b6399674c46649365553a0ab6d3edf2a2111d6f83c4e1",
  "path": "tests/fixtures/synthetic-protocol-sample-1.json"
}
```

该路径是建议位置，不表示项目中已经存在文件。`fixture` 类型也必须在正式接入时登记。示例只证明这些合成字节的摘要可以复算，不能用于证明真实 CLI 兼容。

#### 4.2.3 Git OID 与资源摘要不能混用

`base_sha` 验证为 commit，`candidate_tree` 验证为 tree；记录仓库实际存储的对象格式。Git 提供 `rev-parse --show-object-format` 查询仓库对象格式，并提供带类型限定的 revision 验证。[^R3]

建议由受信 argv 调用进行验证，不能把用户字符串直接拼进 shell：

```text
git rev-parse --show-object-format=storage
git rev-parse --verify --end-of-options HEAD^{commit}
git cat-file -t <已完成格式校验的完整OID>
```

正式输入要求完整 OID，不接受分支名、短 OID、标签表达式或任意 revision 表达式。`cat-file -t` 返回类型必须匹配字段；对象不存在和类型错误分别报错。

即使 Git 仓库使用 SHA-256，对象标识仍是 Git 对象语义下的标识，不等于普通文件原始字节的 `sha256`。未知对象格式不得凭长度猜测成已支持格式；旧工具不支持查询选项时，记录环境限制并采用经批准的核实方法，不假填结果。

#### 4.2.4 三种哈希域

| 域 | 输入 | 允许的处理 | 禁止的处理 |
|---|---|---|---|
| 原始/锁定资源 | Markdown、附件、插件、二进制等最终文件字节 | 二进制读取后直接 SHA-256 | 核验时换行、去空格、重新排版、Unicode 归一化 |
| 核心配置语义快照 | 按 02 规则构建的有效配置投影 | 按固定序列化 profile 生成新文件，再哈希该文件 | 对任意外部 JSON 擅自“语义等价化” |
| v1 历史证据 | 原规则下保留的原文件 | 继续使用原核验规则 | 批量迁移重算后冒充原始摘要 |

文本的 UTF-8 约束适用于新协议或锁定时的要求，不意味着可以把历史证据自动转为 UTF-8。未知编码、无效字节应作为原始证据保留并标记解释限制。

#### 4.2.5 配置语义投影：先严格解析，再按字段分类

正确顺序是：严格解码与重复键检查 → 确认配置 Schema → 字段级验证 → 按 02 的有效配置规则展开默认值/继承 → 生成语义投影 → 固定序列化 → 写出快照 → 生成独立引用。

不能先删除“看起来不重要”的键再检查配置。特别是重复键、未知授权字段、下划线伪装的策略字段，不能在审核前被丢弃。

| 字段类别 | 语义快照 | 环境锁/其他记录 | 示例与风险 |
|---|---|---|---|
| 模型与角色选择 | 保留 | 可同时有运行证据 | provider/model、role、思考策略等 |
| 授权与运行策略 | 保留 | 03 记录实际审核输入 | 网络许可、工具范围、预算策略、角色限制 |
| 影响行为的业务环境值 | 按 Schema 保留安全值或语义引用 | 必要时记录绑定 | 不能把所有环境变量值一律当机器噪声删除 |
| 受控环境变量名称 | 保留 | 环境锁记录是否可用，不泄露值 | 例如凭据变量名与许可列表 |
| 机器定位字段 | 移除 | 放入环境锁 | 本机 executable 路径、受控 worktree 路径 |
| 说明字段 | 仅按 02 登记规则移除 | 可保留在原配置 | 不能递归删除所有未知 `_...` 字段 |
| 凭据值 | 移除 | 凭据系统持有；环境锁不得记录明文 | API key、访问令牌、私钥 |
| 影响外发目标的 endpoint/账户范围 | 保留安全语义绑定或引用 | 03/环境锁验证实际绑定 | 不可仅因它包含 URL 或账户信息就删除 |
| CLI 版本、入口指纹 | 不作为机器路径混入语义快照 | 环境锁保存 | 同一配置也可能跑在不同执行环境 |

凭据轮换可能不改变语义快照摘要，但账户、权限域、外发目标或授权绑定变化仍可能使审核失效。03 必须依据实际绑定与锁规则决定是否重新审核，不能只看配置哈希。

不应把低熵秘密的普通 SHA-256 放进公开 Manifest 作为“脱敏”。凭据绑定可以使用受控版本标识或其他明确设计的安全机制；该机制属于 03/凭据管理，不在 01 擅自实现。

#### 4.2.6 固定序列化与数值规则

原文固定表达式保持不变：

```python
json.dumps(
    value,
    ensure_ascii=False,
    sort_keys=True,
    separators=(",", ":"),
    allow_nan=False,
) + "\n"
```

输出 UTF-8、无 BOM、末尾一个 LF。字符串保留原值，不做 Unicode 归一化。对象键按上述实现排序；数组默认保留顺序。只有 Schema 明确定义为集合的字段，才可在有效配置形成阶段按锁定规则排序/去重；序列化函数本身不擅自改变数组。

本 profile **不是 RFC 8785/JCS**。JCS 的数字序列化、UTF-16 属性排序等规则不能与此 Python 表达式等同；替换成 JCS 会改变某些字节和摘要，需要独立版本与迁移设计。[^R5]

`1` 与 `1.0`、`0.0` 与 `-0.0` 可能产生不同文本。整数型字段应在 Schema/应用校验中拒绝不合规表示；需要统一实数表示的字段必须由 02 明确规则。不得对所有数字实施“差不多相等”的舍入。金额建议采用十进制字符串，见 4.3。

Python 默认 JSON 解析会接受重复键并保留最后一个值，也有接受非有限数的行为。因此 `allow_nan=False` 只约束输出端，不足以保护输入；新入口还需重复键钩子、非有限数拒绝与溢出检查。[^R1]

#### 4.2.7 严格 JSON 入口顺序与上限

建议新协议默认上限：单文档 1 MiB、嵌套深度 64、整数范围如 4.1。此为可配置设计值，不是原有规模承诺；大文件或大事件流应分段，不简单扩大所有内存上限。

| 顺序 | 检查 | 失败行为 |
|---|---|---|
| 1 | 输入确为 bytes、长度在限额内 | `E_JSON_INPUT_TYPE` / `E_JSON_LIMIT` |
| 2 | 新协议 UTF-8、无 BOM | `E_JSON_ENCODING` / `E_JSON_BOM` |
| 3 | 解码前后受控资源上限，预检查嵌套深度 | `E_JSON_LIMIT` |
| 4 | 完整 JSON 文法；拒绝尾随第二文档 | `E_JSON_SYNTAX` |
| 5 | 对象重复键，包括转义后相同的键 | `E_JSON_DUPLICATE_KEY` |
| 6 | 非有限数、数值溢出、非 Unicode 标量字符串 | 对应数值/Unicode 错误 |
| 7 | Schema 家族/版本与字段形状 | `E_SCHEMA_*` |
| 8 | 资源类型、路径、上下文关系、授权前提 | 对应领域错误 |
| 9 | 受控读取与完整字节哈希核验 | `E_RESOURCE_*` |

这是概念阶段顺序；同一次底层解析可能先遇到数值错误再完成重复键遍历。对于多重损坏输入，不承诺所有实现返回同一个“第一处错误”；**单一故障夹具**必须稳定返回指定原因。不得在错误后继续生成已审核视图。

JSON Schema 的字段验证不能发现已经被解析器覆盖的重复键。对象未知字段必须显式关闭；`format` 的断言能力也应按验证库明确启用，而不是只写上 `date-time` 就假定已检查。[^R7][^R8]

#### 4.2.8 字节封存、引用发布与循环依赖

```text
读取/生成输入 → 校验 → 生成最终字节 → 受控临时文件
      → 完整写入与关闭/同步 → 在实际最终字节上计算 SHA-256
      → 以平台支持的方式发布不可变版本
      → 提交 ResourceRef 与索引 → 上层审核引用
```

不可变版本不得覆盖已有不同内容。文件发布成功而索引失败时，将其作为未引用候选保留并待补偿；索引不能先发布一个尚不可读的资源引用。平台的原子替换与崩溃持久性是不同保证，需要分别测试；Python `os` 文档对替换、文件描述符和平台能力有具体说明。[^R9]

核验后消费必须使用同一份已固定字节或同一受控对象版本。禁止“校验 A，随后重新按可变路径读取 B”而仍沿用 A 的审核。

摘要依赖顺序建议为：

```text
配置快照 / 合同 / 插件锁 / 环境锁
                 ↓
             审核记录
                 ↓
            执行与验收记录
                 ↓
            项目集成记录
```

文件不得包含自身摘要。若审核记录引用合同，合同不再反向嵌入包含该合同摘要的审核记录；可由独立索引表达二者关系。出现资源依赖环时返回 `E_RESOURCE_CYCLE`，不得用“先填零摘要再替换”解决。

### 4.3 事件、错误和用量

#### 4.3.1 标准运行事件封装

原文要求保留：统一封装包括 Schema 版本、request/run 标识、run 内递增序号、时间、role、类型、payload 与原始证据引用。厂商事件解析与字段归属仍由 04 定义；项目生命周期索引仍由 10 定义。

以下新增字段名是供 04 采用或审定的公共封装建议，不表示当前 Pi 已输出这些字段。

| 字段 | 类型/约束 | 说明 |
|---|---|---|
| `schema_version` | 正整数；本建议记录版本为 1 | 公共事件版本，不是合同版本 |
| `record_type` | 固定 `run-event` | 与其他公共记录分派 |
| `request_id`、`run_id` | 见 4.1 | 从受信运行上下文注入，不信任厂商代填 |
| `seq` | 正整数；建议从 1 连续递增 | 由 run 日志写入方分配，厂商自有序号另存 |
| `observed_at` | UTC；建议 `YYYY-MM-DDTHH:MM:SS.ffffffZ` | 核心观察时间；表示精度不等于时钟真实精度 |
| `role` | planner/executor/observer；无角色核心事件可为空 | 不允许厂商消息越权改变已绑定角色 |
| `type` | 由 04/核心注册的事件名 | `payload` 必须按对应类型验证 |
| `source_kind` | `core` 或 `vendor` | 明确来源，不用伪造 vendor 事件补缺失 |
| `payload` | 类型注册表定义的对象 | 公共 Schema 只验证封装，不能代替类型 Schema |
| `raw_refs` | 原始证据分段引用和字节范围 | 空数组只有在来源/完整性允许时合法 |
| `integrity` | complete/incomplete/pending | 指该事件的证据完整性，不是整个 run 的验收结果 |
| `adapter_revision` | 适配器修订标识或空 | vendor 派生事件应绑定解析版本 |

标准时间建议统一由核心生成 UTC 表示，厂商时间原样保留在来源信息中。耗时与超时使用单调时钟差值，不以墙上时间相减作为唯一依据。Python 的 `time.monotonic()` 适用于不随系统时钟调整回退的间隔计量；绝对值不作为跨机器时间戳。[^R10]

**合成核心事件示例**：

```json
{
  "schema_version": 1,
  "record_type": "run-event",
  "request_id": "req-11111111111141118111111111111111",
  "run_id": "run-22222222222242228222222222222222",
  "seq": 1,
  "observed_at": "2026-09-25T00:00:00.000000Z",
  "role": "planner",
  "type": "run.prepared",
  "source_kind": "core",
  "payload": {"example_only": true},
  "raw_refs": [],
  "integrity": "complete",
  "adapter_revision": null
}
```

这条样例只是说明运行上下文已准备，不证明子进程或模型已启动；即使事件本身 `integrity=complete`，run 仍可能未执行。`run.prepared` 为本版建议事件名，正式接入需登记载荷 Schema。

#### 4.3.2 seq、重放与并发写入

`seq` 建议定义为**核心持久日志的观察顺序**，不是厂商内部因果顺序。不同 stdout/stderr 流中的消息若缺少厂商统一序号，不得宣称本地接收次序就是厂商真实发生次序。

| 情况 | 处理规则 |
|---|---|
| 首条已提交事件 | `seq=1` |
| 后续新事件 | 单写入方或事务分配 `last_committed_seq+1` |
| 重放同一事件，序号与封存内容相同 | 幂等返回已存在，不再次扣费 |
| 同一 `(run_id, seq)` 携带不同内容 | `E_EVENT_REPLAY_CONFLICT`，隔离冲突 |
| 已提交序号出现缺口 | 标记日志不完整，等待恢复或终止调查；不静默跳过 |
| 进程崩溃后恢复 | 从持久记录恢复序号，不只依赖内存计数 |
| 跨 run 的先后关系 | 由 10 的项目游标和显式依赖表达，不按时间戳强造全序 |
| 同一原始证据换新解析器重建视图 | 新建派生视图修订，保留来源；不覆盖旧已承诺事件 |

序号分配与事件持久提交要在同一事务/追加机制内协调。不能先把 seq 发给订阅方、稍后持久化失败却仍宣称事件已经可靠存在。对外实时预览可使用 `pending` 语义，但不得把尚未封存的预览作为最终审核证据。

回放中的“内容相同”应比较已封存的标准记录版本/字节或受信摘要，而不是重新运行不确定摘要器得到的自然语言。派生视图应有独立的 `view_id` 或版本记录；这不属于新增模型 run。

#### 4.3.3 原始流、脱敏与不可变分段

**原文保留**：厂商原始流经脱敏保留，标准化事件保留其来源；未知或损坏的关键协议内容应标记不完整。

本版进一步区分以下对象，避免“原始”一词掩盖内容已变换：

| 表示 | 含义 | 摘要覆盖什么 |
|---|---|---|
| `captured_raw` | 受控采集的原始字节，仅在明确允许保留时存在 | 实际采集字节；默认不对外共享 |
| `redacted_raw` | 对采集流按版本化规则脱敏后的证据 | 脱敏后的最终字节，不是脱敏前字节 |
| `normalized_event` | 适配器解释后的标准结构 | 标准事件自己的文件字节 |
| `synthetic_fixture` | 人工/程序构造的测试样本 | 合成文件字节，无真实厂商来源声明 |

脱敏元数据至少记录表示类型、来源类别、脱敏规则修订、是否改变字节长度、是否保留协议结构、来源是否可追溯。不能在公开元数据里记录秘密原值；真实原流是否短期保留必须有权限、保留期和访问控制，不以调试方便为由默认永久保留。

原始流尚在追加时，整个文件摘要会变化。建议按不可变 segment 封存，每段有独立 ResourceRef；事件引用已封存段的半开区间 `[byte_start, byte_end)`。范围必须满足 `0 <= start < end <= segment_size`，偏移以**被引用版本的字节**计，不是字符计数。

如果脱敏改变长度，不能继续使用脱敏前偏移定位脱敏后文件。需要生成新的映射/范围，或明确只引用完整脱敏段。无法保证语义字段未被脱敏破坏时，该 fixture 不能证明该字段的真实协议兼容性。

建议流程：

```text
受控采集 → 按规则脱敏/必要的可逆字节编码 → 分段封存
        → 生成来源 Manifest → 解析标准事件 → 关联证据范围
        → 标记解析与采集完整性 → 供检查/记账读取
```

无效 UTF-8 或二进制碎片可按明确的字节编码保留，但编码副本应标注 representation，不把编码后的文本当成厂商原始 JSON。大小上限、分段阈值、敏感字段表和原始协议分类由 04 最终确定。

#### 4.3.4 关键未知内容与终止判定

建议 04 在受信注册表中将协议内容分为 `known_required`、`known_optional` 和 `unknown`。未知内容默认不能被模型自行宣布为无关；只有预先明确可忽略的可选类别才允许不影响关键完整性。

| 观察组合 | 标准视图应表达 | 不允许的做法 |
|---|---|---|
| 退出 0，结束证据缺失 | process 正常退出；协议不完整 | 自动 verdict PASS |
| 结束事件声称成功，但进程非零退出 | 来源冲突或执行失败待评估 | 只保留成功结束事件 |
| 出现无法解析的关键消息 | `integrity=incomplete` 并保留证据 | 过滤后声称“剩下的都成功” |
| 用量消息缺失，其他结束证据完整 | 运行完成与用量未知分别表达 | 把缺失费用补成 0 |
| 取消后进程退出 | 记录取消来源和退出事实 | 把主动取消归为正常成功 |
| 完整事件被重复投递 | 去重后保持一次观察 | 重复累计 token 或费用 |
| 终止后出现新关键内容 | 异常/补充记录，由 04/07 的规则处理 | 悄悄修改旧最终结论 |

`protocol_complete`、`usage_complete`、`process_exited` 和 `legacy_verdict` 应是独立维度。01 规定不可混淆，04 负责协议完整性，07/现有调度器负责运行与门禁，10 负责集成记录。

#### 4.3.5 厂商证据不能授予控制权限

厂商流、模型输出、插件文本和导入 fixture 都是不受信数据。即使它们包含 `request_id`、`role`、`approved=true` 或“请忽略之前限制”，也不得覆盖受信上下文、审核记录或受保护路径范围。

标准化时应按字段归属表明确：核心绑定字段由核心提供；厂商报告字段标为 reported；推断字段标为 derived；未知字段保持未知。未经验证的“模型自报实际模型名”不能自动提升为由 CLI/供应商元数据支持的同等级证据。

#### 4.3.6 结构化错误与退出兼容

原文最低字段保留：`code`、`message`、`details`、`retryable`。建议 `details` 固定为字段指针、来源引用、阶段、原因与可选处理提示；不得直接回显整段输入、密钥或机器私有路径。

```json
{
  "code": "E_JSON_DUPLICATE_KEY",
  "message": "输入对象包含重复字段，不能形成审核输入。",
  "details": {
    "field": "/profiles/default/model",
    "source_ref": null,
    "phase": "decode",
    "reason": "duplicate_object_member",
    "hint": "修正重复字段后重新提交；不要保留最后一个值后继续审核。"
  },
  "retryable": false
}
```

| 错误类别 | 建议错误码 | 自动重试含义 |
|---|---|---|
| 输入格式 | `E_JSON_*`、`E_SCHEMA_*`、`E_INTEGER_RANGE` | 通常需修正输入，不重复执行同样载荷 |
| 路径/访问 | `E_PATH_SYNTAX`、`E_PATH_RESERVED`、`E_PATH_ESCAPE`、`E_PATH_RESOLUTION_FAILED` | 不能靠放宽边界“修复” |
| 资源校验 | `E_RESOURCE_KIND`、`E_RESOURCE_HASH_MISMATCH`、`E_RESOURCE_CYCLE` | 不重算期望摘要来强行通过 |
| Git 对象 | `E_GIT_OBJECT_MISSING`、`E_GIT_OBJECT_TYPE`、`E_GIT_FORMAT_UNSUPPORTED` | 先确认基线/环境，不自动拉取或改仓库 |
| 事件完整性 | `E_EVENT_GAP`、`E_EVENT_REPLAY_CONFLICT`、`E_PROTOCOL_INCOMPLETE` | 可恢复读取，但不自动重新调用模型 |
| 用量 | `E_USAGE_CONFLICT`、`E_USAGE_SCOPE_UNKNOWN`、`E_USAGE_CURRENCY_MISMATCH` | 进入核对/拒绝聚合，不补零 |
| 基线/兼容 | `E_BASELINE_DRIFT`、`E_BASELINE_INPUT_MISSING`、`E_COMPAT_UNSUPPORTED` | 重新取证或明确不支持 |

错误码是机器接口；message 可以改进措辞而不改变 code。每个单一缺陷反例应匹配唯一预期原因，但多缺陷输入不要求所有解析器都选同一个首错。

`retryable=true` 仅表示某种重试有可能恢复，仍须通过授权、预算、状态和幂等检查；它不是执行命令。旧入口 0/1/2/3/4 与 `wait` 的“仍在运行”语义保留，具体映射在 01-T1 从源码和测试逐入口取证，本文不猜编号含义。

#### 4.3.7 用量观测字段

本节定义观测，不定义扣款。07 是预算与用量记账的唯一责任模块；适配器、事件摘要和 UI 不得各自再记一次。

| 字段 | 类型与语义 |
|---|---|
| `usage_id` | 一条观测的逻辑 ID；用于修订与重复识别 |
| `request_id`、`run_id`、`role` | 从可信调用上下文绑定 |
| `provider`、`model` | 已有证据支持的来源/模型；未知为 null |
| `observation_kind` | `delta`、`cumulative`、`final` 或 `unknown` |
| `input_tokens` | 厂商或计量源报告的输入口径；不预设含/不含缓存 |
| `cache_read_tokens`、`cache_write_tokens` | 分别记录；缺失为 null |
| `output_tokens`、`reasoning_tokens` | 分别保留来源口径，不默认可相加 |
| `input_includes_cache`、`output_includes_reasoning` | 已知口径用布尔值，未知用 null |
| `reported_cost` | 来源报告费用；`amount` 为非负十进制字符串，`currency` 为已识别币种 |
| `estimated_cost` | 按明确价目/规则估算的费用，不能冒充 reported |
| `billing_source` | vendor_reported/provider_invoice/adapter_estimated/unavailable |
| `billing_event_id` | 厂商稳定账单/用量标识；没有则为 null |
| `supersedes_usage_id` | 明确取代的旧观测；无修订时为 null |
| `unknown_reasons` | 计量、费用、模型等未知字段的原因字典 |
| `evidence_refs` | 原始/脱敏证据或受信账单引用 |

对计量值，`0` 表示确有证据支持的零；`null` 表示未知或不可用。`supersedes_usage_id=null` 等关联字段为空不一定代表证据缺失，不应为每一个合法空关联制造告警。

货币金额不用二进制浮点直接累计，十进制字符串不能带货币符号、千分位、指数或空格。本文核心观测样例仅允许非负费用；退款、抵扣或账单调整应由 07 定义独立调整类型，不能塞进负 token 或悄悄覆盖旧观测。

#### 4.3.8 累计、增量、修订与重复的处理表

| 输入观测 | 合法解释 | 错误解释 |
|---|---|---|
| 同一 run 累计输入 100，随后累计 150 | 同一范围下当前累计为 150 | 100+150=250 |
| 两条独立 delta 输入 100 与 50 | 去重后合计 150 | 只取最大值 100 |
| 同一 usage_id 被再次投递 | 保持一次 | 再计一次 |
| final 观测明确修订前一观测 | 保留修订链，按规则替代有效值 | 将旧值与新值都加总 |
| 部分输入 100，另一个组成部分未知 | 展示已知部分 100，并标记总量不完整 | 声称完整总量=100 |
| input=1000，其中 cache_read=800 且说明已包含 | 输入总数仍为 1000，缓存细分为 800 | 再加缓存得到 1800 |
| reported_cost 缺失，只有 estimated_cost | 可显示估算与依据；实际费用未知 | 把估算写成供应商实际收费 |
| USD 与 CNY 观测 | 分币种汇总 | 直接相加为一个金额 |
| 两个来源范围不明的观测 | `E_USAGE_SCOPE_UNKNOWN` 或待核对 | 为得到整齐数字而猜口径 |

建议 07 优先使用“provider + 受控账户范围 + billing_event_id”作为有外部稳定身份的去重依据；同时验证它映射到哪次调用。缺外部标识时采用核心定义的 run/计量范围/观测版本键，并明确冲突规则，不能单以金额相等认定重复。

最终实际汇总应按币种分组且包含 `known_total`、`is_complete`、`unknown_count`。任何缺失证据都必须向聚合结果传播。预算在未知用量下是否暂停、预留或人工复核由 07 的已批准策略决定，不能由 01 默认视作免费。

本次主会话用量不可由这些项目样例测得，因此本文不报告节省比例、真实 token 或真实成本。

#### 4.4.2 严格 Schema 与显式兼容分派

```text
受信入口声明 expected_kind / expected_family
    → 受控读取原字节
    → 选择明确的历史只读路径或新入口
    → 严格解析与版本检查
    → 对应 Schema 与语义校验
    → 形成可消费的受限视图
```

新 Schema 未识别时返回不支持，不得去掉字段后尝试 v1。配置中的 `_...` 说明字段例外只在 02 明确登记的位置生效；审核、合同和插件不能继承这一例外。扩展字段只能在预先定义的扩展容器中使用，不能通过任意未知顶层字段逃逸严格校验。

历史读取与新的执行授权分开：历史记录即使存在歧义，也应保留原字节和原规则下可重现的判断；但它不能因为被标注 legacy 就自动成为当前可派遣输入。若安全入口收紧与旧测试预期冲突，必须登记兼容差异并由正式决策处理，不能宣称完全兼容。

#### 4.4.3 纯协议模块的依赖约束

`scripts/codekit/protocols.py` 建议只依赖标准库和已明确锁定的 Schema 验证依赖。导入模块时不得读取密钥、探测模型、扫描整个工作区、启动 CLI、获取网络资源或修改文件。

资源类型注册表和 Schema 解析应使用随包提供的本地可信资源；运行时不因 `$ref` 或 `kind` 自动访问外网下载 Schema。公共 API 的错误与版本检查应在新消费者中先采用，再经差异验证逐步迁移旧入口。

## 6. 实施步骤

### 6.1 阶段 0：确认授权、输入和运行边界

实施前读取当前 `AGENTS.md` 与总设计，核实允许的文件范围、解释器、离线 profile、预算与受保护文件。确认 `tests/stub_pi.py` 是否真正覆盖所有 CLI 启动入口、是否有后台进程/网络/凭据访问。仅看到文件名含 stub 不足以证明离线。

建议在无真实凭据、受控网络与专用临时仓库环境执行；网络禁止必须由环境实际实现，不能把设置一个自创环境变量描述成已经隔离。不得为运行测试自动安装包、联网拉取模型或运行未经确认的 `pi --version` 包装脚本。

**阻断条件**：授权不明、输入缺失、解释器不明确、stub 无法核实、测试会触达真实生产资源。记录 BLOCKED，而不是跳过限制继续执行。

### 6.2 阶段 1：采集实际 HEAD、工作区与环境

以下是**实施命令清单，本文未在项目仓库执行**。命令使用可信 argv 与明确 cwd；输出必须按二进制保存，避免终端/PowerShell 文本重编码改变证据。

| 目的 | 建议命令/操作 | 必须保留 |
|---|---|---|
| Python 环境 | 选择的解释器执行 `--version` | 实际 argv、版本、解释器定位事实 |
| Git 环境 | `git --version` | 完整版本输出和退出码 |
| 仓库根 | `git rev-parse --show-toplevel` | 受控环境记录，不混入业务路径 |
| 实际提交 | `git rev-parse --verify --end-of-options HEAD^{commit}` | 完整 OID、stderr、退出码 |
| 对象格式 | `git rev-parse --show-object-format=storage` | 格式值或不支持证据 |
| 工作区状态 | `git -c core.fsmonitor=false status --porcelain=v1 -z --untracked-files=all` | 原始 NUL 分隔字节 |
| 未暂存差异 | `git --no-pager diff --no-ext-diff --no-textconv --binary` | 原始差异字节，留意敏感内容 |
| 已暂存差异 | `git --no-pager diff --cached --no-ext-diff --no-textconv --binary` | 原始差异字节 |
| 相关输入 | 按受信输入清单读取并生成摘要 | 已跟踪、相关未跟踪、依赖/配置事实 |
| 平台特性 | 记录 OS、架构、文件系统能力和允许的环境变量名称 | 不输出所有环境变量值 |

Git 的 porcelain v1 格式面向脚本并有稳定格式承诺；使用 `-z` 可避免把含空格/特殊字符的路径错误拆分。实现解析仍需按该格式处理重命名等记录，而非简单逐行 split。[^R11]

禁止使用 `git reset --hard`、`git clean -fdx`、强制 checkout 或批量行尾转换制造“干净基线”。脏工作区应如实记录；是否允许在该基线上测试由正式合同决定。

基线证据默认写入专用且受保护的输出目录，不写进尚未采集完成的输入范围。对报告目录的排除必须精确且有记录，不能用过宽排除掩盖输入变化。

仓库外临时采集路径属于环境事实，不得直接填入 ResourceRef 的业务 `path`。需要正式文件引用时，应在授权下将已脱敏、封存的证据归档到仓库管理的证据路径，再生成仓库相对引用；外部采集位置留在受控环境记录。基线前后采样应在归档造成的新文件变化之前完成，或事先精确登记该受控输出目录不属于测试输入。

### 6.3 阶段 2：运行现有离线基准

原文入口保持：

```text
python tests/test_dispatch.py
```

解释器名称按实际平台/profile 选择，不假定所有机器都用 `python3`。该入口的退出码来自**测试进程**，不是来自管道末端的日志工具。

每次运行最少记录：实际 argv 数组、cwd 的受控记录、解释器/工具链版本、输入基线引用、开始/结束 UTC、单调耗时、进程退出码或信号、stdout/stderr 引用、是否完整采集、测试框架汇总、未运行项、平台限制。

若需要示范二进制采集，可采用以下模式。它只展示输出捕获，不提供完整进程树超时/取消机制；正式执行必须置于经批准的现有监督器中，不能把此片段当成新的 `run_supervised`。

```python
from pathlib import Path
import subprocess
import time


def capture_once(argv: list[str], cwd: Path, output_dir: Path) -> dict:
    # argv、cwd、output_dir 均须由受信调用方确定；此函数不做授权。
    # output_dir 应是专用目录；"xb" 防止覆盖已有日志。
    started = time.monotonic()
    with (output_dir / "stdout.bin").open("xb") as out:
        with (output_dir / "stderr.bin").open("xb") as err:
            completed = subprocess.run(
                argv, cwd=cwd, stdin=subprocess.DEVNULL,
                stdout=out, stderr=err, shell=False, check=False,
            )
    return {
        "argv": argv,
        "returncode": completed.returncode,
        "duration_seconds": time.monotonic() - started,
        "interpretation": "not_evaluated",
    }
```

输出可能含敏感内容，原始捕获目录须受控；只有完成脱敏和来源记录后的证据才能进入共享 fixtures。启动失败、写盘失败或监督器中断须由外层报告 ERROR/不完整，不把不存在的 returncode 补为 0。

**通过判据**：基线一致、进程结果符合该测试入口规则、测试框架明确完成预期检查、没有被隐去的失败或必要未运行项、证据可读取且可核验。退出码 0 是必要证据之一，不是充分条件。

建议报告字段如下。未采集时为 null/NOT_RUN，不能填看似合理的版本、数量或哈希。

| 报告分区 | 必填信息 |
|---|---|
| `identity` | 报告 ID、schema/报告格式版本、创建主体、源文档引用 |
| `baseline` | 调查提交、实际 HEAD、对象格式、输入 Manifest、前后采样、是否一致 |
| `environment` | platform、架构、工具链、环境锁、隔离事实、能力限制 |
| `checks[]` | check ID、命令、预期、实际结果、状态、证据类型、日志引用 |
| `legacy_inventory[]` | 函数/测试位置、旧行为、旧状态枚举和退出语义取证 |
| `compatibility[]` | 资源类型、版本、平台、支持能力、限制 |
| `acceptance[]` | A 编号、结果、证据、未满足原因 |
| `limitations[]` | 未取得输入、未运行项、不支持平台、日志缺失、预算限制 |

建议一条未运行记录如下。此为报告模板，不属于附录 A 的运行事件：

```json
{
  "check_id": "legacy-dispatch-full-suite",
  "argv": ["python", "tests/test_dispatch.py"],
  "execution_status": "NOT_RUN",
  "evidence_basis": "source_reported",
  "returncode": null,
  "baseline_ref": null,
  "stdout_ref": null,
  "stderr_ref": null,
  "reason": "本次未提供项目仓库，未执行该命令。"
}
```

报告模板中的 null 引用不是真正的 ResourceRef。正式报告格式应允许未运行记录为空，但一旦将状态标为 PASS，必须要求对应基线与证据引用齐全，不能靠字段全部可空绕过取证。

### 6.6 阶段 5：建立兼容 fixtures

| 步骤 | 操作 | 成功判据 |
|---|---|---|
| 选样 | 覆盖正常、缺字段、失败、超时、取消、恢复、候选漂移等旧场景 | 每类有来源；缺样本如实登记 |
| 固定来源 | 记录仓库提交/测试标识/原采集条件 | 可追到原始依据，不是“模型记忆” |
| 脱敏 | 版本化规则，必要时保留字段结构但替换秘密 | 无真实凭据；不破坏待证明的协议语义 |

| 锁定预期 | 从旧实现/旧证据得到关键判断 | 不把新实现的输出自动当旧预期 |

| 审核 | 检查来源、脱敏、预期与能力声明 | 未修改样本换取通过 |

兼容测试不能只比较“均无异常”。至少比较 normalize 后关键默认值、合同校验判断、缺证据状态、候选/补丁判断、门禁结果和旧入口状态解释；具体字段在 01-T1 锁定。

## 8. 兼容与恢复

### 8.1 能力矩阵，而非单一“兼容”布尔值

| 输入类型 | 读取/审计 | 当前新执行入口 | 处理要求 |
|---|---|---|---|
| 已支持且来源完整的 v1 历史合同/证据 | 按旧规则读取 | 经明确兼容分支与当前授权检查后才可使用 | 保留旧能力说明，不暗示新审核已具备 |
| 本文新增公共记录 v1 | 新消费者按对应家族读取 | 只有相应功能已实现/授权时可消费 | 不能当作合同 v1 |
| 已知家族、未知版本 | 可保留原字节待升级 | 拒绝 | 不删除字段降级 |
| 未知资源类型 | 可隔离保存 | 拒绝 | 不动态信任远程 Schema |
| 重复键/歧义的历史记录 | 可保留原字节及已核实的旧解释，限审计 | 不因 legacy 标签自动放行 | 登记兼容风险，必要时重新发布明确输入 |
| 损坏/截断证据 | 保留损坏事实与可读部分 | 不能形成完整成功证明 | 不用空对象代替失败 |
| 合成 fixture | 测试 profile 中可使用 | 不得作为真实业务授权或厂商证据 | 来源标签随导出保留 |

历史只读能力不是派遣许可。任何读取兼容与安全收紧冲突都应成为显式迁移决策，而不是在解析器内偷偷覆盖旧语义。

### 8.2 渐进接入与回退顺序

建议先以新入口调用公共模块，旧入口保持原有路径；在 fixture 差分明确后逐步迁移单一消费者。每一步记录启用范围、Schema 版本、回归证据与回退入口。

回退步骤：停止新派遣进入新增入口；按现有监督器处理已在运行的任务；封存新增证据；停用新消费者；恢复经核验的旧入口；对新格式资源保留只读或明确不支持状态；重新核实基线与关键旧回归。

回退不删除新证据、不改写旧合同、不重新生成旧哈希、不把运行中任务强行当成未开始。未知新格式不能为“回退成功”而转换为空配置或旧格式。

### 8.3 故障恢复决策表

| 故障 | 立即处理 | 恢复与升级 |
|---|---|---|
| 日志目录写入失败/磁盘满 | 标记采集不完整，停止发布有效引用 | 修复环境后新建取证记录；保留旧失败 |
| 封存文件成功、索引失败 | 记录未引用候选，不伪造索引成功 | 按相同字节/身份幂等补录或受控清理 |
| 索引引用文件不可读/哈希不符 | 阻断消费与审核 | 核对来源、权限或损坏，不更新期望哈希来消错 |
| 事件序号冲突 | 隔离冲突并冻结受影响视图 | 对照持久日志与来源；交给 04/07 处理 |
| 基线前后漂移 | 保留日志，但撤销该运行作为一致基线证明的资格 | 重新绑定实际输入再运行 |
| fixture 含真实凭据 | 停止分发，限制访问并启动凭据处置 | 脱敏后新建修订；保留受控事故记录 |
| 未知 Schema 或平台功能 | 拒绝对应能力 | 升级实现或收窄能力声明，不能猜默认值 |
| 临时目录归属不明 | 停止清理 | 人工确认；不对用户仓库执行递归删除 |

### 8.4 临时目录与清理安全

沿用原文“专用临时仓库与清理逻辑”原则，但实施前必须核实具体归属。清理应同时验证预期父目录、由本任务创建的随机目录名/标记、真实路径和任务所有权；仅凭字符串包含 `tmp`、文件夹名匹配或存在一个可伪造标记都不充分。

不得把用户仓库、受保护目录、历史证据或共享工作区当可丢弃 fixture。失败时优先保留隔离目录和诊断引用，不在不确定情况下递归删除。

| 对象 | 必需的额外检查 |
|---|---|
| 全部新记录 | 字节大小/深度限制、重复键、UTF-8、非有限数、严格整数类型、受信入口家族 |
| ResourceRef | kind 已登记；文件类型要求 path；合法路径与保护范围；相同已固定字节上的完整 SHA-256 |
| RunContext | 标识由核心分配/绑定；executor 所需字段非空；合同引用、版本、任务与 request 一致 |
| 结构化错误 | 不泄露输入秘密；来源引用可信；retryable 不执行任何动作 |
| 时间 | 日历日期确实有效；启用格式断言；固定 UTC 表示；不以格式精度声称真实时钟精度 |
| 运行事件 | seq 连续/重复/冲突判断；type 注册及 payload Schema；角色和 run 绑定；事件来源 |
| raw_refs | start < end <= 真实被引用段大小；stream 合法；脱敏后偏移与引用版本匹配 |
| vendor 事件 | 解析修订必须已知；没有可引用来源的事件不得声称证据完整 |
| 核心事件 | 空 raw_refs 不能用于伪装厂商成功、模型身份或用量 |
| 用量 | 计数口径、累计/增量范围、unknown 原因、费用来源、币种是否识别、修订链与唯一记账 |
| Schema 路由 | 新版本不能回退 v1；未知字段不能静默丢弃；加载 Schema 不允许外发 |

事件封装 `payload` 允许对象，是因为具体字段归 04 的类型 Schema；这不是“任意 payload 可执行”。用量的 `unknown_reasons` 开放键用于字段级原因，正式消费者应限制键名属于可未知字段及其明确子路径，拒绝借此塞入控制参数。

```python
"""Code-Kit 01 reference helpers; not the project's production implementation.

Only validates JSON values, lexical paths, a static path preview and byte hashes.
It does NOT implement authorization, race-safe file access, dispatch or billing.
"""
from __future__ import annotations

import hashlib
import hmac
import json
import math
import re
from pathlib import Path
from typing import Any

MAX_SAFE_INTEGER = 2**53 - 1
SHA256_RE = re.compile(r"[0-9a-f]{64}\Z")
ID_RE = re.compile(r"[a-z0-9][a-z0-9._:-]{0,127}\Z")
KIND_RE = re.compile(r"[a-z][a-z0-9-]{0,63}\Z")
RESERVED = {"CON", "PRN", "AUX", "NUL", "CONIN$", "CONOUT$"} | {
    prefix + digit for prefix in ("COM", "LPT")
    for digit in tuple("123456789") + ("¹", "²", "³")
}


class ProtocolError(ValueError):
    def __init__(self, code: str, *, field: str | None = None,
                 reason: str = "invalid value", retryable: bool = False):
        super().__init__(code)
        self.code = code
        self.details = {"field": field, "reason": reason}
        self.retryable = retryable


def _pointer(parent: str, key: str | int) -> str:
    escaped = str(key).replace("~", "~0").replace("/", "~1")
    return parent + "/" + escaped


def _unicode_scalar_string(value: str, field: str) -> None:
    if any(0xD800 <= ord(c) <= 0xDFFF for c in value):
        raise ProtocolError("E_JSON_UNICODE", field=field,
                            reason="unpaired surrogate is not allowed")


def _check_depth(text: str, max_depth: int) -> None:
    depth, in_string, escaped = 0, False, False
    for char in text:
        if in_string:
            if escaped:
                escaped = False
            elif char == "\\":
                escaped = True
            elif char == '"':
                in_string = False
        elif char == '"':
            in_string = True
        elif char in "[{":
            depth += 1
            if depth > max_depth:
                raise ProtocolError("E_JSON_LIMIT", reason="nesting limit exceeded")
        elif char in "]}":
            depth -= 1
    # Bracket correctness, escape validity and unfinished strings are checked by json.


class _Pairs(list):
    """Keep object pairs until duplicate names can be checked with a JSON Pointer."""


def _reject_constant(_: str) -> Any:
    raise ProtocolError("E_JSON_NON_FINITE", reason="non-finite numeric literal")


def _parse_float(text: str) -> float:
    value = float(text)
    if not math.isfinite(value):
        raise ProtocolError("E_JSON_NON_FINITE", reason="numeric conversion overflow")
    return value


def _parse_int(text: str) -> int:
    if len(text.lstrip("-")) > 16:
        raise ProtocolError("E_INTEGER_RANGE", reason="integer outside public profile")
    value = int(text)
    if abs(value) > MAX_SAFE_INTEGER:
        raise ProtocolError("E_INTEGER_RANGE", reason="integer outside public profile")
    return value


def _materialize(value: Any, field: str = "") -> Any:
    if isinstance(value, _Pairs):
        result: dict[str, Any] = {}
        for key, item in value:
            child = _pointer(field, key)
            _unicode_scalar_string(key, child)
            if key in result:
                raise ProtocolError("E_JSON_DUPLICATE_KEY", field=child,
                                    reason="duplicate object member")
            result[key] = _materialize(item, child)
        return result
    if isinstance(value, list):
        return [_materialize(item, _pointer(field, i)) for i, item in enumerate(value)]
    if isinstance(value, str):
        _unicode_scalar_string(value, field)
    return value


def strict_json_loads(raw: bytes, *, max_bytes: int = 1_048_576,
                      max_depth: int = 64) -> Any:
    if type(raw) is not bytes:
        raise ProtocolError("E_JSON_INPUT_TYPE", reason="bytes input required")
    if not 1 <= len(raw) <= max_bytes:
        raise ProtocolError("E_JSON_LIMIT", reason="empty input or byte limit exceeded")
    if raw.startswith(b"\xef\xbb\xbf"):
        raise ProtocolError("E_JSON_BOM", reason="UTF-8 BOM not accepted in new protocol")
    try:
        text = raw.decode("utf-8", errors="strict")
    except UnicodeDecodeError as exc:
        raise ProtocolError("E_JSON_ENCODING", reason="UTF-8 decoding failed") from exc
    _check_depth(text, max_depth)
    try:
        parsed = json.loads(text, object_pairs_hook=_Pairs, parse_constant=_reject_constant,
                            parse_float=_parse_float, parse_int=_parse_int)
        return _materialize(parsed)
    except json.JSONDecodeError as exc:
        raise ProtocolError("E_JSON_SYNTAX",
                            reason=f"syntax error at line {exc.lineno}, column {exc.colno}") from exc
    except RecursionError as exc:
        raise ProtocolError("E_JSON_LIMIT", reason="decoder recursion limit exceeded") from exc


def _check_value(value: Any, field: str = "", depth: int = 0,
                 ancestors: set[int] | None = None) -> None:
    if depth > 64:
        raise ProtocolError("E_JSON_LIMIT", field=field, reason="nesting limit exceeded")
    if ancestors is None:
        ancestors = set()
    kind = type(value)
    if value is None or kind is bool:
        return
    if kind is str:
        _unicode_scalar_string(value, field)
        return
    if kind is int:
        if abs(value) > MAX_SAFE_INTEGER:
            raise ProtocolError("E_INTEGER_RANGE", field=field)
        return
    if kind is float:
        if not math.isfinite(value):
            raise ProtocolError("E_JSON_NON_FINITE", field=field)
        return
    if kind not in (list, dict):
        raise ProtocolError("E_JSON_VALUE_TYPE", field=field,
                            reason="only JSON-native values are accepted")
    identity = id(value)
    if identity in ancestors:
        raise ProtocolError("E_JSON_CYCLE", field=field, reason="cyclic container")
    ancestors.add(identity)
    try:
        if kind is dict:
            for key, item in value.items():
                if type(key) is not str:
                    raise ProtocolError("E_JSON_KEY_TYPE", field=field,
                                        reason="object keys must be strings")
                child = _pointer(field, key)
                _unicode_scalar_string(key, child)
                _check_value(item, child, depth + 1, ancestors)
        else:
            for index, item in enumerate(value):
                _check_value(item, _pointer(field, index), depth + 1, ancestors)
    finally:
        ancestors.remove(identity)


def stable_snapshot_bytes(value: dict[str, Any]) -> bytes:
    """Input must ALREADY be the schema-validated semantic projection from module 02."""
    if type(value) is not dict:
        raise ProtocolError("E_SCHEMA_TYPE", reason="snapshot root must be an object")
    _check_value(value)
    encoded = (json.dumps(value, ensure_ascii=False, sort_keys=True,
                          separators=(",", ":"), allow_nan=False) + "\n").encode("utf-8")
    if len(encoded) > 1_048_576:
        raise ProtocolError("E_JSON_LIMIT", reason="snapshot byte limit exceeded")
    return encoded


def require_schema_version(value: dict[str, Any], supported: set[int]) -> int:
    version = value.get("schema_version")
    if type(version) is not int or version < 1:
        raise ProtocolError("E_SCHEMA_VERSION_TYPE", field="/schema_version")
    if version not in supported:
        raise ProtocolError("E_SCHEMA_VERSION_UNSUPPORTED", field="/schema_version")
    return version


def validate_business_path(value: str) -> str:
    """Portable lexical profile only; not an authorization or filesystem safety check."""
    if type(value) is not str or not value:
        raise ProtocolError("E_PATH_SYNTAX", field="/path", reason="nonempty string required")
    _unicode_scalar_string(value, "/path")
    if len(value.encode("utf-8")) > 4096:
        raise ProtocolError("E_PATH_SYNTAX", field="/path", reason="path length limit")
    if value.startswith("/") or any(c in value for c in '\\:<>"|?*'):
        raise ProtocolError("E_PATH_SYNTAX", field="/path", reason="nonportable path syntax")
    if any(ord(c) < 32 or ord(c) == 127 for c in value):
        raise ProtocolError("E_PATH_SYNTAX", field="/path", reason="control character")
    for segment in value.split("/"):
        if (segment in ("", ".", "..") or segment.endswith((".", " "))
                or len(segment.encode("utf-8")) > 255):
            raise ProtocolError("E_PATH_SYNTAX", field="/path", reason="invalid path component")
        if segment.split(".", 1)[0].upper() in RESERVED:
            raise ProtocolError("E_PATH_RESERVED", field="/path", reason="reserved device name")
    return value


def resolve_existing_path_for_review(root: Path, business_path: str) -> Path:
    """Static review only. Never use the returned path as a race-safe open capability."""
    validate_business_path(business_path)
    try:
        trusted_root = root.resolve(strict=True)
        target = (trusted_root / business_path).resolve(strict=True)
        if not trusted_root.is_dir():
            raise ProtocolError("E_PATH_ROOT", reason="trusted root is not a directory")
    except FileNotFoundError as exc:
        raise ProtocolError("E_PATH_NOT_FOUND", field="/path") from exc
    except (OSError, RuntimeError) as exc:
        raise ProtocolError("E_PATH_RESOLUTION_FAILED", field="/path") from exc
    try:
        target.relative_to(trusted_root)
    except ValueError as exc:
        raise ProtocolError("E_PATH_ESCAPE", field="/path") from exc
    return target


def validate_resource_ref(ref: dict[str, Any], *, known_kinds: set[str],
                          file_kinds: set[str]) -> None:
    if type(ref) is not dict:
        raise ProtocolError("E_SCHEMA_TYPE", reason="ResourceRef must be an object")
    required = {"kind", "id", "sha256"}
    if not required <= ref.keys() or set(ref) - required - {"path"}:
        raise ProtocolError("E_SCHEMA_FIELDS", reason="missing or unknown ResourceRef field")
    for field, regex in (("kind", KIND_RE), ("id", ID_RE), ("sha256", SHA256_RE)):
        if type(ref[field]) is not str or not regex.fullmatch(ref[field]):
            raise ProtocolError("E_RESOURCE_FIELD", field="/" + field)
    if ref["kind"] not in known_kinds:
        raise ProtocolError("E_RESOURCE_KIND", field="/kind")
    if ref["kind"] in file_kinds and "path" not in ref:
        raise ProtocolError("E_RESOURCE_PATH_REQUIRED", field="/path")
    if "path" in ref:
        validate_business_path(ref["path"])


def verify_resource_bytes(ref: dict[str, Any], raw: bytes, *, known_kinds: set[str],
                          file_kinds: set[str]) -> None:
    validate_resource_ref(ref, known_kinds=known_kinds, file_kinds=file_kinds)
    if type(raw) is not bytes:
        raise ProtocolError("E_RESOURCE_BYTES", reason="bytes input required")
    actual = hashlib.sha256(raw).hexdigest()
    if not hmac.compare_digest(actual, ref["sha256"]):
        raise ProtocolError("E_RESOURCE_HASH_MISMATCH", field="/sha256")
```

import hashlib
import json
import os
import tempfile
import unittest
from pathlib import Path

from protocols_reference import (ProtocolError, strict_json_loads, stable_snapshot_bytes,
    require_schema_version, validate_business_path, resolve_existing_path_for_review,
    validate_resource_ref, verify_resource_bytes)

class ProtocolReferenceTests(unittest.TestCase):
    def rejects(self, code, function, *args, **kwargs):
        with self.assertRaises(ProtocolError) as caught:
            function(*args, **kwargs)
        self.assertEqual(caught.exception.code, code)
        return caught.exception

    def test_json_positive(self):
        value = strict_json_loads('{"文字":"测试","n":1,"a":[null,true,1.5]}'.encode())
        self.assertEqual(value['文字'], '测试')
        self.assertEqual(value['n'], 1)

    def test_duplicate_member_pointer(self):
        exc = self.rejects('E_JSON_DUPLICATE_KEY', strict_json_loads,
                           b'{"a":[{"x/y":1,"x/y":2}]}')
        self.assertEqual(exc.details['field'], '/a/0/x~1y')

    def test_escaped_duplicate(self):
        self.rejects('E_JSON_DUPLICATE_KEY', strict_json_loads, b'{"a":1,"\\u0061":2}')

    def test_non_finite_literals_and_overflow(self):
        for value in (b'NaN', b'Infinity', b'-Infinity', b'1e10000'):
            with self.subTest(value=value):
                self.rejects('E_JSON_NON_FINITE', strict_json_loads, value)

    def test_bom_and_encoding(self):
        self.rejects('E_JSON_BOM', strict_json_loads, b'\xef\xbb\xbf{}')
        self.rejects('E_JSON_ENCODING', strict_json_loads, b'\xff')

    def test_surrogate_rejected_but_pair_accepted(self):
        self.rejects('E_JSON_UNICODE', strict_json_loads, b'"\\ud800"')
        self.assertEqual(strict_json_loads(b'"\\ud83d\\ude00"'), '\U0001f600')

    def test_trailing_data(self):
        self.rejects('E_JSON_SYNTAX', strict_json_loads, b'{}{}')

    def test_limits(self):
        self.rejects('E_JSON_LIMIT', strict_json_loads, b'{}', max_bytes=1)
        self.rejects('E_JSON_LIMIT', strict_json_loads, b'[[[]]]', max_depth=2)
        self.assertEqual(strict_json_loads(b'{"literal":"[[["}', max_depth=1), {'literal':'[[['})

    def test_integer_boundary(self):
        self.assertEqual(strict_json_loads(b'9007199254740991'), 2**53-1)
        self.rejects('E_INTEGER_RANGE', strict_json_loads, b'9007199254740992')

    def test_version_is_exact_integer(self):
        for value in (True, '1', 1.0, 0, None):
            with self.subTest(value=value):
                self.rejects('E_SCHEMA_VERSION_TYPE', require_schema_version,
                             {'schema_version':value}, {1})
        self.assertEqual(require_schema_version({'schema_version':1}, {1}),1)
        self.rejects('E_SCHEMA_VERSION_UNSUPPORTED', require_schema_version,
                     {'schema_version':2}, {1})

    def test_snapshot_order(self):
        self.assertEqual(stable_snapshot_bytes({'b':2,'a':1}), b'{"a":1,"b":2}\n')
        self.assertEqual(stable_snapshot_bytes({'b':2,'a':1}), stable_snapshot_bytes({'a':1,'b':2}))

    def test_snapshot_keeps_array_and_unicode_distinctions(self):
        self.assertNotEqual(stable_snapshot_bytes({'a':[1,2]}), stable_snapshot_bytes({'a':[2,1]}))
        self.assertNotEqual(stable_snapshot_bytes({'text':'é'}), stable_snapshot_bytes({'text':'e\u0301'}))
        self.assertNotEqual(stable_snapshot_bytes({'n':1}), stable_snapshot_bytes({'n':1.0}))

    def test_snapshot_native_types(self):
        for value, code in [({1:'a'},'E_JSON_KEY_TYPE'), ({'x':(1,2)},'E_JSON_VALUE_TYPE'),
                            ({'x':float('nan')},'E_JSON_NON_FINITE'), ({'x':'\ud800'},'E_JSON_UNICODE')]:
            with self.subTest(code=code):
                self.rejects(code, stable_snapshot_bytes, value)

    def test_cycle_and_reused_container(self):
        cyclic = {}; cyclic['self'] = cyclic
        self.rejects('E_JSON_CYCLE', stable_snapshot_bytes, cyclic)
        shared = [1]
        self.assertEqual(stable_snapshot_bytes({'a':shared,'b':shared}), b'{"a":[1],"b":[1]}\n')

    def test_valid_paths(self):
        for value in ('src/main.py', '文档/说明.md', '.config/profile.json'):
            self.assertEqual(validate_business_path(value), value)

    def test_invalid_paths(self):
        for value in ('/etc/passwd','../x','a/../b','a//b','./x','a/',r'a\b','C:/x','C:x',
                      '//server/share','a\x00b','a\nb','a:stream','a?b','dir./file','a/space '):
            with self.subTest(value=value):
                self.rejects('E_PATH_SYNTAX', validate_business_path, value)

    def test_reserved_windows_names(self):

            with self.subTest(value=value):
                self.rejects('E_PATH_RESERVED', validate_business_path, value)

    def test_static_resolution(self):
        with tempfile.TemporaryDirectory() as directory:
            root = Path(directory); (root/'ok.txt').write_text('ok')
            self.assertEqual(resolve_existing_path_for_review(root,'ok.txt'), root/'ok.txt')
            self.rejects('E_PATH_NOT_FOUND', resolve_existing_path_for_review,root,'missing.txt')

    @unittest.skipUnless(os.name == 'posix', 'requires POSIX symbolic-link fixture')
    def test_static_symlink_escape(self):
