# 13 可选摘要 Observer

状态：拟议实施说明，尚未实现；本文件不是已审核或可直接派遣的任务合同。
上位设计：[总设计](../code-kit-v2-design.md)第 8 节；导航：[实施索引](README.md)。
本模块是可选增强，不阻塞 [12 集成交付](12-integration-and-migration-审阅增强版.md)，默认依靠确定性 brief。

## 1. 目标与非目标

在项目事件较多时，用可配置 CLI/model 压缩已记录的信息，帮助主模型发现待处理问题。
摘要建议应可核对、可丢弃、可禁用；事实、授权和最终判断仍有各自的确定来源。
先证明摘要相比确定性 brief 提供额外阅读价值，再决定是否启用额外模型调用。

- 包含：有边界的摘要请求、来源引用、输出校验、预算、触发抑制和失败降级。
- 包含：把长进度压缩成目标、变化、风险、待决定项及建议下一动作。
- 不包含：写规则/合同/原始证据、派遣、审批、验收、自动集成或修改项目事实。
- 不包含：自由探索仓库、读取凭据、无限循环监督或保证主模型不会遗忘。
- 不让 observer 自己审批其建议，也不让摘要中的“已通过”改变任务状态。

## 2. 依赖与输入输出

必需依赖：[10 项目状态与简报](10-project-state-and-brief.md)已具备可靠事件、来源和恢复能力。
复用 [04 适配器](04-cli-adapters-and-pi.md)的调用证据，以及 [07 调度](07-workflows-and-scheduling.md)的预算与串并行约束。
角色/profile 由模块 02 配置，摘要调用仍遵守模块 03 的授权与锁定边界。

| 输入 | 输出 |
|---|---|
| 固定事件区间、确定性 brief 及必要来源片段 | 带来源的摘要建议 |
| 目标、主模型确认的决定和适用规则索引 | 变化、风险、未决问题与建议下一动作 |
| 允许调用的 profile、预算和时限 | 可追溯的调用结果、用量与失败原因 |

摘要只能消费调度器选定的材料；源事件不允许自行指定新的工具、任意路径或授权。
拟议产物位于 `.agent/project/observer/`，与 `brief.md`、决定和原始 attempt 证据分开。
关闭 observer 时，确定性 `project brief` 与 `project status` 必须继续完整可用。

## 3. 现状与复用点

当前 `cmd_status` 和 `cmd_metrics` 提供 attempt 层面的状态和费用摘要，但没有此角色。
总设计选择先做可重建状态，避免把常驻 agent 的聊天历史当作唯一项目记忆。
已有 CLI 事件采集、超时/取消和费用未知处理可复用；不能新增一条无取证的摘要调用旁路。
模块 10 将提供稳定游标、来源引用和确定性 brief，本模块只增加阅读辅助层。

本次不接入任何摘要模型，也不修改默认 profile 或开启定期联网任务。
启用所需的代码传输和费用授权，应在实施会话中明确覆盖 observer 调用。

## 4. 接口和行为约束

### 4.1 输入与输出协议

ObserverRequest 至少携带 schema、`request_id`、源事件起止游标、brief 引用、来源集合和输出长度限制。
调用绑定解析后的 profile、环境记录、单次时限、重试上限和预算预留。
资源引用复用 `ResourceRef = {kind, id, sha256}`；文件另含仓库相对 `path`。
`sha256` 锁定具体 UTF-8 文件字节；不为摘要另造内容规范化或来源身份规则。
来源只包含必要脱敏片段，不能整份复制巨型日志、环境变量或无关项目内容。

| 摘要字段 | 约束 |
|---|---|
| `source_cursor` / `source_refs` | 表明摘要依据的事件范围和具体来源 |
| `facts` | 每条都含来源，不能把推断写成事实 |
| `hypotheses` | 显式标注推断、缺失信息和核实方法 |
| `risks` / `open_questions` | 指向受影响任务与证据，不自动改为 BLOCKED |
| `suggested_next_actions` | 仅建议，不生成可自动运行的授权 |
| `omitted` | 说明因长度限制省略的项目或来源 |

输出由调度器校验结构、引用存在性和输入边界；引用合法不证明语义正确。
摘要与确定性状态或原证据冲突时标为不可信建议，保持事实投影不变并交主模型核对。
过期、无来源或超出输入的信息不得进入确认决定；不能通过覆盖 brief 隐藏冲突。
observer 不得写 `.agent/runs/`、规则、正式合同、审核记录或确认的决定。
产物和调用记录由调度器受控写入；模型没有管理目录的任意写权限。
禁用不必要工具、固定受控请求和输出入口；需要强制只读时使用真实运行隔离，并验证其约束能力。
适配器不能满足该角色必需约束时拒绝 observer 用途；同账户无隔离仅是流程约束，不能凭提示词宣称操作系统强制只读。

### 4.2 触发、预算与循环抑制

只在配置的事件阈值、阶段边界或主模型明确请求时运行；普通心跳继续用确定性逻辑。
以已处理游标和输入引用集合去重，同一输入不重复消费预算。
运行期间到达的新事件留到下一轮；旧摘要完成后保留其实际游标，不冒充覆盖了新进度。
observer 自己的摘要/调用完成事件不能再次触发同一摘要循环。
使用单飞锁或等效并发控制，同一项目同一摘要范围只能有一个活动请求。
调用计入原 `request_id` 的全局预算，并受独立 observer 上限约束，不能靠新角色重置额度。
调度器启动前预留调用次数/时间预算，结束后按证据结算，未知费用保留 `unknown`。
未回报 token 或费用不表示免费；无法提供金额硬限制时，用次数和时限实现机械停止。
预算不足、超时或协议失败时停止本轮摘要，保持确定性 brief 可读，不阻塞执行验收。
有限重试仍计入预算；达到重试上限后显示失败原因，不自行换模型或扩大权限。

### 4.3 反馈给主模型

默认在主会话检查点拉取 brief 时一并展示有效摘要建议，并标注来源时间与游标。
有真实 host adapter 推送接口时可通知“有新建议”，记录投递状态而非假定主模型已阅读。
宿主没有通知能力时仅支持 pull；后台生成文件不能自动注入任意会话上下文。
主模型可接受建议后另行登记决定，或直接忽略；observer 不能确认自己的输出。
规则核对、配置/合同锁、范围、授权和验收门禁始终由调度器执行，不依赖摘要提醒。
当前主会话 token 不可观测时记 `unknown`，不把 observer 产出短文本当成节省比例的实测值。

## 5. 预计文件范围

- 新增 `scripts/codekit/observer.py` 或职责等价模块，保持摘要调度与事实投影分离。
- 新增输入/输出 schema、来源校验及有限摘要模板。
- 接入角色配置、适配器、预算账本与项目 brief 展示逻辑。
- 新增去重、超时、预算、来源冲突和降级测试及脱敏输出夹具。
- 更新可选功能说明与主会话检查点技能；本机 profile 选择须另行授权。

默认关闭额外模型摘要，确定性模式作为无额外模型的默认行为。
新增 observer 存储默认忽略版本管理，确认的决定仍由模块 10 规定的流程持久保存。

## 6. 实施步骤

1. 用模块 10 的真实简报痛点确定最小输出，固定“事实/推断/建议”的字段和来源约束。
2. 先实现无模型夹具路径，验证只读输入、隔离写入和摘要不可推进项目状态。
3. 接入适配器、预算、触发去重与并发控制，确保失败不会影响确定性 brief。
4. 在授权下选择精确 profile 并做小样本真实摘要，对照原证据检查错漏与阅读价值。
5. 接入主会话拉取入口；有实际宿主接口时再验证通知，保留全部失败降级路径。
6. 根据摘要错误、额外费用和阅读价值决定是否启用，未达预期则保持关闭。

## 7. 验收标准

| 编号 | 场景与通过条件 |
|---|---|
| 13-A01 | 关闭、缺 profile、预算不足或调用失败，确定性 brief 和核心流程仍可用 |
| 13-A02 | facts 有输入内来源，推断与建议显式区分，缺失引用被拒绝或标无效 |
| 13-A03 | 摘要伪称 PASS、授权或规则变更，任务状态和确认决定均不改变 |
| 13-A04 | 重复心跳、相同输入、并发触发及自身事件不会形成重复调用循环 |
| 13-A05 | 调用计入全局 request 和 observer 子预算，重试或角色切换不清零 |
| 13-A06 | 超时、无结束事件、unknown 用量和来源冲突均有可读的降级结果 |
| 13-A07 | 摘要保留实际游标；新事件到达后旧输出不会被显示为最新全部进度 |
| 13-A08 | 无宿主接口只宣称 pull，通知结果与阅读记录分别表达 |
| 13-A09 | 多余工具被禁用，受控请求/输出入口有效；缺角色必需隔离能力时拒绝用途，同账户流程约束不冒称系统强制只读 |

这些是后续可选实施的验收项，本次没有执行摘要调用或测量 token 节省。

## 8. 兼容与恢复

关闭功能后停止新的 observer 调用，保留历史建议供追溯，不改变确认决定和事实投影。
摘要产物丢失不影响项目恢复；同源重新生成须由主模型显式请求，不能自动绕过去重。
重新生成分配新的 `run_id`，保留原来源及重生成原因，作为新的调用计费并继续受全局和 observer 预算限制。
过期摘要展示旧版本标记，不能修改其来源游标伪装为新结果。
进程恢复先核对已有调用记录与预算，不能无条件再次运行造成重复支出。
