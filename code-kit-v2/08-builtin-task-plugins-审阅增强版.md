## 1. 目标与非目标

### 1.1 原文目标与完成定义

本模块以**缺陷修复、文档维护、回归测试补充**三个完整组合验证任务插件的实际用途。首批插件为受信任的声明式资源，输入、输出、上下文和检查要求明确化；工作流差异体现在业务产物及质量检查，不改变核心证据和门禁。首期仅覆盖 Git 仓库内的代码、文档和测试维护，默认使用离线 stub 与本地 fixture，不把真实模型调用作为测试前置条件。[^P08]

建议完成定义为：在已实现且已验证的 01–07 基础上，09 能从受控目录选择三个组合；各组合有固定输入、合法资源锁、候选绑定、确定性检查、失败样例和主模型复审入口；成功与拒绝均可回查原始证据。**仅生成七个目录、若干提示词或一份写着 PASS 的 JSON，不满足完成定义。**

### 1.2 非目标与保证上限

不支持非 Git 文档平台、数据分析工作流、生产部署或任意外部系统写入；不自动选择模型、改变 profile、安装 CLI 或依赖；不负责插件市场、远程版本解析及动态扩展执行。插件不登记有效审核、不发布正式合同、不授予权限、不直接签发候选 verdict。

“内置”仅表示由项目可信维护流程发布，不代表检查脚本可以绕过审核或天然无副作用。“声明式”表示插件不在调度器进程内装载任意代码，不意味着后续测试不会执行项目代码。执行隔离、网络约束、进程监督仍由 05 和既有安全策略负责。[^P06][^P05]

### 2.2 对象流与身份作用域

```text
受审需求/正式合同/授权基线 + 固定插件锁 + 项目检查配置
        ↓
AnalysisReport（可复用已有、仍有效的固定调查产物）
        ↓
ChangeReport + 实际工作副本差异
        ↓ 核心 record_candidate；不是插件自行签名
CandidateBinding(K)
        ├── 确定性检查 K → CheckObservation / DocsFindings
        ├── 验收侧反测 K 的受控副本 → CountertestObservation
        └── 主模型内容/设计复审 → 固定复审记录
        ↓
ReviewBundle → 既有 evaluate_gates / cmd_verdict → 接受事实
        ↓ 仅在另有集成/基线使用授权时
后续跨任务输入或集成流程
```

`request_id` 仍是预算根；`task_id` 是可独立验收任务；`plan_version` 是合同版本；`stage_id` 在任务内唯一；模型调用使用新的 `run_id`。纯确定性检查使用 `operation_id/check_execution_id`，没有模型调用时不虚构 `run_id` 或 token 消耗。检查一旦实际调用模型，则必须有单独授权、模型 run 和 07 用量归属。[^P01][^P07E]

### 2.3 必须显式解决的跨模块接口差异

**D08-01：确定性插件与角色非空约束。** 06 增强版附录的参考 Manifest Schema 要求 `roles` 至少一项，且只枚举 planner/executor/observer。08 中 `python-checks`、`docs-checks`、`mutation-review` 不应为了通过这项参考约束而伪装成 observer、增加空提示词或启动模型。该非空条件来自上一章的**参考实现建议**，不是 08 原文已解决的生产机制。

建议在下一版受审 Manifest Schema 中允许“无模型步骤的纯检查声明”具有 `roles=[]`、`steps=[]`，由受保护核心中的已注册编译器把声明转换为 05 检查定义。只放宽这条约束不够：还须验证没有隐藏模型调用、至少提供有效检查出口、编译器来源受信、命令与权限经过正常审核。Schema 变更使用新版本或明确的注册表修订及新摘要；不能在旧 Schema 名称下偷偷解释新字段。

**D08-02：08 组合不是 07 离线 Schema 的直接替代。** 07 增强版的静态原型仅覆盖 `execute/freeze/check/verdict`，没有完整生产输入映射。附录的 `analysis/change/freeze/check/review` 是独立的 `builtin-workflow-recipes-proposal`：用于验证业务交接，不伪称可直接传给旧解析器。正式编译时，change 对应执行阶段；freeze/check 复用核心阶段；review 只组装复审输入，再进入受控 verdict。analysis 可消费规划时的固定报告，也可成为另获授权的调查调用。[^P07E]

**D08-03：类型名称必须对应已锁 Schema。** 附录用 `analysis-report@1` 等名字展示端口一致性；生产必须把这些名字绑定到固定 Schema ResourceRef、记录家族和字段路径。两条字符串相同不证明两个任意 Schema 等价；不得据此替代 06/07 的类型注册与实例校验。

**D08-04：核心动作不是业务插件。** `record_candidate`、审核登记、候选接受、预算结算、证据封存和受控变异入口属于核心。Manifest 不能靠声明这些名字获得执行权；可输出需求或引用，实际动作仍由核心依据当前准入执行。

上述四项应作为正式实施前的接口决策记录。附录目录明确使用 `-proposal` 类型及版本，不伪造七份“已被 06/07 接纳”的生产 Manifest。

## 4. 接口和行为约束

### 4.1 插件职责

#### 4.1.1 公共产物封装

建议登记以下新记录家族，均使用自己的 `schema_version: 1`，不改变合同 Schema 版本或现有 attempt 状态。附录提供八类结构 Schema；结构通过后仍需领域校验和可信来源核验。

| 字段 | 建议约束 | 语义 |
|---|---|---|
| `record_type` | 注册家族；未知拒绝 | 不能按文件名或字段相似度猜类型 |
| `schema_version` | 精确版本 | 不允许解析失败后当 v1 合同继续 |
| `context.request_id/task_id/plan_version` | 核心核对的稳定身份 | 不从模型回答里取得预算根 |
| `context.contract_ref` | 已锁合同或明确的合成测试引用 | 正式执行必须能追到合法合同 |
| `context.plugin_lock_ref` | 06 发布的固定锁引用 | `locked:true` 不构成替代 |
| `context.candidate_ref` | 改动前可为 null；正式候选检查必填 | 不用可变 worktree 路径代替候选 |
| `producer.mode` | `model_report/core_observation/synthetic` | 表示来源类别，不是身份认证 |
| `producer.run_id` | 模型 run 或 null | 纯检查不伪造模型调用 |
| `producer.operation_id` | 一次具体操作的稳定标识 | 重送同一操作不执行第二次 |
| `payload` | 记录家族限定的封闭对象 | 不允许偷偷附加 `PASS/approved/permissions` |

**可信封装规则**：插件提交 payload 及合法引用；核心校验实际来源、上下文和资源后形成登记记录。JSON 中声称 `core_observation` 不能使一个执行器文件成为核心证据。即使附录样例使用该字段，生产仍须凭受控入口、运行索引和实际采集来源判定。

所有资源使用 `ResourceRef={kind,id,sha256,path}`；公共三字段不变，文件资源增加仓库相对定位。摘要覆盖完整锁定字节。记录不包含自己的摘要，审核与产物间不得制造循环哈希。金额和非整数精度数据沿用 01/07 的十进制字符串约定，不引入另一套预算算法。[^P01]

#### 4.1.3 需求、事实、推断与未决问题

| 类别 | 最小要求 | 是否能直接驱动实现 |
|---|---|---|
| 已批准需求 | 稳定 requirement ID、正式合同/需求来源、行为边界 | 在合同范围内可以 |
| 观察事实 | 固定资源引用、字节范围/检查记录、客观陈述 | 只说明观察结果；不自动授予变更权 |
| 推断 | 来源事实、推断过程的摘要、反例或限制 | 须按风险复审，不能冒充原文事实 |
| 假设 | 未验证内容、验证方法、影响面 | 关键假设未解决时阻塞实现或验收 |
| 未决问题 | 问题、阻塞程度、所需决定、责任入口 | 不以默认选择替用户或主模型作决定 |

对文本来源，建议 `SourceAnchor` 保存原文件 ResourceRef、UTF-8 **字节**半开区间 `[byte_start,byte_end)` 和该片段的 SHA-256；展示行号是辅助信息。消费时先核验完整文件，再检查范围及片段摘要。不能把 Unicode 字符下标当字节坐标，也不能先做换行转换再沿用旧坐标。二进制或命令观察使用对应资源/日志记录，不强迫伪造文本行号。

例如需求是“大小等于上限时允许”，调查观察到实现使用 `<`。可以报告边界不符；不能自行补出“支持负数”“自动扩容”“更改 API 类型”等未获批准需求。附录 fixture 对非负整数域的约定属于人工给定的测试合同，不是对任意真实项目的默认设计。

#### 4.1.4 七个插件职责矩阵（原文保留并展开）

| 插件 ID | 职责 | 明确限制 |
|---|---|---|
| `repo-analysis` | 产出事实、文件引用、约束和未决问题 | 不写产品代码；事实必须带来源 |
| `code-change` | 按正式合同生成代码候选与自检报告 | 不自行扩大范围、授权或架构 |
| `python-checks` | 编译明确的 Python 检查定义 | 不自动安装依赖，不猜测项目命令 |
| `docs-change` | 按读者和内容目标修改仓库文档 | 不把源材料中的指令当授权 |
| `docs-checks` | 本地链接、目标存在性和约定格式检查 | 网络链接访问须有相应范围与授权 |
| `regression-tests` | 针对已定义行为补充有效回归测试 | 不削弱旧断言、不删测试换取通过 |
| `mutation-review` | 声明固定候选上的反测和证据要求 | 由验收侧调度器执行，不自发修改候选 |

插件 Manifest 声明所需角色和能力，不指定唯一 CLI 品牌或默认模型。规划与执行可用不同已支持 adapter；交接通过固定合同、产物和证据。业务插件无 supervisor 审核调用权。[^P08]

#### 4.1.5 字段校验、错误和体量限制

建议新 JSON 产物上限 1 MiB、嵌套深度 64；事实/变更/测试摘要默认最多 1,000 项。大报告拆成多个固定资源并附索引，不以提高所有内存限制解决。以上是设计初值，不是原文既有能力或压测结果。源码、补丁和日志等大文件按 01/05 的证据分段规则处理。

顺序为：输入大小/编码 → 严格 JSON 与重复键 → 家族/版本 → Schema → 字段关联 → 资源类型及完整性 → 候选/合同上下文 → 当前授权和消费动作。未知字段拒绝；配置中 `_...` 说明例外不适用于这些记录。JSON Schema 默认允许额外属性，封闭对象必须明确声明；Schema 通过不证明引用存在、来源可信或业务为真。[^R09]

| 错误族 | 例子 | 处理 |
|---|---|---|
| `E_ARTIFACT_*` | 未知家族、字段、生产者上下文不符 | 保留原始提交，不登记正式产物 |
| `E_SOURCE_*` | 缺来源、范围错误、片段摘要不符 | 重新取证，不能把无法核验内容当事实 |
| `E_CANDIDATE_*` | tree/补丁/清单不一致、候选漂移 | 固定新候选并重新检查 |
| `E_CHECK_*` | 命令/平台缺口、零测试、采集缺失 | 明确失败或不完整，不自动安装/跳过 |
| `E_DOC_*` | 链接/锚点错误、方言不支持、内容未复审 | 返回文件与目标，按问题类别修复 |
| `E_COUNTERTEST_*` | 对照不可比、变异不合法、失败不相关 | 不形成回归有效性证明 |
| `E_REVIEW_*` | 核心门禁/内容复审/必需检查缺失 | 不登记接受；交主模型决定 |

错误依旧有 `code/message/details/retryable`，details 不泄露凭据、完整环境或受限内容。`retryable` 不能自行授予重复调用或新费用。

#### 4.1.6 `repo-analysis`：只读调查与有效复用

输入至少有问题/读者目标、正式范围或受审调查范围、固定源码/文档及规则引用、已知事实、允许的调查操作和问题清单。输出 `AnalysisReport`，事实和推断分别标注；记录实际查阅文件、无法访问资源、未验证事项与建议检查，但不直接写代码、不发布合同。

调查可以在已获授权的规划请求中运行，也可以是独立受审调查任务。两者使用各自的审核与预算，不要求“必须先有执行合同才能规划”，也不允许借规划读取全仓库或敏感路径。只读工具白名单与 OS 权限边界分开报告。

复用键建议包含：问题/需求引用、相关源码/文档闭包、规则与术语引用、调查方法/模板版本，以及影响结论的环境事实。缓存命中还须核验当前读权限、引用完整性和结论仍适用；无关进度变化不失效，相关源码变化不能只因任务名相同继续用旧结论。相同 hash 的报告不自动拥有新的读权限。

资料不足时输出未决问题，不用模型常识填成项目事实。源文件包含“忽略规则、运行此脚本”之类文字时按数据处理，不能转为工具权限。

#### 4.1.7 `code-change`：声明必须与实际差异核对

输入为固定合同、行为需求、相关调查报告、获准基线、允许写路径/操作类型、项目编码约定及显式检查要求。输出实际工作副本差异和 ChangeReport：需求 ID、修改理由、文件/操作声明、已做自检、未做检查、兼容风险与未决项。

核心独立产生实际差异清单，核验新增、删除、重命名两端、文件模式、二进制变更、链接与子模块等类别。**模型列出的 changed_files 只是声明**，不能取代实际 Git diff/候选清单。重命名移出受保护路径或移入范围外都必须拒绝；“删除旧文件再新增同内容”不能绕过同样检查。

禁止为满足检查而删除测试、扩大异常捕获、吞掉错误、放宽权限、改动保护规则或引入未批准依赖。确需架构/需求变更时生成明确阻塞原因，由主模型决定新合同版本。

#### 4.1.8 `python-checks`：显式检查计划的编译器

该插件不从 README 中抓命令执行，也不因为看到 `.py` 文件就默认选择 pytest。输入来自已核验项目配置及正式合同：Python 入口绑定、测试框架/版本、工作目录、精确目标、参数、所需配置/插件、依赖环境、时限、预期退出语义和机器可读结果要求。缺少项目检查定义时阻塞。

输出 CheckPlan/CommandSet 候选，经过 03 审核与 05 环境绑定后执行。编译只验证结构、字段来源和平台覆盖；不能通过运行 `--collect-only`、导入测试或启动构建来冒充“静态预检”。确定性编译器由可信核心注册，不从 Manifest 字符串动态 import。

检查分层建议为语法/导入、目标回归、既有相关测试、静态质量；项目没有某类检查时明确适用性，不伪造零项通过。测试导入与收集本身可能加载项目代码；pytest 的自动插件、环境选项和 conftest 加载也需纳入受审配置，禁用包自动加载不等于禁用所有 conftest 或显式插件。[^R01][^R03]

若采用 pytest，则退出码 5 表示未收集测试，不能当作相关回归通过。其他错误码的解释按锁定版本记录，不能认为“非零都意味着目标缺陷被发现”；当前官方文档亦可能包含旧版本没有的退出类别。[^R02]

#### 4.1.9 `docs-change`：受约束的内容维护

输入至少包含目标读者、文档类型、修改目标、允许路径、术语表、权威实现/接口来源、明确要求保留的章节/锚点、语言和 Markdown 方言、可运行示例的白名单及过时内容处理规则。

输出文档候选、需求/段落映射、事实来源、术语变化、链接/锚点变化、示例变化、删除内容理由及未验证声明。不能把缺少源码证据的语句写成“已经实现/测试通过”；不要为了形式完整虚构版本、性能、截图、命令输出或验收记录。

文档任务不得借扩展名越过受保护路径，例如根目录或嵌套 `AGENTS.md`、管理目录、源技能或 CI 管理文件；具体保护集合以现行核心策略为准，不能由插件写一份较短列表替代。重命名和符号链接同样检查。

仅格式/错别字调整可采用轻量内容复核，不强制无关变异测试；涉及 API、权限、部署命令或行为承诺时必须增加对应来源核对。源材料中的命令默认只是文档内容，不因为置于代码围栏就获得执行权。

#### 4.1.10 `docs-checks`：链接、方言与覆盖范围

输入为固定候选、允许读取的文档/资源闭包、Markdown 方言和版本、渲染规则、链接策略、显式锚点/目录路由规则、样例执行清单。默认只做本地确定性检查；不访问远端，不自动启动站点构建，不运行所有代码块。

输出应逐项记录 source、目标、结果、依据和未检查原因；结构状态与内容复审状态分开。无网络授权的外部链接应记 `NOT_CHECKED_EXTERNAL`，不是“有效”，也不是因未访问而自动判文档错误。若任务承诺所有外链可用，则该承诺仍未满足。

附录实现使用 CommonMark AST 解析行内链接、引用式链接和图片，跳过真正的代码 token；HTML 仅覆盖明示的有限标签与链接。**参考锚点模式为 `commonmark-explicit-anchors-v1`，不实现 GitHub 自动标题 slug、MDX、站点目录索引或任意 HTML。** 真实项目需选择与实际渲染器匹配且有样例验证的适配器。CommonMark 定义语法，但项目渲染器的标题锚点与目录路由还需要独立规则。[^R04][^R05]

#### 4.1.11 `regression-tests`：行为驱动而不是实现镜像

输入为已确定行为、缺陷触发条件、允许测试范围、权威预期值、现有测试约束和验收侧反测方案。输出新增/修改测试、每项对应需求、测试选择 ID、断言依据、fixture 数据、自检及未覆盖说明。

目标测试不得仅比较一个函数与它自己的再次调用，不得把实际实现输出直接复制为期望值，不得通过 skip/xfail、移除断言、缩小测试选择或改写 pytest/unittest 发现规则换取通过。参数化可以使用独立业务规则或明确黄金输入输出，不能与被测实现共享同一个有缺陷的逻辑分支。

回归测试补充通常只允许改测试及明确测试 fixture；发现产品代码错误时应报告，而不是自动修复超出范围的实现。目标测试可能同时验证正确行为及边界/非法输入；输入域和异常预期必须来自合同，不擅自发明。

#### 4.1.12 `mutation-review`：验收侧反测声明

该插件声明反测需求，而不是普通执行器的“故意改坏代码”工具。输入包括固定候选、目标行为、精确测试清单、已审反测方式、允许变化位置、变异算子/旧实现来源、预期失败签名和预算。输出 CountertestPlan，执行与 Observation 由验收侧核心完成。

首期建议精确、少量、可解释的反例：将某个受审边界条件改回旧缺陷，或在可比较环境中使用已固定旧实现。算子由受信注册表限定，绑定文件原始摘要与精确匹配次数；匹配 0 次或多次都拒绝，不用宽泛正则替换整个仓库。

一个目标缺陷被检测只能说明这项回归有对应证据，不说明系统无其他缺陷。除非任务确实要求广泛变异分析，不以“杀死很多无关变异”替代目标行为证明。

### 4.2 工作流组合

#### 4.2.1 原文组合与阶段性质

原文的三个组合保持不变：缺陷修复为 `repo-analysis → code-change → python-checks/项目检查`；文档维护为 `repo-analysis → docs-change → docs-checks`；回归测试为 `repo-analysis → regression-tests → mutation-review`。箭头默认表示**一个任务合同内的阶段**，不是 07 的跨任务 DAG，也不要求每个箭头对应一次模型调用。[^P08]

所有组合都显式经过核心“固定候选 → 独立检查 → 复审输入 → 主模型裁决”。候选尚未 PASS 时可以检查；阶段间共享合同与证据链，不制造额外 commit。调查已经完成且输入仍有效时直接消费固定报告，不为凑节点重复调查或重复收费。

| 阶段 | 执行者 | 输入前提 | 输出 | 能否签发 PASS |
|---|---|---|---|---|
| analysis | 获准的调查角色，或复用既有产物 | 调查/规划许可、固定来源 | AnalysisReport | 不能 |
| change | 正式合同的 executor | 具体合同、审核、范围、基线、预算 | 实际差异 + ChangeReport | 不能 |
| freeze | 核心候选机制 | 改动过程已停止写入、差异可核验 | CandidateBinding K | 不能 |
| check | 05 runner 与受信解释器 | K、正式命令、环境和准入 | 观察、日志与缺口 | 不能 |
| review bundle | 核心组装 | K 上的必需证据、内容复审 | ReviewBundle | 不能 |
| verdict | 既有受控 supervisor 入口 | 核心门禁与当前授权条件 | 精确绑定候选的裁决 | 按既有机制 |

#### 4.2.2 精确候选绑定与检查键

每次独立检查应绑定下列内容，而不是只保存 `task_id` 或检查标题：

```text
CheckExecutionKey =
  repository_namespace + request_id + task_id + plan_version + attempt_id
  + candidate_ref + check_set_ref + environment_ref
  + tool/parser/resource-policy refs + purpose + repetition_index
```

这是逻辑字段集合，不是直接拼接字符串的算法。若生成摘要，应使用 01 的固定写出规则生成新记录，再哈希其完整字节。相同操作重送保持 operation_id；重新执行另建 check_execution_id，保留旧日志和结果。check 只读复用缓存也必须检查原输入、环境、授权、完整性与适用性，不能从“曾经成功”推导可复用。

候选 K 包含所需 Git tree/patch 与实际检查物化来源。检查前核对清单，检查后检测源码、测试、配置和文档的非预期变化。允许的临时缓存应位于独立 scratch；其豁免路径必须精确受控，不能把整个工作区排除。若检查本身修改候选源码、测试或必需输入，记录漂移并使本次结果不适用于原 K。

Git worktree 是独立工作副本安排，不是独立权限边界；它与主仓库共享部分仓库管理内容。签出还要考虑 hooks、attributes、内容过滤和换行转换；不能把一次 checkout 当成无副作用或字节天然一致的沙箱。物化策略和实际检查字节须由 05/核心确认。[^R06][^R07][^R08]

#### 4.2.3 缺陷修复：完整输入、对照与失败修复

以下是**人工合成业务案例**，不表示用户项目存在该缺陷。

| 项目 | 固定内容 |
|---|---|
| 输入域 | 本 fixture 规定 size、limit 为整数，limit 非负 |
| 需求 R1 | `0 <= size <= limit` 时允许；超过上限或 size 为负时拒绝 |
| 原缺陷 | 实现使用 `0 <= size < limit`，等于上限被拒绝 |
| 获准变更 | 仅修改 `limits.py` 及合同明确允许的目标测试 |
| 正确候选 | 使用 `0 <= size <= limit` |
| 失败修复 | 无条件返回 True，边界通过但负数/超额守卫失败 |
| 目标证据 | 相同测试字节在正确实现通过，在原缺陷上命中 R1 对应断言 |
| 保留约束 | 测试删除、断言弱化、范围外修改、依赖安装均不允许 |

执行顺序为：固定需求和来源 → 调查并引用 `<` 的原始字节 → 在合法范围生成候选 → 核心固定 K → 对 K 执行目标与既有相关测试 → 在验收副本对旧缺陷执行**同一份新测试** → 归类失败签名 → 组装复审材料 → 主模型裁决。

| 实现/测试组合 | 边界 size=10, limit=10 | size=11 | size=-1 | 业务解释 |
|---|---|---|---|---|
| 原缺陷 + 固定测试 | 失败 | 通过 | 通过 | 复现目标边界缺陷 |
| 正确候选 + 固定测试 | 通过 | 通过 | 通过 | 局部行为检查满足，可继续复审 |
| 无条件 True + 固定测试 | 通过 | 失败 | 失败 | 失败修复，不获正常接受 |
| 正确/错误实现 + 自比较空测试 | 均通过 | 未覆盖 | 未覆盖 | 不能证明目标缺陷会被发现 |

这里只覆盖 fixture 的有限输入和性质；不能将三项测试推广成任意输入已被形式证明。实际项目需补齐合同要求的边界、异常、集成与兼容场景。

#### 4.2.4 文档维护：结构通过与内容拒绝并存

人工合成输入是一份面向调用者的 `docs/guide.md`，应说明“等于上限允许”，并链接 `docs/api.md` 的显式 `limits` 锚点。

| 候选 | 本地链接 | 格式/锚点 | 内容 | 后续处理 |
|---|---|---|---|---|
| 指向 `missing.md` | 失败 | 无法核验目标 | 无论内容如何 | 修复链接后生成新候选/重查 |
| 链接正确，写“等于上限拒绝” | 通过 | 通过 | 与需求和实现不符 | 内容复审拒绝；不能用结构通过覆盖 |
| 链接正确，写“等于上限允许” | 通过 | 通过 | 与本 fixture 规则一致 | 仍经核心门禁和正式裁决 |
| 外部链接未访问 | NOT_CHECKED_EXTERNAL | 本地部分可核验 | 外部可用性未知 | 报告检查边界，不冒称外链有效 |

内容复审逐条核对目标读者是否能完成任务、术语是否一致、示例是否对应实际接口、删除是否损失约束、权限/版本/状态声明是否有来源。附录的 `synthetic_content_review` 只检查本案例给定句子，是**固定测试 oracle**，不是通用语义验证器，更不是生产主模型复审。

当文档示例确需执行时，为每个片段登记文件 ResourceRef、片段坐标/摘要、语言、输入、预期结果、固定解释器、允许副作用和时限，纳入正式检查集合。没有这项绑定的代码块只能做静态审阅，不默认运行。

#### 4.2.5 回归测试补充：正确参考与反测副本

该组合以正确实现为基线，只允许增加目标回归测试。主模型预先定义“将 `<=` 改回 `<`”的受控反例，执行器不获得产品代码变异权限。

```text
固定候选 K = 正确实现 C + 新测试 T
    ├─ 验收副本 V0：C + T → 必需目标测试实际通过
    └─ 验收副本 V1：M(C) + 完全相同的 T
                         → 命中受审 assertion_id 的目标失败
```

V1 不写回 K，不纳入交付补丁，不复用上一轮残留缓存，不改变测试本身。保存 C、T、变异规则、M(C)、runner 和环境的引用及实际变化清单。若使用旧实现而不是变异，须核验旧实现与 T 的接口兼容；不兼容时不能把 ImportError 当成成功反测。

附录实际演示了正确参考通过、边界变异命中目标、空测试在两边均通过、语法错误被归类为非法变体四种结果。它没有实现真实项目的变异权限、Git 副本物化、生产隔离或主模型裁决。

#### 4.2.6 阶段就绪、失败与循环防护

建议为本模块的阶段投影使用 `PENDING / READY / RUNNING / OUTPUT_FIXED / BLOCKED / FAILED / CANCELLED / INCOMPLETE`；这些不是替换现有 attempt/verdict 的新状态名。

| 转换 | 必须守卫 | 失败后动作 |
|---|---|---|
| analysis → change | 相关事实来源有效；关键未决问题已解决；执行合同有效 | 保持阻塞，报告需决定事项 |
| change → freeze | 写入已停止；实际差异与声明一致；范围可核验 | 保留工作副本，拒绝形成可验收候选 |
| freeze → check | 固定 K 已发布；检查定义、环境及准入有效 | 不启动检查；不能等待 K 先 PASS |
| check → review bundle | 所需证据已封存；缺口逐项可见 | 允许组装失败材料，不伪造成功证据 |
| review bundle → verdict | 当前授权和现行门禁满足，主模型已审阅 | 不由插件自动接受 |
| 返工 → 新 freeze | 新运行/新候选身份；预算和审核仍适用 | 重新核验，旧检查只属于旧候选 |

检测两层图：任务 DAG 按 07 验证；任务内阶段图按明确依赖验证。端口不能引用未来阶段、同名但另一任务的临时输出、未固定的“latest”文件。列表书写顺序不决定执行顺序；无依赖的阶段也只能在权限和独立性成立时并行。

#### 4.2.7 跨任务拆分的界限

只有拆成多个可独立验收合同的任务时才形成跨任务依赖。此时上游须已获接受，所需代码须存在于真实、获准使用的基线提交；调度器不自动 commit、集成或替换下游 `base_sha`。一个任务内部 check 读取未 PASS 候选，不受跨任务“上游先接受”的约束。[^P07]

候选补丁、任务接受、基线使用许可与集成许可是不同事实。文档或测试组合也不能靠“没有代码修改”自动跳过这些正式下游条件。

### 4.3 各类验收区别

#### 4.3.1 通用独立验收输入与最小判据

正式结果接受至少要求以下事实同时成立：固定候选及输入完整；实际差异在合法范围；相关审核和当前业务授权有效；执行和工具证据满足现行要求；正式检查集合没有缺失/替换；对应平台环境真实可用；必需检查满足各自断言；内容/设计复审完成；现行 G0–G6 通过。

07 管理接受状态，08 只提供领域证据与缺口。即使这些项目满足，插件也只能返回“材料已就绪”，不能调用 verdict 写入入口。

| 证据 | 谁产生 | 能证明 | 不能证明 |
|---|---|---|---|
| 执行器 self-check | 执行器及其运行报告 | 它报告做了什么，可供调查 | 独立检查实际成功 |
| 原始日志/TransportSummary | 05 受控采集 | 进程、退出、采集等事实 | 自动证明所有测试断言真实可靠 |
| 结构化测试报告 | 已锁解释器/测试框架，核心核验 | 选定测试结果及来源 | 抵抗任意恶意项目代码的强认证 |
| 反测结果 | 验收侧核心 | 受审对照下目标失败是否出现 | 所有缺陷均被覆盖 |
| 内容复审 | 主模型受控流程 | 该候选内容的评审结论 | 自动授予执行或集成权限 |
| 插件输出 `PASS` | 不受信业务输出 | 仅是一段数据 | 任何正式门禁或候选接受 |

恶意测试可以伪造自己的 JSON、覆盖报告文件、修改测试框架或退出行为。因此需要保护 runner、独立采集、候选漂移检查和测试代码审阅；单纯“报告 hash 正确”只能证明报告字节没变，不证明其描述为真。附录的结果来源字段和 Python 参数对象不提供 OS 隔离或密码学身份。

#### 4.3.2 Python 检查：目标收集、执行与结果归约

不同检查类型使用不同指标。语法检查或文档检查没有 unittest 测试数是正常的；**只有声明为测试执行的检查**要求测试收集与目标执行证明，不能给所有检查强加 `tests > 0`。对于回归测试，必需 target ID 必须出现在机器记录中且真正执行。

| 观察 | 质量状态建议 | 能否证明目标回归通过 |
|---|---|---|
| 目标均运行且通过，相关既有检查无失败，采集完整 | SATISFIED | 可以作为局部证据 |
| 退出 0，但无测试/未找到目标 ID | INCOMPLETE 或 FAILED | 不能 |
| 目标 SKIPPED / XFAIL | TARGET_NOT_EXERCISED | 不能；另行豁免需明确条件 |
| XPASS、收集/导入错误、内部异常 | FAILED 或 INFRA_ERROR | 不能 |
| 缺工具/依赖/平台实现 | BLOCKED | 不能自动安装或换平台 |
| 超时、取消、日志截断 | INCOMPLETE | 不能按最后一行“OK”判通过 |
| 目标通过，但已有相关测试失败 | FAILED | 不能忽略既有失败 |
| 重跑结果不一致 | FLAKY_OR_INCONSISTENT | 不能只选最好的一次 |

unittest 提供 testsRun、failures、errors、skipped、expectedFailures 等结果，项目解释器版本与发现机制必须锁定；只读取 `wasSuccessful()` 或命令退出码不足以表达“指定目标已实际运行”的项目要求。[^R01]

既有失败不能由执行器自行列入 allowlist。需要明确的受审差异化验收时，绑定固定基线失败清单、原因、适用测试、有效期及不能受损的目标；它不覆盖核心门禁，也不能把原失败变为“通过”。

测试依赖及配置是执行输入：Python 入口、环境包、测试发现配置、conftest/插件、被导入辅助模块、数据 fixture、时区/locale/随机种子等按影响范围锁定或登记。仅锁住 `test_new.py` 不能证明测试含义不变。无法列清任意动态 import 闭包时，应采用受控完整环境/源码快照并如实记录剩余限制，而不是宣称已经追踪所有依赖。

#### 4.3.3 文档检查：解析与目标规则

建议按以下流水线处理本地文档：

```text
固定候选文件清单
  → 严格读取允许文档字节
  → 固定版本 Markdown AST / 声明的渲染适配器
  → 提取真实链接、图片、引用定义及支持的 HTML 属性
  → URL 分类与一次解码
  → 仓库内逻辑路径归约
  → 目标文件/目录规则与锚点核验
  → 逐项结果 + 未检查范围
  → 独立内容复审
```

不能用一个正则扫描所有 `[text](url)` 来宣称覆盖 Markdown：代码块/代码跨度中的文本不是要访问的链接，引用式链接和嵌套语法也需要按语法解释。CommonMark 为这些结构定义了专门规则；具体 AST 库及版本应进入检查工具链。[^R04]

**路径是两层语义。** `ResourceRef.path` 沿用 01 的规范格式，拒绝 `..`。Markdown 中 `../README.md` 可能是合法的文档相对链接；它必须先相对源文档解析并限制在候选仓库内，再得到规范化资源定位。不能直接借 ResourceRef 规则误杀所有上级链接，也不能把 Markdown 的 `..` 直接作为文件系统自由读取权限。GitHub 的相对链接还包含其自身仓库根及渲染语义，实际项目须固定目标 profile。[^R05]

| 目标类别 | 默认规则 | 结果与限制 |
|---|---|---|
| `a.md`、`../a.md`、仓库根 `/docs/a.md` | 在固定清单内解析，越界拒绝 | 规范定位后核验完整目标 |
| `%20` 等转义路径 | 校验 percent 形式，UTF-8 严格解码一次 | 不二次解码 `%252e` 形成新的路径穿越 |
| 反斜杠、驱动路径、控制字符 | 拒绝或按明示渲染策略处理 | 不能让 Windows 与 POSIX 自行猜 |
| `file:`、`javascript:`、未知 scheme | 不打开；按安全/方言策略拒绝 | 不因解析库隐藏为纯文本就宣称已审安全 |
| http/https、协议相对 URL | 不联网 | NOT_CHECKED_EXTERNAL |
| mailto/tel | 非本地文件，不访问 | NOT_CHECKED_NONFILE |
| 目录、站点路由、query 参数 | 需固定站点解析器/显式策略 | 不支持时标明，不悄悄去掉参数 |
| `#fragment` | 使用目标 renderer 的锚点集合 | 不把简单 lower/replace 当通用算法 |
| 非 Markdown 文件 fragment | 需该格式的专用能力 | 不支持时明确不完整 |

标题更名、重复标题顺序和格式变化可能影响渲染器生成的链接锚点。应锁定 renderer/slug 规则并测试重复标题、Unicode、内联代码、标点与显式锚点；附录只实现显式锚点，自动标题片段在该 profile 下不会被判有效。它不是完整 GitHub 渲染兼容性证明。[^R05]

生产还应处理引用标签不完整、脚注、front matter、include、MDX/模板指令、图片资源、目录 index、站点 base URL、大小写及 Unicode 路径差异。未支持的方言应阻塞相关完整性承诺，不把“当前解析器没看懂”默认为无链接。

**检查覆盖量分母**应报告：文档总数、已解析数、遇到的链接数、本地已验证数、坏链接数、外部未检查数、不支持项数。不得把未检查项从展示中删除后写“全部通过”。附录只输出其 profile 下的发现与未检查计数，不声称实现生产全方言覆盖统计。

#### 4.3.4 回归与变异：严格对照算法

输入为已审核 CountertestPlan、正确参考运行 O0、反例运行 O1 及两边原始证据。依次核验：

1. 候选、测试集合、runner、配置、环境及反测方案引用完整；有权创建受控副本和执行对应测试。
2. 正确参考实际完成，所有必需目标通过；没有未解释的收集、导入、环境或相关测试失败。
3. 反例确按计划生成，原文件摘要与匹配次数符合要求，只改变允许的实现部分，测试字节不变。
4. 两边测试 ID、选择参数、测试资源、runner 和环境可比；不得通过增删测试或换环境制造差异。
5. 反例失败命中预先指定的目标测试与断言/预期错误类别，并能由原始观察追溯；进程退出事实与结构化结果一致。报告断言失败但原始退出为成功或未知时，标记证据冲突，不能算命中。
6. 按预定重复次数保存全部结果；不一致则报告 flaky，不从多次运行中挑选最好的一次。

| 反例结果 | 建议分类 | 是否满足本模块的“有效目标反测” |
|---|---|---|
| 目标断言失败，签名与受审行为一致 | DETECTED_TARGET_ASSERTION | 是，作为局部证据 |
| 两边都通过 | SURVIVED_OR_UNPROVEN | 否；可能测试无力或变异不影响该行为 |
| 正确参考本身失败 | REFERENCE_INVALID | 否；先修参考/环境 |
| 测试/runner/环境/选择集不一致 | INCOMPARABLE / COLLECTION_DRIFT | 否 |
| 语法错误、收集错误或框架崩溃 | INVALID_VARIANT / HARNESS_ERROR | 否；不能混成“杀死缺陷” |
| 其他测试/其他断言失败 | UNRELATED_FAILURE | 否，除非预先受审方案明确覆盖它 |
| 目标 skip/xfail/未执行 | TARGET_NOT_EXERCISED | 否 |
| 超时或采集不完整 | INCONCLUSIVE_TIMEOUT / INCOMPLETE | 默认否 |
| 多次结果不一致 | FLAKY_OR_INCONSISTENT | 否，需调查 |

这是**本模块新增的严格业务判据**，不是冒充所有 mutation 工具的通用定义。例如 Stryker 的通用指标可把 timeout 计为 detected；本模块默认不据此证明一个指定业务断言有效。目标本身就是超时/死循环时，可另审专门的确定性时限判据，绑定时钟、输入、重复规则、环境和允许误差，而不是事后把任何 timeout 算成功。[^R10]

不把等价变异自动算作失败，也不由插件一句“equivalent”自动豁免。等价性需要受审说明或更强证明；无法判定则保留 UNKNOWN。首期核心指标建议为：目标行为证据覆盖率、有效反测数、存活数、非法/不确定数分别报告；未要求广泛突变率时不制造一个看似权威的总分。

#### 4.3.5 反测资源、异常与清理

默认一次仅启用一个变异，独立 scratch 和进程作用域；同一原候选只读保留。执行后保存实际变异清单、原始日志、结构化观察、时限、退出及清理报告。不能让反测副本进入普通提交/集成路径。

超时/取消由 05 按既有进程监督处理。清理不确定时保留隔离目录和运行标识，阻止其被复用；恢复先核验进程身份，不凭 PID 猜测，更不能在未知启动状态下直接重跑。07 的调用/时限/并发预算覆盖这些检查；若实际产生模型用量则照实归属同一 request。

#### 4.3.6 文档、代码与测试任务的差异化门禁

| 任务类型 | 必需业务证据 | 不应机械强加 |
|---|---|---|
| 有可复现缺陷的代码修复 | 明确触发、修复前后对照、相关回归与范围/设计复审 | 无关全仓库大规模 mutation |
| 纯排版/错字文档维护 | 指定范围、链接/格式适用检查、内容无意外变化复核 | 为改字造无意义代码测试 |
| API/行为文档维护 | 固定实现/规范来源、示例一致性、链接和读者任务复核 | 自动执行所有代码围栏 |
| 回归测试补充 | 正确参考通过、目标反例有效、旧测试未弱化 | 为测试覆盖名义自动改产品代码 |
| 不适用的检查项 | 预先定义适用条件及具体原因 | 将缺能力或失败事后改为 N/A |

### 4.4 资源和权限

#### 4.4.1 完整内容锁与固定消费

模板、示例、Schema、检查定义及实际加载的规则和辅助资源都进入 06 的锁定闭包。正式合同冻结前纳入插件锁和检查引用；审核后不能回填合同制造循环哈希或改变字节。prepare/run 与后续相关操作重核引用及当前准入。[^P06][^P08]

```text
显式启用目录
  → 06 解析 Manifest 与资源闭包
  → 08 类型/业务组合校验
  → 受信编译器生成请求/检查候选
  → 01 封存字节及资源引用
  → 03 审核与动作校验
  → 07 编排，05 消费同一组固定输入
```

执行不能在核验后重新读取同名可变路径；要么固定字节/对象版本，要么通过已验证的受控物化方案保持一致。新增配置文件、测试插件、文档 include 或动态加载项应被发现并重新纳入锁，不能只比较原清单里的文件。

#### 4.4.2 唯一来源技能与 06 路径边界的协调

原文要求 `.agents/skills/plan-task/test-design.md` 是唯一来源；06 又要求插件资源路径不能穿越插件根。不能直接在 Manifest 写 `../../.agents/skills/...` 或创建越界 symlink 来同时“满足”两者。

建议由可信维护流程把源技能发布为独立共享资源，或者生成只读的带 provenance 派生副本。记录源路径/摘要、源版本、编译器/同步器版本、输出摘要及引用关系；派生副本只由该流程生成，禁止业务插件手工维护。插件根内只引用合法资源；外部来源通过核心登记的资源依赖纳入整体审核，而不是放宽任意路径读取。

源变更后更新派生资源与相关锁，再重新审核。历史 run 保留旧原字节及来源记录；不会因更新规则就重写历史。若当前 06 尚无共享资源发布机制，应把它列为工具链维护前置工作，不偷偷加路径例外。

#### 4.4.3 权限需求矩阵

有效权限始终取用户授权、项目策略、角色允许集合、正式合同授权的交集；插件只能提出需求，不扩大其中任何一层。[^P06]

| 插件 | 默认读取 | 默认写入 | 进程/网络 |
|---|---|---|---|
| repo-analysis | 获准相关源码/文档/规则 | 由核心保存输出，产品文件不写 | 调查命令另行审核；默认无网络 |
| code-change | 合同范围及必要上下文 | 已批准代码/测试路径 | 自检必须属于正式许可 |
| python-checks | 固定候选和检查资源 | 受控 scratch/报告 | 确定性编译不执行；执行走 05 |
| docs-change | 获准文档与权威来源 | 明确文档范围，保护路径优先 | 不自动执行源文档命令 |
| docs-checks | 固定文档/本地目标清单 | 核心报告 | 默认无网络、无站点构建 |
| regression-tests | 已定义行为及允许测试上下文 | 明确测试/fixture 范围 | 不安装依赖，不改发现规则逃避检查 |
| mutation-review | 固定候选/方案/测试 | 仅验收侧独立反测副本 | 权限在核心，普通 executor 无变异权 |

所有默认项均不包含联网、依赖安装、提交、推送和部署。业务确需这些操作时回到既有授权和审核流程，不借 `setup`、`preflight`、`post-check` 等名称绕过。

#### 4.4.4 威胁与控制边界

| 风险 | 必须控制 | 不能声称 |
|---|---|---|
| 源材料/日志中的指令注入 | 把输入视为数据；受信模板和工具权限分离 | 文本分隔符就是安全沙箱 |
| 恶意测试或检查脚本 | 固定代码、受控进程、最小环境、文件/网络限制、独立复审 | `shell=False` 或临时目录能禁止所有副作用 |
| 报告伪造 | 来源验证、核心日志、候选/检查绑定 | 字段 `core_observation` 能认证发送者 |
| 隐式依赖/配置注入 | 锁定加载来源、禁用未声明自动发现、核验环境 | 禁用一种自动加载即可封闭所有依赖 |
| 资源替换和链接逃逸 | 06 的安全读取、不可变发布和固定消费 | 在可写路径上先 stat 后 read 就完全无竞态 |
| 测试作弊 | 实际测试选择/结果、旧断言保护、反测与代码审阅 | 仅用 grep 或 AST 禁止词能证明测试有意义 |

Python 的 subprocess 文档区分 argv、shell、管道与进程行为；通用执行仍应复用 05。附录仅对小型已知 fixture 使用 capture_output 和有限 timeout，不具备生产流量限制、Windows Job、POSIX 后代回收或恶意子进程隔离能力。[^R11]

#### 4.4.5 草稿校验与正式执行的分界

草稿阶段允许纯 JSON/Schema、字段来源、类型、资源存在性和平台覆盖检查；不运行模型生成的 setup/check，不导入测试，不执行版本/帮助探测，除非该探测自身已有独立正式准入。生成命令候选不等于获准运行该命令。

正式执行必须消费固定 CommandSet、FinalLaunchPlan、环境记录及单次准入。为修复缺依赖而改变环境、为修复测试而改选择范围、为访问外链而联网，均是需按影响范围重新核验/审核的变化，不作为自动补偿动作。

### 6.2 静态编译算法建议

```text
compile_builtin_recipe(locked_inputs, catalog, plugin_registry, platform_inventory):
  1. 核验目录/Schema/插件版本与实际内容锁；未登记 proposal 拒绝生产消费。
  2. 识别业务组合及明确需求；无行为依据则输出未决问题。
  3. 解析任务内阶段；复用仍有效 AnalysisReport，不强制新增模型调用。
  4. 逐端口核验 Schema 绑定与实例；禁止未来输出和 latest 路径。
  5. 为核心 freeze/check/review 保留受控阶段，不交给业务插件自证。
  6. 将项目显式检查配置编译为 CommandSet 候选；验证所有声明平台。
  7. 将输入、模板、工具和检查资源闭包封存；生成可读来源/差异报告。
  8. 返回 DRAFT_VALIDATED 或带字段/依赖链的错误；不启动进程、不发布合同。
```

正式执行前仍要经过 03/07 当前审核、授权、预算与领取守卫。编译器与 Schema 的更新本身会改变检查规则，需更新相关锁及审核，不只是修改插件版本标签。

### 6.3 独立检查接线的事务与持久化顺序

建议顺序：先验证候选与正式检查绑定 → 03/07 当前准入 → 05 接受 handoff → 执行并收集原流 → 固定日志与观察资源 → 核心登记检查结果引用 → 形成 ReviewBundle。

结果资源封存与账本提交不是天然同一事务。封存成功但登记失败时保留孤儿资源，使用同一操作身份对账；登记成功但响应丢失时查询原结果，不再执行一次测试。执行状态未知时遵守 03/05 的 `START_UNKNOWN`，不能因预算预留超时自动重跑。

只有完整登记、引用可读且上下文正确的观察才能消费；临时文件存在、模型说完成、stdout 出现 PASS 都不能充当提交事实。缺证据的检查仍应保留失败/未知记录供恢复，不能删除目录后伪装未发生。

## 8. 兼容与恢复

### 8.1 原文兼容边界

插件集合是 v2 的显式能力；旧合同不自动改成工作流，不自动启用新插件。模板/检查改变生成新锁并重新审核相关输入，活动 attempt 保留原资源快照。组合失败保留产物和检查，由主模型决定修实现还是修合同，不静默换插件。停用新工作流后可以继续合法旧入口，但 v2 证据仍按原协议读取。新任务类型需要明确产物及验收适配，不能只换提示词声称已支持。[^P08]

### 8.2 恢复的共同前置条件

恢复操作者首先确认自己具备维护/读取权限，并取得 request/task/plan/attempt、候选、审核、插件锁和运行记录。暂停受影响新派遣但不篡改历史状态；控制面或证据不可信时先进入隔离。已存在的费用和潜在外发不能通过删除任务抹去。

### 8.3 八步操作流程

1. **定位并暂停**：找到受影响任务/阶段及 operation_id，暂停其新派遣和自动重试；记录故障发现时间、当前主控代际和维护原因。成功判据是后续轮询不再创建新活动运行。
2. **确认进程事实**：调用 05 的状态/身份核验，确认是否从未启动、仍运行、已退出或 START_UNKNOWN。不能仅看阶段字段和 PID；身份不明则升级到运行维护者，不盲目杀进程或重跑。
3. **封存已有证据**：保留原 stdout/stderr、临时/完整结果、候选/反测副本清单和清理记录。未封存资源可补封存，但不得补写虚假的“当时已通过”状态。
4. **核对固定绑定**：逐项检查合同、审核、插件锁、候选、检查集、环境与反测方案引用。字节损坏与合法新发布分开处理；恢复原字节不等于恢复已经撤销的权限。
5. **判断故障归属**：按下表区分产物、项目行为、检查环境、合同、权限或控制面问题；主模型决定返工/重审，不由插件自行放宽验收。
6. **采取一个明确动作**：查询已有登记结果、恢复可信原字节、申请新检查运行、生成新候选或新合同版本。每次动作有幂等身份和当前准入；不同时“改配置、换环境、换模型、改测试”导致不可归因。
7. **重新验证与收尾**：对新绑定运行所需检查，保存原失败和新结果。反测副本核验无残留且不会进入交付路径；无法证明清理完成则保留隔离，不复用目录。
8. **形成恢复记录**：记录故障、引用变化、动作、操作者/入口、检查结果、仍未解决问题、预算影响与是否允许恢复派遣。成功判据是当前事实完整可核验、未解决阻塞不被隐藏、历史证据未改写。

### 8.4 故障—动作—升级表

| 故障 | 保留什么 | 允许的恢复方向 | 禁止动作 |
|---|---|---|---|
| 调查报告来源缺失/漂移 | 原报告和引用 | 重取证、生成新报告并重审相关输入 | 用常识填来源或改旧 hash |
| 改动报告与实际差异不符 | 实际候选、声明和差异 | 修报告或返工，由主模型判断 | 相信报告忽略隐藏文件 |
| 链接/格式错误 | 失败目标与候选 | 修文档生成 K2，再跑相关检查 | 在旧 K 上覆盖文件后沿用结果 |
| 内容错误但结构通过 | 结构报告与拒绝理由 | 修内容/澄清需求，保留拒绝记录 | 把格式通过改写成内容通过 |
| 目标测试未收集 | 命令、配置、日志、框架版本 | 明确检查定义/环境后重新审核执行 | 将退出 0 当目标通过 |
| 反例无法编译/不可比 | V0/V1、测试与环境引用 | 修订反测方案并重新审阅 | 把异常计为杀死或偷偷改测试 |
| 反测超时/残留 | 原始日志、身份和清理记录 | 05 受控清理；必要时调整已审限额 | 删除目录或无身份地 kill |
| 输出封存成功、登记失败 | 完整孤儿资源及 operation | 同幂等操作对账后补登记 | 重跑以“找回”已有输出 |
| 登记提交成功、响应丢失 | 提交事实与资源 | 查原记录、标记 replay | 新建第二条相矛盾结果 |
| handoff 后状态未知 | 准入、进程线索、日志 | START_UNKNOWN 恢复流程 | 直接认定未执行后重发 |
| 当前权限撤销/锁变化 | 旧历史及撤销/绑定事实 | 阻止后续动作，按策略取消/重审 | 改回同名文件复活旧审核 |
| 历史资源库/账本回退 | 备份和可信高水位证据 | 隔离、对齐当前撤销与登记状态 | 恢复旧备份后立即重新派遣 |

### 8.5 只读诊断输出建议

不虚构项目已经存在的 CLI 子命令。后续状态 API/CLI 应输出以下只读字段：当前 stage/attempt/operation、是否启动及证据来源、精确候选与检查集合、每项缺口、等待的主模型决定、剩余预算、原始观察引用、清理范围及未验证平台。查询不得触发检查、生成新候选或修改审核。

def canonical_bytes(value: Any) -> bytes:
    # This fixed writer is for new reference resources, NOT external JSON equivalence.
    return (json.dumps(value, ensure_ascii=False, sort_keys=True,

def strict_json(data: bytes) -> Any:
    if not isinstance(data, bytes) or len(data) > MAX_BYTES:
        raise ContractError("E_JSON_LIMIT")

            if key in out:

def topo(stages: list[dict[str, Any]]) -> list[str]:
    by_id = {s["id"]: s for s in stages}
    if len(by_id) != len(stages):
        raise ContractError("E_STAGE_DUPLICATE")
    indegree = {key: 0 for key in by_id}
    children: dict[str, list[str]] = {key: [] for key in by_id}
    for s in stages:
        if len(s["depends_on"]) != len(set(s["depends_on"])):
            raise ContractError("E_STAGE_EDGE")
        for dep in s["depends_on"]:
            if dep not in by_id:
                raise ContractError("E_STAGE_MISSING", dep)
            indegree[s["id"]] += 1
            children[dep].append(s["id"])
    ready = sorted(k for k, v in indegree.items() if v == 0)
    result: list[str] = []
    while ready:
        key = ready.pop(0)
        result.append(key)
        for child in sorted(children[key]):
            indegree[child] -= 1
            if indegree[child] == 0:
                ready.append(child)
                ready.sort()
    if len(result) != len(by_id):
        raise ContractError("E_STAGE_CYCLE")
    return result

    """Validate the separate 08 recipe profile. Not the entire 07 workflow Schema."""
    order = topo(flow["stages"])
    by_id = {s["id"]: s for s in flow["stages"]}
    kinds = {"analysis", "change", "freeze", "check", "review"}
    ancestors: dict[str, set[str]] = {}
    if len(flow["platforms"]) != len(set(flow["platforms"])) or not set(flow["platforms"]) <= PLATFORMS:
        raise ContractError("E_PLATFORM")
    if [s["kind"] for s in flow["stages"]].count("freeze") != 1:
        raise ContractError("E_FREEZE_COUNT")
    for sid in order:
        s = by_id[sid]
        if s["kind"] not in kinds:
            raise ContractError("E_STAGE_KIND")
        ancestors[sid] = set(s["depends_on"])
        for dep in s["depends_on"]:
            ancestors[sid] |= ancestors[dep]
        plugin_id = s["plugin_id"]
        if plugin_id is not None:
            if plugin_id not in catalog or catalog[plugin_id]["version"] != s["plugin_version"]:
                raise ContractError("E_PLUGIN_VERSION")
            p = catalog[plugin_id]
            if not set(flow["platforms"]) <= set(p["platforms"]):
                raise ContractError("E_PLUGIN_PLATFORM")
            if p["stage_kind"] != s["kind"]:
                raise ContractError("E_PLUGIN_STAGE")
            if p["execution"] != s["execution"]:
                raise ContractError("E_STAGE_EXECUTION")
        elif s["kind"] not in {"freeze", "review"}:
            raise ContractError("E_PLUGIN_MISSING")
        if s["kind"] in {"freeze", "review"} and (plugin_id is not None or s["execution"] != "core"):
            raise ContractError("E_CORE_STAGE")
        for mapping in s["inputs"]:
            if set(mapping) != {"port", "from_stage", "from_port", "schema_id"}:
                raise ContractError("E_PORT_FIELDS")
            parent = mapping["from_stage"]
            if parent not in ancestors[sid]:
                raise ContractError("E_PORT_FUTURE")
            if by_id[parent]["outputs"].get(mapping["from_port"]) != mapping["schema_id"]:
                raise ContractError("E_PORT_TYPE")
        if plugin_id is not None:
            if set(s["outputs"].values()) != {p["output_type"]}:
                raise ContractError("E_PLUGIN_OUTPUT_TYPE")
            if s["kind"] != "analysis" and not any(m["schema_id"] == p["input_type"] for m in s["inputs"]):
                raise ContractError("E_PLUGIN_INPUT_TYPE")
        ancestor_kinds = {by_id[x]["kind"] for x in ancestors[sid]}
        if s["kind"] == "freeze" and "change" not in ancestor_kinds:
            raise ContractError("E_FREEZE_ORDER")
        if s["kind"] == "check":
            if "freeze" not in ancestor_kinds or "review" in ancestor_kinds:
                raise ContractError("E_CHECK_ORDER")
            if not any(m["schema_id"] == "candidate-binding@1" for m in s["inputs"]):
                raise ContractError("E_CHECK_CANDIDATE")
        if s["kind"] == "review" and "check" not in ancestor_kinds:
            raise ContractError("E_REVIEW_ORDER")
    return order

        if a.get("id"):
            self.anchors.append(a["id"])
        if tag == "a" and a.get("name"):
            self.anchors.append(a["name"])
        for key in ("href", "src"):
            if a.get(key) is not None:
                self.links.append(a[key])
    def handle_startendtag(self, tag: str, attrs: list[tuple[str, str | None]]) -> None:
        self.handle_starttag(tag, attrs)


def markdown_facts(data: bytes) -> tuple[list[str], list[str], list[str]]:
    """CommonMark parsing with an explicit-anchor-only project profile."""
    if len(data) > MAX_BYTES:
        raise ContractError("E_DOC_LIMIT")
    try:
        text = data.decode("utf-8")
    except UnicodeError as exc:
        raise ContractError("E_DOC_ENCODING") from exc
    if text.startswith("\ufeff"):
        raise ContractError("E_DOC_ENCODING")
    # Collect parsed nodes, not regex matches from source code fences.
    parser = MarkdownIt("commonmark", {"maxNesting": 64})
    parser.validateLink = lambda url: True  # retain unsafe schemes for explicit rejection
    tokens = parser.parse(text)
    links: list[str] = []
    anchors: list[str] = []
    unsupported: list[str] = []
    stack = list(reversed(tokens))
    count = 0
    while stack:
        token = stack.pop()
        count += 1
        if count > 100_000:
            raise ContractError("E_DOC_LIMIT")
        if token.type == "link_open":
            links.append(token.attrGet("href") or "")
        elif token.type == "image":
            links.append(token.attrGet("src") or "")
        elif token.type in {"html_inline", "html_block"}:
            h = HtmlFacts()
            h.feed(token.content)
            h.close()
            links.extend(h.links)
            anchors.extend(h.anchors)
            unsupported.extend(h.unsupported)
        if token.children:
            stack.extend(reversed(token.children))
    return links, anchors, unsupported


def local_target(source: str, url: str) -> tuple[str, str, str]:
    """Resolve a Markdown link; unlike ResourceRef syntax, internal ../ is allowed."""
    repo_path(source)
    if any(ord(c) < 32 or ord(c) == 127 for c in url) or "\\" in url:
        return "FORBIDDEN_PATH", "", ""
    try:
        u = urlsplit(url)
    except ValueError:
        return "INVALID_URL", "", ""
    if u.scheme.lower() in {"http", "https"} or (not u.scheme and u.netloc):
        return "NOT_CHECKED_EXTERNAL", "", ""
    if u.scheme.lower() in {"mailto", "tel"}:
        return "NOT_CHECKED_NONFILE", "", ""
    if u.scheme:
        return "FORBIDDEN_SCHEME", "", ""
    if u.query:
        return "UNSUPPORTED_QUERY", "", ""
    if re.search(r"%(?![0-9a-fA-F]{2})", u.path + u.fragment):
        return "INVALID_URL", "", ""
    try:
        path = unquote(u.path, encoding="utf-8", errors="strict")
        fragment = unquote(u.fragment, encoding="utf-8", errors="strict")
    except UnicodeError:
        return "INVALID_URL", "", ""
    if any(ord(c) < 32 or ord(c) == 127 for c in path + fragment) or "\\" in path or ":" in path:
        return "FORBIDDEN_PATH", "", ""
    if not path:
        return "LOCAL", source, fragment
    # Do not decode a second time. A literal %2e name is not another parent segment.
    parts = [] if path.startswith("/") else source.split("/")[:-1]
    for p in path.split("/"):
        if p in {"", "."}:
            continue
        if p == "..":
            if not parts:
                return "FORBIDDEN_PATH", "", ""
            parts.pop()
        else:
            parts.append(p)
    if not parts:
        return "DIRECTORY_TARGET_UNSUPPORTED", "", ""
    return "LOCAL", "/".join(parts), fragment


def docs_check(snapshot: Snapshot, source_paths: list[str]) -> dict[str, Any]:
    findings: list[dict[str, str]] = []
    cache: dict[str, tuple[list[str], list[str], list[str]]] = {}
    def facts(p: str):
        if p not in cache:
            cache[p] = markdown_facts(snapshot.read(p))
        return cache[p]
    for path in sorted(set(source_paths)):
        links, anchors, unsupported = facts(path)
        if len(anchors) != len(set(anchors)):
            findings.append({"source": path, "target": "", "status": "DUPLICATE_ANCHOR"})
        for tag in sorted(set(unsupported)):
            findings.append({"source": path, "target": tag, "status": "UNSUPPORTED_HTML"})
        for href in links:
            status, target, fragment = local_target(path, href)
            if status == "LOCAL":
                if target not in snapshot.names():
                    status = "BROKEN_LOCAL_LINK"
                elif fragment:
                    if not target.endswith(".md"):
                        status = "UNSUPPORTED_FRAGMENT_TARGET"
                    else:
                        _, ids, bad = facts(target)
                        if bad:
                            status = "UNSUPPORTED_HTML"
                        elif len(ids) != len(set(ids)):
                            status = "DUPLICATE_ANCHOR"
                        else:
                            status = "LOCAL_OK" if fragment in ids else "BROKEN_FRAGMENT"
                else:
                    status = "LOCAL_OK"
            findings.append({"source": path, "target": href, "status": status})
    excluded = {"NOT_CHECKED_EXTERNAL", "NOT_CHECKED_NONFILE"}
    errors = [f for f in findings if f["status"] not in excluded | {"LOCAL_OK"}]
    return {"profile": "commonmark-explicit-anchors-v1", "findings": findings,
            "local_status": "SATISFIED" if not errors else "FAILED_OR_INCOMPLETE",
            "unchecked": sum(f["status"] in excluded for f in findings),
            "semantic_review": "NOT_PERFORMED"}

def quality_issues(observation: dict[str, Any], required_tests: set[str]) -> list[str]:
    """Input already provided by the trusted assembly layer; no authentication here."""
    issues: list[str] = []
    if not observation.get("transport_complete"):
        issues.append("E_CHECK_INCOMPLETE")
    if type(observation.get("exit_code")) is not int or observation.get("exit_code") != 0:
        issues.append("E_CHECK_EXIT")
    tests = observation.get("tests", {})
    if not tests:
        issues.append("E_NO_TESTS")
    if required_tests - tests.keys():
        issues.append("E_TARGET_TEST_MISSING")
    for ident in sorted(required_tests & tests.keys()):
        if tests[ident]["status"] != "PASSED":
            issues.append("E_TARGET_NOT_PASSED:" + ident)
    # Existing failures/errors are not made harmless by the new target passing.
    if any(x["status"] in {"ASSERTION_FAILURE", "ERROR", "XPASS"} for x in tests.values()):
        issues.append("E_TEST_SUITE_FAILURE")
    return issues


def review_readiness(expected: CheckBinding, observations: list[dict[str, Any]],
                     required_check_ids: set[str], required_tests: set[str],
                     content_status: str, core_gates: str) -> dict[str, Any]:
    """Never emits PASS/ACCEPTED; core gates and human/model review remain separate."""
    issues: list[str] = []
    ids = [o["check_id"] for o in observations]
    if len(ids) != len(set(ids)):
        issues.append("E_CHECK_DUPLICATE")
    if set(ids) != required_check_ids:
        issues.append("E_CHECK_SET")
    for o in observations:
        if o["binding"] != expected.__dict__:
            issues.append("E_CANDIDATE_OR_ENV_DRIFT")
        if o.get("source_kind") != "core_observation":
            issues.append("E_SELF_REPORT")
        issues.extend(quality_issues(o, required_tests))
    if content_status != "REVIEWED_SATISFIED":
        issues.append("E_CONTENT_REVIEW_REQUIRED")
    if core_gates != "SATISFIED":
        issues.append("E_CORE_GATES")
    return {"status": "BLOCKED" if issues else "READY_FOR_SUPERVISOR_DECISION",
            "issues": sorted(set(issues))}


def classify_countertest(good: dict[str, Any], variant: dict[str, Any],
                         target_id: str, assertion_id: str) -> str:
    """Stricter than generic mutation scores; failure must hit the approved assertion."""
    for key in ("suite_sha256", "runner_sha256", "environment_sha256"):
        if good[key] != variant[key]:
            return "INCOMPARABLE"
    if good.get("transport_complete") is not True or type(good.get("exit_code")) is not int or good.get("exit_code") != 0:
        return "REFERENCE_INVALID"
    if not good.get("tests") or any(t["status"] != "PASSED" for t in good["tests"].values()):
        return "REFERENCE_INVALID"
    if target_id not in good["tests"]:
        return "REFERENCE_INVALID"
    if variant.get("mutation_verified") is not True:
        return "VARIANT_UNVERIFIED"
    if variant.get("timed_out"):
        return "INCONCLUSIVE_TIMEOUT"
    if variant.get("transport_complete") is not True:
        return "INCOMPLETE"
    if any(t["status"] == "ERROR" for t in variant.get("tests", {}).values()):
        return "INVALID_VARIANT"
    if set(good["tests"]) != set(variant.get("tests", {})):
        return "COLLECTION_DRIFT"
    target = variant["tests"][target_id]
    if target["status"] == "ASSERTION_FAILURE" and target.get("assertion_id") == assertion_id:
        # A failure row with a success/unknown process exit is conflicting evidence.
        if type(variant.get("exit_code")) is not int or variant["exit_code"] != 1:
            return "HARNESS_ERROR"
        return "DETECTED_TARGET_ASSERTION"
    if target["status"] in {"SKIPPED", "XFAIL", "XPASS"}:
        return "TARGET_NOT_EXERCISED"
    if any(t["status"] == "ASSERTION_FAILURE" for t in variant["tests"].values()):
        return "UNRELATED_FAILURE"
    if variant.get("exit_code") != 0:
        return "HARNESS_ERROR"
    return "SURVIVED_OR_UNPROVEN"


def reduce_repeats(outcomes: list[str], expected_repetitions: int) -> str:
    if type(expected_repetitions) is not int or expected_repetitions < 1 or len(outcomes) != expected_repetitions:
        return "INCOMPLETE"
    if len(set(outcomes)) != 1:
        return "FLAKY_OR_INCONSISTENT"
    return outcomes[0]

"""Extract only explicitly named UTF-8 files; does not execute extracted content."""
from __future__ import annotations
import argparse
from pathlib import Path, PurePosixPath
import re

MARKER = re.compile(r"<!-- artifact-file: ([^>]+?) -->\s*$")
FENCE = re.compile(r"(`{3,}|~{3,})([A-Za-z0-9_-]*)\s*$")


def read_embedded(markdown: Path) -> dict[str, bytes]:
    lines = markdown.read_bytes().decode('utf-8', errors='strict').splitlines(keepends=True)
    result: dict[str, bytes] = {}
    index = 0
    while index < len(lines):
        marker = MARKER.fullmatch(lines[index].rstrip('\r\n'))
        if marker is None:
            index += 1
            continue
        name = marker.group(1)
        path = PurePosixPath(name)
        if (not name or '\\' in name or ':' in name or path.is_absolute()
            or any(x in ('', '.', '..') for x in name.split('/'))
            or any(ord(c) < 32 or ord(c) == 127 for c in name)):
            raise ValueError('Unsafe embedded path: ' + repr(name))
        if name in result:
            raise ValueError('Duplicate embedded path: ' + name)
        index += 1
        if index >= len(lines):
            raise ValueError('Missing code fence for ' + name)
        opening = FENCE.fullmatch(lines[index].rstrip('\r\n'))
        if opening is None:
            raise ValueError('Expected immediate code fence for ' + name)
        fence = opening.group(1)
        index += 1
        content: list[str] = []
        while index < len(lines) and lines[index].rstrip('\r\n') != fence:
            content.append(lines[index])
            index += 1
        if index >= len(lines):
            raise ValueError('Unclosed code fence for ' + name)
        result[name] = ''.join(content).encode('utf-8')
        index += 1
    if not result:
        raise ValueError('No named files found')
    # Avoid platform-specific collisions before any writes.
    import unicodedata
    keys = [unicodedata.normalize('NFC', x).casefold() for x in result]
    if len(set(keys)) != len(keys):
        raise ValueError('Portable filename collision')
    return result


def main() -> None:
    parser = argparse.ArgumentParser(description=__doc__)
    parser.add_argument('markdown', type=Path)
    parser.add_argument('destination', type=Path)
    args = parser.parse_args()
    files = read_embedded(args.markdown)
    # Deliberately no --force/overwrite mode; use a fresh owned directory.
    args.destination.mkdir(parents=True, exist_ok=False)
    for name, payload in files.items():
        target = args.destination.joinpath(*PurePosixPath(name).parts)
        target.parent.mkdir(parents=True, exist_ok=True)
        with target.open('xb') as handle:
            handle.write(payload)
    print(f'Extracted {len(files)} files into {args.destination}')


if __name__ == '__main__':
    main()
