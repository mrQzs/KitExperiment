## 1. 目标与非目标

### 1.1 原文目标与首期交付

本模块把明确的任务及插件组合为可检查的依赖图，管理就绪、并行、预算和停止条件。任务顺序、类型化产物映射、写入范围和互斥约束必须显式表达；只有审核、真实基线、输入锁、能力、权限、额度和冲突条件同时满足时，才进入派遣路径。planner、executor、独立复审与可选 observer 的消耗都归入同一需求。[^P07]

首期先证明**无模型、无外部副作用的静态校验和事务决策**，再接入现有 attempt。人工已发布合同或离线 fixture 即可验证 07；不以 09 规划 CLI 完成为前置条件。

建议“完成 07”的标准不是画出 DAG 或使 stub 返回成功，而是：同一冻结输入能够产生可复核的就绪理由；重复请求不能创建重复活动尝试；并行预留不能重复占用同一余量；未知启动、未知费用和复审未决不能被当成正常完成；恢复过程不丢失历史运行与真实消耗。

### 1.2 非目标和禁止的隐式扩展

**原文保留**：DAG 不自动决定架构，不修改合同、不接受失败结果、不批准集成；首期不支持非 Git 产物存储，也不承诺分布式集群调度。[^P07]

本版进一步限定首期实现：

| 范围 | 首期建议 | 明确不包含 |
|---|---|---|
| 执行位置 | 一个受信宿主、一个明确仓库命名空间、一个权威调度账本 | 跨主机抢占、共享盘集群、跨地域容灾承诺 |
| 图形态 | 静态、有限、有向无环；跨任务依赖全部为 AND | 动态插节点、运行时脚本表达式、无限循环、隐式 OR 分支 |
| 类型映射 | 固定端口与固定 Schema；不能证明兼容就拒绝 | 根据模型文本猜字段、静默转换或任意映射脚本 |
| 调度 | 先串行；并行逐对有独立性记录且有独立 worktree | 仅按路径字符串不同推断安全 |
| 自动重试 | 受主模型已登记裁决、机械上限、当前授权及余额约束 | `retryable=true` 直接触发调用、自动换模型或扩大工具范围 |
| 产物 | Git 对象及其固定字节引用；运行证据另由现有证据存储保留 | 将任意云盘 URL、临时文件或“最新结果”当正式业务产物 |

“首期不支持非 Git 产物存储”不意味着强迫日志、审核和预算数据库提交到业务分支；它约束跨任务可消费的业务产物。运行日志仍按既有 `.agent/` 证据规则存储，二者不能混为一谈。

### 1.3 必须维持的不变量

| 编号 | 不变量 |
|---|---|
| I01 | `request_id` 是预算根；拆任务、改名、换角色、换 CLI、换合同版本及重试均不重置累计。 |
| I02 | `task_id`、`stage_id`、`attempt_id`、`run_id`、`operation_id` 分别建模，不相互替代。 |
| I03 | 可细化不要求尚未存在的执行合同；可执行必须有针对真实基线的正式合同与有效审核。 |
| I04 | 跨任务消费需要上游接受；同一合同检查可以读取尚未 PASS 的固定候选。 |
| I05 | Git 对象存在、候选 PASS、主模型接受、基线使用许可和集成许可是不同事实。 |
| I06 | 领取、资源占用、预算预留和权威事件在同一权威事务中成立，或明确采用有补偿边界的分步协议。 |
| I07 | 租约到期、PID 不可见、退出 0、管道 EOF 都不能单独证明可以释放全部运行占用。 |
| I08 | 旧协调器不能继续使用旧代际改变当前调度；数据库 fencing 不被夸大为已阻止所有外部副作用。 |
| I09 | 费用迟到、超预算、失败、取消或运行未知时仍登记真实用量，不截断事实以维持“余额非负”。 |
| I10 | 接受绑定确切候选和检查集；重放、合并、rebase 或检查定义改变不能继承旧 PASS。 |
| I11 | 审核、接受和历史运行只追加；当前失效不抹掉当时实际发生的事实。 |
| I12 | 停止后禁止新派遣，但允许必要的采集、对账、身份核对与已授权清理；这些动作不是免费模型重试。 |

### 2.2 身份、版本与唯一性

| 字段 | 作用域/建议约束 | 变化规则 |
|---|---|---|
| `repository_namespace` | 受信登记的仓库身份；关联 Git common dir 与环境实例 | 同一物理仓库的别名不能绕过冲突锁 |
| `request_id` | 用户目标的稳定预算根 | 不能通过重新规划换 ID 重置额度 |
| `workflow_id` / `workflow_version` | 一个图及其冻结版本 | 改边、映射、节点声明或预算生成新版本 |
| `task_id` | request 内稳定任务身份 | 业务名称只是展示；重试和 plan 变化仍属于原任务 |
| `plan_version` | 正整数，正式合同版本 | 合同内容修改后追加版本 |
| `stage_id` | 仅在该任务合同内唯一 | `task-a/check` 与 `task-b/check` 不冲突 |
| `attempt_id` / 原 `attempt` | 一次任务执行尝试及既有序号 | 一次 attempt 可包含多个角色 run/检查；原序号语义保留 |
| `run_id` | 一次具体角色调用 | 每次重试/新调用使用新值；不以 vendor session ID 代替 |
| `operation_id` | 一次可能产生外部副作用的操作 | 重送同一操作保持不变；与 run/阶段关联 |
| `claim_generation` | 同一领取范围的单调代际 | 明确转移所有权时增加 |
| `controller_generation` | 主控接管/重启代际 | 不在每次轮询、连接或心跳时增加 |
| `guard_version` | 指向一组可核对的当前守卫高水位 | 是 CAS 条件，不是业务授权本身 |

**关键建议**：活动任务唯一约束应至少覆盖 `(repository_namespace, request_id, task_id)`，而不是仅覆盖 `(task_id, plan_version)`。否则 v1 合同尚在运行时发布 v2，两个版本可能同时写同一业务任务。任务内部的检查并行应使用独立阶段领取，不靠创建第二个任务 attempt 绕开这项约束。

纯本机检查可以有 `execution_id/operation_id` 而没有模型 `run_id`；一旦检查工具实际调用模型，就必须另登记可归属的模型 run 和用量。不能把每条 shell 命令一律统计为一次模型调用。

## 4. 接口和行为约束

### 4.1 任务图、任务内阶段与类型约束

#### 4.1.1 两层图及边的含义

**原文保留**：任务 DAG 节点对应可独立验收的任务合同；节点声明 ID、阶段组合、输入输出、依赖、预计写范围与子预算。任务内阶段声明插件版本、角色、输入映射和检查。任务边与阶段边分别建模；数组位置不代表业务顺序。[^P07]

```text
跨任务 DAG：  任务 A ──[已接受结果 + 固定产物 + 真实获准基线]──> 任务 B

任务 A 内部： execute ──> freeze(candidate K) ──> check(K) ──> verdict(K)
                         固定候选尚未 PASS，检查仍可开始

禁止改写为：  execute ──> 等待任务 A 已接受 ──> check
```

首期跨任务边全部为必需的 AND 依赖。上游被取消/拒绝不自动满足依赖；没有 OR、fallback、`continue_on_error` 或条件跳过的隐含语义。任务图和阶段图分别校验无环，报错分别携带 `task_id` 和 `stage_id`。

#### 4.1.2 工作流与节点字段合同

以下字段为**建议 API 家族第 1 版**，不等同于旧执行合同 schema v1。附录 A 的参考 Schema 使用该版本轴。

| 层级/字段 | 类型与要求 | 领域校验 |
|---|---|---|
| `record_type/schema_version` | 固定家族与整数版本 | 未知家族或版本拒绝，不退回旧合同解释 |
| `workflow_id/workflow_version` | 稳定 ID、正整数版本 | 发布不可原地覆盖 |
| `request_id/repo_id` | 必填身份 | 与正式合同、产物、预算账本的归属一致 |
| `platforms` | 非空去重枚举集合 | 全集合能力/检查覆盖由 05/06 已核验结果证明 |
| `plugin_lock_ref` | 固定锁文件引用 | 精确版本及闭包由 06 验证；不重新加载插件 |
| `nodes[]` | 非空节点数组 | ID 唯一；建议上限 1,000 节点、10,000 条边，待压测 |
| `max_parallel_tasks` | 正整数；首期建议 1 | 不能大于实际授权的 request 并发上限 |
| 节点 `depends_on[]` | 去重任务 ID 集合 | 所有目标存在；不可引用阶段 ID |
| 节点 `inputs/outputs` | 具名端口及完整 Schema 引用 | 类型身份包含 dialect/资源闭包，不只看标题 |
| 节点 `input_bindings` | 必需端口逐项绑定 | 缺失、额外绑定、来源不属于依赖时拒绝 |
| 节点 `stages[]` | 有明确依赖的阶段 | 局部 ID 唯一，顺序与候选检查约束成立 |
| `contract_ref/baseline_ref` | 草稿图可为 null | null 表示尚未具备正式对象，不可伪造占位引用 |
| `write_scope[]/resource_keys[]` | 文件/目录范围与语义互斥资源 | 核验真实平台路径；引用模块、接口、产物等冲突域 |
| `budget` | 子预算及计量维度 | 同 task 的多个 plan/attempt 共同消耗，不独立重置 |
| `retry_policy` | 总尝试数及退避条件 | 机械上限是必要条件，不是重试授权 |
| `priority` | 有限非负整数 | 只决定候选排序，不绕过依赖、资源或额度 |

输入根必须先经过 01 的严格 JSON 解析；重复键、非法 Unicode、非有限数、版本未知和结构未知不能先被“清洗”再校验。配置的 `_...` 说明例外不适用于本模块的图锁、合同、预算策略或接受记录。[^P01][^P02]

附录原型进一步限制：计数只接受真实整数，不接受 bool 或 `1.0`；不提供浮点配置字段；金额以十进制字符串表示。这是参考 profile 的限制，不宣称 01 的所有协议都禁止浮点数。

#### 4.1.3 阶段字段、检查消费和候选版本

| 阶段字段 | 要求 |
|---|---|
| `id/kind/role` | `kind` 与角色权限由受审阶段模板配对；冻结/签发等核心动作不能交给普通 executor 自证 |
| `depends_on` | 显式阶段 ID；阶段数组不决定先后 |
| `plugin_step_ref` | 精确插件步骤引用；核心内建阶段可为 null |
| `input_mapping`（生产扩展） | 只取本任务已锁输入、前序阶段固定输出或明确 candidate；不能引用未来阶段 |
| `checks_ref`（生产扩展） | 已锁正式命令/断言/独立检查集；不从插件文本执行任意命令 |
| `candidate_binding`（生产扩展） | 每项检查精确绑定 candidate/check-set/environment；不能用“当前 worktree”代替 |

附录静态原型只实现 `execute/freeze/check/verdict` 四类阶段、依赖和任务级具名端口；**没有实现生产 `input_mapping`、角色授权或完整检查集编译**。其字段草案在上表中单独列出，不伪装为已由代码验证。

单合同的候选可以是尚未提交的固定 tree/补丁与证据；检查不要求它先有任务接受事件，也不因阶段切换强迫新 commit。若执行返工产生 K2，K1 的检查只证明 K1。K2 必须重新固定，并按受审规则重跑相关检查，主模型裁决不得把 K1 的 PASS 简单复制过去。

#### 4.1.4 类型兼容不是“拿一个样例跑过 Schema”

定义语义目标：上游允许输出集合为 `S_out`，下游允许输入集合为 `S_in`，安全直连要求 `S_out ⊆ S_in`，且实际产物也满足目标约束。验证一个实例只说明该实例合法，不能证明集合包含。

**首期建议选择保守、可实现的规则**：相同已登记类型身份、相同 Schema 完整字节引用及引用闭包可直接匹配；不同 Schema 默认返回 `E_TYPE_UNPROVEN`。需要结构投影/转换时，先定义并审核一个有限映射 profile 及其输出 Schema，再由核心执行，并在绑定时验证实际结果。不把 JSON Schema 的 `allOf` 当对象合并器或继承求解器。`additionalProperties` 的封闭范围也需要正确理解。[^W05]

Schema 相同不代表业务数据安全、来源可信或基线可用。还要检查资源种类、端口语义、大小上限、产物 provenance，以及下游是否获准读取该数据。

| 情况 | 处理 |
|---|---|
| 同名类型、不同 Schema 字节 | 不自动兼容；记录引用差异 |
| Schema 相同、路径不同 | 类型可相同，但两处资源定位和字节仍各自核验 |
| 源有可选字段、目标要求必填 | 必须证明总能提供；仅某条样例有该字段不够 |
| 字段缺失 | `MISSING`；不自动转为 null |
| 显式 null | 按目标 Schema 判断；与缺失不同 |
| 数字字符串到整数、枚举大小写转换 | 不自动转换；映射规则需版本化 |
| 任意 `$ref` URL 或文件路径 | 只在受控本地 registry 中解析；未知引用拒绝 |

JSON Schema 资源注册可以使用固定的 `referencing.Registry`；不要为方便而给用户提供任意联网 retrieve。Schema 的结构约束与 resolver 的来源信任是两层校验。[^W06]

#### 4.1.5 输入映射算法与实际实例核验

```text
输入：冻结工作流版本、已解析插件类型、外部固定输入、上游 AcceptedResult
1. 对每个目标端口检查映射恰好 0/1 个；必填为 1，额外端口拒绝。
2. task-output 来源必须属于该节点显式依赖，输出端口必须存在。
3. 核验上游接受记录、实际产物引用及其当前可消费性；不查询“latest”。
4. 证明类型兼容；首期只允许精确已登记 Schema 身份匹配。
5. 在受控大小上限内读取已固定字节，按端口媒体类型解析。
6. 如采用已批准映射 profile，生成新的输入字节；记录 source→target 映射。
7. 验证目标实例、必填/缺失规则、类型与授权覆盖。
8. 封存 InputBindingReceipt；prepare/run 只消费该回执指向的固定对象。
```

跨任务绑定必须记录“哪个 task、哪个接受版本、哪个候选、哪个输出端口、哪个产物、哪个目标 Schema”。用 `upstream_task_id` 加一个路径不足以防止同名输出被后续重试替换。

如将来启用 JSON Pointer：采用 RFC 6901 的 `~0/~1` 转义，空 pointer 指整个文档，缺路径必须报错；不能自动解释 JSONPath、通配符、Python 表达式或 shell。附录有独立 pointer 语法测试，但**未将 pointer 映射启用为工作流功能**。[^W07]

#### 4.1.6 图校验顺序和确定性

建议次序：大小/编码/严格 JSON → 家族/Schema → ID/路径 → 插件闭包与平台能力 → 两层边存在性 → 两层无环 → 端口/类型 → 阶段候选规则 → 预算形状 → 资源冲突声明 → 工作流锁候选。

拓扑排序建议使用 Kahn 算法，并在同时可取节点之间按稳定 ID 排序；运行策略可以再按受审优先级选择候选。剩余入度大于零说明存在循环相关阻塞，但**不等于所有剩余节点都在最小环内**。正式诊断再执行 DFS/SCC 产出具体环路径。附录原型只报告剩余受阻节点，明确不声称输出最小环。

静态校验不能执行模型、运行插件、下载 Schema、自动 fetch Git 或调用平台检查命令；这些都是独立受控动作。动态能力证据不足，返回预检缺口而不是假定支持。

#### 4.1.7 工作流锁、相关变更与精确失效

`WorkflowLock` 建议记录原定义引用、所选插件锁、Schema/映射 profile、编译器版本、确定性节点/边清单、共享调度/预算策略。原定义始终按其实际文件字节保留；只有核心生成的新锁才采用已登记的固定序列化规则，不对用户原 JSON 做重排后冒充原哈希。

**重要边界**：审核若引用整个工作流锁，工作流锁一字节改变就必须重新核验所有依赖该锁的审核。不能同时宣称“锁定全图”却又无依据地忽略全图变化。将来要实现按节点精准失效，必须新增可信的节点闭包投影：上游契约、映射、共享策略、冲突域及预算依赖均进入投影，并明确证明未包含部分确实无关。首期建议先用完整锁，接受较保守的再审核范围。[^P03][^P07]

| 变化 | 当前待运行节点 | 已运行/已完成记录 |
|---|---|---|
| 边、输入映射、所选插件、Schema、预算 | 新工作流版本和相关再审核 | 保留原锁；后续动作重核验 |
| 某 task 正式合同/基线变化 | 新 plan 版本；旧 READY 观察失效 | 原 run 不被改写到新基线 |
| 只读状态游标、日志展示排序 | 不应使语义锁失效 | 仅新投影 |
| 上游接受被撤销或产物损坏 | 受影响后继停止新派遣 | 历史接受仍保留，增加当前失效/待决状态 |
| 发布 A→B→A | 遵守 03 的受控绑定代际建议，不仅比较当前摘要 | 不自动复活原准入 |

### 4.2 就绪与真实基线

#### 4.2.1 可细化、可执行与允许启动规划是三个判断

**原文保留**：必要上游已接受且固定输入可核对、所需代码位于真实且获准使用的可解析提交时，任务可进入合同细化。正式执行还需针对该基线的合同、审核、输入锁、能力、权限、额度和无冲突条件。规划调用自身核对规划授权、profile 和预算，不要求尚未生成的执行合同。[^P07]

```text
can_refine = accepted_inputs_ok AND baseline_exists AND baseline_use_authorized

can_start_planner = can_refine AND planning_authorized
                   AND planning_profile_verified AND planning_budget_reserved
                   AND request_allows_planning AND planning_inputs_locked

can_execute = can_refine AND formal_contract_current AND approval_current
              AND input_locks_match AND capabilities_satisfied
              AND execution_authorized AND budget_available
              AND conflicts_clear AND request_allows_dispatch
```

`can_refine=true` 只是可以起草具体合同，不等于已经获准启动付费规划。相反，缺执行合同不应该把已满足规划条件的节点永久卡在 `WAIT_CONTRACT`，导致 09 等 07、07 又等 09。

附录原型的 `readiness()` 只接收受信的合成事实，演示上述逻辑拆分；它不读取真实审核、Git、权限或预算，不是公开 API 可接受调用者自填布尔值的实现。

#### 4.2.2 就绪诊断字段与等待理由

建议 `ReadinessReport` 记录 workflow/contract/input/environment 引用、当前依赖接受版本、观察时刻、guard high-water、两类就绪与全部原因。它是**观察快照**；领取和 handoff 必须重查当前条件，不能缓存 `ready=true` 后无限复用。

| 原因 | 可否继续细化 | 可否执行 | 责任方/解决方式 |
|---|---|---|---|
| `WAIT_UPSTREAM_ACCEPTANCE` | 否 | 否 | 等主模型接受固定结果，不读未验收输出 |
| `WAIT_FIXED_ARTIFACT` / `ARTIFACT_CORRUPT` | 否 | 否 | 恢复原字节或重新产生/接受结果 |
| `WAIT_REAL_COMMIT` | 否 | 否 | 按既有授权提供真实 commit；不自动提交 |
| `WAIT_BASELINE_AUTHORIZATION` | 否 | 否 | 核验现有使用授权或由主模型处理 |
| `WAIT_CONTRACT` | 是，若前置两项满足 | 否 | 人工或 09 生成针对固定基线的合同 |
| `WAIT_APPROVAL` / `INPUT_DRIFT` | 可生成新草稿 | 否 | 03 登记/重新审核具体版本 |
| `CAPABILITY_GAP` / `PLATFORM_GAP` | 不自动改变任务 | 否 | 04/05/06 提供缺口，禁止静默跳过 |
| `WAIT_RESOURCE` / `WAIT_CONCURRENCY` | 通常是 | 否 | 等真实占用释放，不改授权 |
| `WAIT_BUDGET` / `USAGE_UNKNOWN` | 不授予新调用 | 否 | 对账或主模型明确处置额度 |
| `REQUEST_STOPPED` / `RECOVERY_REQUIRED` | 仅允许已明确批准的整理 | 否 | 先恢复事实，再明确 resume |

错误严重度与等待可恢复性单独表示；“暂时可重试”不等于可重新执行模型。内部异常不得被转换成“无阻塞”。建议 `retryable` 仅针对这次状态查询或事务竞争，不隐式绑定到业务重跑。

#### 4.2.3 基线核验不是一个 `git rev-parse` 就完成

`BaselineBinding` 至少包括 repo/environment、Git 对象格式、完整 `base_sha`、实际 commit/tree、所需上游结果、内容覆盖模式、授权引用、观察证据和守卫版本。

| 核验层 | 必须证明 | 不能代替它的事实 |
|---|---|---|
| 身份 | 当前确为受信登记的仓库，未混用 Windows/WSL/Git common dir | 路径文字相同 |
| 对象 | 完整 OID 在该仓库可解析，类型为 commit | 分支名、短 SHA、存在一个同名文件 |
| 内容 | 所需代码/业务产物确实出现在目标基线中 | commit 是某上游提交的后代 |
| 来源 | 内容与接受记录、候选、检查结果有可追溯关系 | 提交说明写了“测试通过” |
| 授权 | 允许创建/使用该候选提交或集成版本 | 候选测试 PASS、具备读取文件权限 |
| 当前性 | 没有相关撤销/漂移；合同确实绑定该基线 | 过去某次预检成功 |

Git 的 `cat-file` 可以查询对象类型及原始对象内容；`merge-base --is-ancestor A B` 只判断祖先关系，退出状态必须与错误区分。祖先成立不证明 B 仍保留 A 的所有代码或验收语义。[^W03][^W04]

建议使用 05 受控 argv 调用明确的只读取证命令，输入先验证为完整 OID。以下是**命令规格示意，不是本次对用户仓库的执行记录**：

```text
git rev-parse --show-object-format=storage
git cat-file -t <validated-full-commit-oid>
git cat-file -p <validated-full-commit-oid>
git merge-base --is-ancestor <validated-upstream-oid> <validated-base-oid>
```

`rev-parse` 的仓库对象格式和完整对象验证能力要按实际 Git 版本取证；Git OID 与 ResourceRef 的普通文件 SHA-256 不是同一语义。[^W08]

生产读取还要明确 replacement refs、grafts、浅克隆、promisor/lazy fetch、submodule 与 LFS 的影响。需要禁用或记录改变对象解释的机制；缺本地对象时阻塞，不在“只读核验”名义下自动联网补齐。具体禁止联网能力由 05 保证，不能只放一个 Git 参数就宣称网络已隔离。

#### 4.2.4 内容覆盖的三种受审模式

| 模式 | 判定 | 适用与限制 |
|---|---|---|
| `exact_tree` | 获准 commit 的 tree 与已接受 candidate tree 精确一致 | 最清晰；仍须核验提交使用授权，不自动创建 commit |
| `pinned_artifact_set` | 基线中声明的路径/模式/blob 与接受产物清单逐项相同 | 必须有受审清单与跨模块语义评估，不能拿少量文件一致证明整项目等价 |
| `revalidated_integration` | 合并/rebase 后新候选有新检查及接受记录 | 基线来自新结果；不继承旧候选 PASS |

`pinned_artifact_set` 的文件列表不得由执行器在发现差异后临时删减。应包括文件模式、路径、blob、相关接口/生成物与必要依赖；目录内未声明新增项的处理也要确定。符号链接、submodule gitlink、LFS pointer 与普通文件分别按 06/05 已受审规则处理。

报告类 JSON 也必须有可定位的 Git 版本与真实字节；`schema_ref` 合法不意味着业务产物已经提交。首期无法提供可消费 Git 产物时保持等待，不能临时引入另一种存储绕过原范围。

#### 4.2.5 多上游合流：禁止静默选一个分支

假设 A、B 均从 S0 独立执行并被接受，分别产生 KA、KB。C 同时依赖 A、B。C 的基线不能简单选择 A 的 commit，除非已证明其中包含 C 所需的 B 产物并获准使用；不能把两份未提交补丁直接拼进 C 工作区并仍写 `base_sha=S0`。

正确流程：保存 A/B 的接受与产物 → 主模型按现有授权决定来源 → 在有明确授权时由受控集成路径构造合流候选 KC → 对 KC 重新执行相关检查与接受 → 形成获准 commit SC → C 针对 SC 细化合同并审核。没有提交/使用/集成授权时，C 停在 `WAIT_REAL_COMMIT` 或 `WAIT_BASELINE_AUTHORIZATION`。

这些动作不由 DAG 自动执行，也不要求 A/B 任务内部的检查必须先创建 commit；跨任务基线要求与单任务候选检查要求必须保持分离。

#### 4.2.6 读取固定产物与重新核验

读取流程建议为：解析受控 Git 对象/封存证据 → 取得固定字节 → 完整哈希 → Schema/类型验证 → 建立输入绑定 → 后续消费同一固定字节/对象版本。禁止“审核时读 A、运行时按相同文件名读 B”。

缓存键至少包含 workflow/contract/input refs、依赖接受版本、基线、配置与插件锁、环境记录、相关审核/策略代际和校验器版本。缓存只加速不可变对象核验；当前撤销、额度、资源占用和 request stop 始终重新检查。mtime、文件大小和任务名称不能代替内容锁。

### 4.3 并发、重试与结果接受

#### 4.3.1 状态域必须分开

| 状态域 | 建议表示 | 不应推导出的结论 |
|---|---|---|
| 定义/发布 | DRAFT / VALIDATED / LOCKED / PUBLISHED / SUPERSEDED | PUBLISHED 不等于可执行 |
| 就绪投影 | can_refine、can_execute、reasons[] | ready 不是长期许可 |
| 任务进展 | WAITING / CONTRACT_PENDING / CLAIMED / ACTIVE / REVIEW_PENDING / ACCEPTED / REJECTED / CANCELLED | ACCEPTED 不等于已集成或永久可消费 |
| 准入/启动 | CLAIMED → ADMITTED → HANDOFF_ACCEPTED → STARTED；另有 START_UNKNOWN | HANDOFF_ACCEPTED 不证明进程已启动 |
| attempt | 继续使用既有状态/verdict | 不重命名或重写旧历史 |
| 运行与采集 | 05 的 process/I/O/cleanup 状态 | 主进程退出不等于全部监督范围清空 |
| 预算 | reserved / provisional / unknown liability / reconciled / corrected | reconciled 不证明任务接受 |
| request 控制 | OPEN / PAUSING / STOPPED / RECOVERING / CLOSED | CLOSED 不意味着迟到账单可以丢弃 |

原型将若干内部阶段简化为 `RESERVED/HANDOFF_ACCEPTED/RUNNING/START_UNKNOWN/REVIEW_PENDING/...`；它不修改正式架构或旧 attempt 名称，也不完整模拟 `ADMITTED` 与 03 的生产接线。

#### 4.3.2 并行独立性和资源占用

**原文保留**：同文件、同模块、显式互斥资源的写任务默认串行；不同文件也检查接口及产物依赖。并行必须有已记录独立性判断与独立 worktree。[^P07]

建议同时维护两类约束：**冲突资源集**和**独立性证明**。资源无冲突只是必要条件，不是充分条件。

| 资源类别 | 建议锁键/比较 | 典型漏判 |
|---|---|---|
| 文件/目录 | repo + 规范化路径 + file/tree + R/W | `src/a` 与 `src/a/x.py`；同一文件大小写别名 |
| 模块/接口 | repo + 版本化模块/接口 ID | A 改接口声明，B 在不同文件依赖旧行为 |
| 产物/导出 | repo + artifact/export ID | 两个任务写同名报告或生成代码 |
| 运行环境 | 缓存、端口、数据库、测试服务或可写临时区 ID | worktree 独立但测试使用同一端口/外部环境 |
| Git 管理动作 | common dir + 管理操作类别 | 并发操作共享 refs/index/工作树管理状态 |
| 显式 mutex | 受控命名空间内的 ID | 用 request 私有键绕过另一 request 的同模块冲突 |

比较规则：同键 R/R 可兼容，R/W 与 W/W 冲突；目录按路径段判断包含，不使用简单字符串前缀。`src/a` 不包含 `src/ab`。平台路径身份、大小写/Unicode 冲突、symlink/junction 与真实对象解析归 05/06；不能在调度层统一 `.lower()` 代替平台语义。

未知 glob 交集、动态输出或无法界定的模块影响应按冲突处理，或要求更保守的模块锁。并行证明须绑定相关节点合同、基线、scope、接口和环境资源；这些输入改变后不能复用原证明。

同一 repository 的所有 request 使用同一资源占用权威。任务释放进程并发槽和文件占用后，其待复审 attempt 仍占用**本任务活动尝试槽**；不得在复审未决时开启另一版本写该任务。已接受产物的保留 pin 与写锁不同，不能因为停止写入就删除其来源。

#### 4.3.3 单宿主权威存储建议

首期建议使用本地 SQLite 作为权威领取/预算账本，所有相关连接显式开启外键，短写事务使用 `BEGIN IMMEDIATE`；账本对象、当前守卫及 outbox 尽量处于同一数据库。SQLite 同时允许多个读事务，但只有一个写事务；`BEGIN IMMEDIATE` 仍可能返回 `SQLITE_BUSY`，必须有限重试或返回竞争状态。[^W01][^W09]

**这是新增存储建议，不是原文规定，也不表示用户已有该数据库。** 若实际项目已有可靠持久领取机制，应先评估复用，不以新增数据库为由绕开原锁。

附录测试使用 **DELETE journal + synchronous=FULL**。本容器实际 SQLite 为 `3.46.1`，没有据此声称 WAL 生产安全已验收。SQLite 官方已记录 WAL-reset 问题及修复版本：3.51.3 及以后、部分回补分支包括 3.44.6/3.50.7；采用 WAL 前应核对实际链接的引擎或供应商修复证明。WAL 还要求同宿主共享状态，不适用于把数据库放在网络文件系统做集群调度。[^W02]

| 概念表 | 主键/约束 | 作用 |
|---|---|---|
| request / request-policy-head | request 唯一、策略代际 | 总预算、停止状态、并发和当前授权范围 |
| workflow-version / task-head | 冻结资源引用、当前 generation | 固定定义与可执行合同版本 |
| attempt / stage-operation | task 活动唯一、阶段活动唯一、operation ID 唯一 | 防跨 plan 重复尝试与阶段重复启动 |
| resource-hold | repo + 资源规范键 + 持有者 | 占用与兼容模式 |
| budget-reservation / usage-observation | reservation ID、经济调用键/修订唯一 | 预留、追加事实和去重 |
| usage-current / budget-projection | 带游标的可重建当前值 | 计算余额，不作为第二套计费来源 |
| idempotency | 主体/范围/操作/键唯一 | 响应丢失恢复 |
| outbox / consumer-cursor | 稳定事件 ID/游标 | 事务内记录，事务外重放 |

附录 `ledger_ref.py` 中的完整 DDL 是上述内容的**受限事务原型**：一任务一次主调用、精确排他键、固定合成守卫、累计计量。它没有完整 production table family，不能直接替换真实审核数据库。

#### 4.3.4 原子领取的事务边界

慢操作应在事务外完成：读取固定文件、哈希、Git 取证、06 静态解析等。它们输出不可变资源与受信版本化事实。进入事务后只检查这些事实仍对应当前绑定，避免持有数据库写锁时启动模型、访问网络、遍历大目录或等待用户。

```text
TX CLAIM（同一权威数据库）
  BEGIN IMMEDIATE
  1. 查 scoped idempotency key：同内容重放原结果；不同内容报冲突。
  2. 检查 controller/claim generation、request OPEN、policy/guard version。
  3. 检查 task 当前 plan、正式合同/审核/输入锁、固定基线证据仍有效。
  4. 检查上游接受可消费、无活动 task attempt、阶段依赖与允许的重试裁决。
  5. 检查独立性证明、全 repo 资源冲突和 request 并发槽。
  6. 以同一观察点检查 request 总预算与 task 子预算，预留所有受控维度。
  7. 原子写 attempt/operation、资源占用、预留、幂等映射和 outbox 事实。
  COMMIT
结果：CLAIMED / RESERVED；不是“进程已经启动”。
```

数据库唯一索引是最后防线，不能替代上面的守卫。可用部分唯一索引对活动状态施加约束；SQLite 官方文档说明了部分索引及唯一性语义。[^W10]

原型中的实际约束示例：

```sql
CREATE UNIQUE INDEX one_active_task
ON operations(request_id, task_id)
WHERE state IN (
  'RESERVED', 'HANDOFF_ACCEPTED', 'RUNNING', 'START_UNKNOWN', 'REVIEW_PENDING'
);
```

`request_id` 在原型账本内全局唯一且绑定 repo；生产若改为局部 ID，必须把 repository namespace 加入相应键与所有外键，不能只改查询条件。

**03/07 分库时的边界**：独立 SQLite 文件、JSON 账本、外部授权服务和 OS 启动不能被一个 Python `with` 自动变成原子事务。优先共享当前守卫与事务接口；无法共享时采用版本化单次许可 + 预留票据 + handoff 再核验 + 补偿记录，明确中间状态和撤销窗口，不能宣称全部跨系统“恰好一次”。

#### 4.3.5 幂等、响应丢失与提交不明

建议幂等范围为 `(repo, request, caller_scope, operation_kind, idempotency_key)`。指纹包括正式输入、expected generation、plan/workflow refs、预留向量和资源集；排除服务器临时生成的 ID/时间。生成指纹的序列化 profile 需登记，不能拼接带歧义的字符串。

| 场景 | 行为 |
|---|---|
| 同键同内容且事务已提交 | 返回原 attempt/operation、当前状态和 `replayed=true`；不新预留、不新启动 |
| 同键不同内容 | `E_IDEMPOTENCY_CONFLICT` |
| 同键首次请求仍在执行事务 | 等待有限锁窗口或返回 `BUSY`；不分配第二次尝试 |
| 提交成功但响应丢失 | 以原键查询；“没收到成功响应”不是重做理由 |
| 提交结果无法判断 | 进入 `COMMIT_UNKNOWN`/恢复流程，先查权威事实 |
| 原 operation 已停止/撤销/过期 | 返回原登记事实，但不得复活启动资格 |
| 新键请求相同活动 task | `E_ACTIVE_TASK`；不能因键不同绕过活动唯一性 |

Python `sqlite3` 的事务控制应显式选定，不依赖跨版本默认行为；参考实现使用 `isolation_level=None` 与显式 BEGIN/COMMIT/ROLLBACK。提交失败后的事务状态必须检查，不能把通用异常捕获等同于“数据库肯定没写入”。[^W11]

#### 4.3.6 Handoff 与 OS 启动之间不承诺天然原子

```text
已领取/预留
  → 03 authorize_transition（固定 action/run/operation，当前审核和权限）
  → 04 固定 Invocation + 05 FinalLaunchPlan
  → handoff 再核验 stop/epoch/锁/预算/进程能力
  → 持久记录 HANDOFF_ACCEPTED，单次消费
  → 05 创建与监督进程
  → STARTED + ProcessIdentity；或 NOT_STARTED 的可靠证据；或 START_UNKNOWN
```

执行器/runner 必须根据相同 `operation_id` 实施受控去重和状态查询。数据库唯一领取只能防重复登记，不能自动阻止另一个入口手工启动同一命令。准备、直接 run、恢复、兼容入口与检查执行入口都要接同一准入路径。

03 的实时撤销与 05 的启动存在平台相关竞态。handoff 已发生后撤销，记录顺序并通知取消；不能承诺撤销后所有在途网络请求均被收回。无法确认启动结果时，禁止盲目重送或把 operation 视为零消耗。[^P03E][^P05E]

#### 4.3.7 租约、心跳、代际和释放条件

租约控制“谁可继续改变调度状态”，不证明旧进程已经死亡。建议记录 owner、controller generation、claim generation、host/boot identity、最近心跳和期限。相同 boot 内可用单调时钟测时；跨重启的单调值不得直接比较，恢复时重新核对。单调时钟没有可移植的业务历元，只适合在正确上下文内计算时间差。[^W12]

与原型字段一致的续租 SQL 示意：

```sql
UPDATE operations
SET lease_until = :new_deadline
WHERE operation_id = :operation_id
  AND owner = :owner
  AND generation = :generation
  AND generation = (SELECT generation FROM controller WHERE singleton = 1)
  AND lease_until > :now
  AND state IN ('RESERVED', 'HANDOFF_ACCEPTED', 'RUNNING');
-- 必须 rowcount=1；new_deadline 要经过上限和不回退校验。
```

| 占用 | 可释放条件 | 不充分的条件 |
|---|---|---|
| 尚未 handoff 的领取与额度 | 持久事实证明未 handoff，旧 owner 已被 fencing，取消事务成功 | 租约超时、某进程查询空结果 |
| 运行并发槽/文件锁 | 05 证明相关受控范围退出与必要清理完成 | 主进程退出 0、收到了 JSON terminal event |
| task 活动尝试槽 | 复审已登记明确结果或按恢复裁决关闭尝试 | 运行结束但 REVIEW_PENDING |
| 未结费用预留 | 有完整、可信、可归属的最终计量或明确风险处置 | attempt 结束、状态显示 CANCELLED |
| 产物保留 pin | 无未完成/复审/下游/历史保留依赖，且符合 GC 策略 | 文件写锁释放 |

超时或强杀后 `scope_empty_verified` 的实际含义由 05 说明；POSIX 不能保证所有逃离进程组的后代都被回收。07 不增强这一底层保证，只传播其限制和恢复阻塞。[^P05]

#### 4.3.8 调度循环、公平性与无进展诊断

建议循环分三步：读取一致状态/处理事实 → 计算候选与分项理由 → 对某一候选尝试短事务领取。不能在持锁事务中轮询进程。

排序建议由受审策略固定为：优先级降序 → 首次进入当前可执行窗口的序号升序 → 稳定 task ID。等待时长不因每次轮询重置；同一 snapshot 产生同一排序。首期并发为 1，逐步开启经证明独立的任务。

资源一次性全取或全不取，按受控稳定键排序；不让任务拿着模块 A 锁无限等待模块 B。预算不足也不能先占住全部文件锁不释放。图无环不代表资源不会死锁；资源等待与 DAG 依赖需要分别报告。

无进展建议诊断 `WAIT_UPSTREAM / WAIT_REVIEW / WAIT_BASELINE / WAIT_RESOURCE / WAIT_BUDGET / RECOVERY_REQUIRED`。不得把“没有可执行节点”直接判断为工作流完成。必要节点未接受时，最终状态应是明确的阻塞/停止/未完成，而不是成功。

#### 4.3.9 执行结束、主模型复审与接受

**原文保留**：attempt 结束先复审；退出码 0 不构成接受。失败归因由主模型负责，执行问题可按裁决返工，合同问题生成新版本；旧 attempt 和审核保留。[^P07]

接受建议事务要求：

1. 当前待复审 attempt 身份、plan、candidate、检查集与实际证据相符。
2. 既有 G0–G6 与独立检查满足原要求；必要事实缺失时不能由一段报告文本代替。
3. 主模型明确的接受裁决经受控入口登记，授权范围正确。
4. 输出产物已封存并符合其类型，具备可核对的 Git 来源。
5. CAS 确认 task 当前复审对象未变化，写不可变 `AcceptedResult`、当前关系、输出绑定与 outbox。

`AcceptedResult` 的候选、检查与 verdict 必须匹配同一对象。它不内嵌自己的哈希，也不自动签发 `baseline-use` 或 `integrate` 权限。费用未结可与业务接受并存，但 request 的未知费用停止条件仍独立生效。

撤销接受时保留原记录，增加当前不可消费关系，按反向依赖找出未运行后继并阻塞；已运行后继保留启动时证据，按主模型决定取消或复审，不能重写历史为“从未接受/从未运行”。

#### 4.3.10 有限重试与合同返工

| 分类 | 默认处置 | 必须重新核验 |
|---|---|---|
| 领取竞争/数据库 BUSY，尚无副作用 | 有限事务重试或返回等待；同幂等键 | 当前 guard、余额、stop、资源 |
| 明确未启动的临时环境故障 | 主模型既有重试裁决允许时新动作 | 环境、权限、次数与预留 |
| 模型执行问题 | 主模型归因后决定返工；新 run/attempt | 相同或新合同是否仍有效，失败遗留副作用 |
| 合同缺陷、基线错误、scope 不足 | 新 plan 与相关审核 | 原合同不能就地修补 |
| 模型失配、越权、核心门禁失败 | 阻塞与复审，不自动换配置绕开 | 相关原因与安全影响 |
| START_UNKNOWN、费用不明、残留身份不明 | 先恢复，不默认重试 | 运行/预算事实、清理/外发状态 |

`max_attempts_total` 建议定义为同一稳定 task 下所有合同版本累计的尝试数；另设 request 级总派遣数。取消前未启动的领取是否占 attempt 数必须锁定；附录原型采用保守方案：已领取就占一次 task 尝试，只有预算预留可因可靠未启动证明释放。

退避策略不能替代主模型裁决。可登记允许的故障集合、最大次数、有效时间、退避上限及禁止自动改变的字段。更换 CLI、角色、模型或工具集合是受审输入变化，不属于普通网络重试。

### 4.4 预算与停止

#### 4.4.1 预算维度、作用域与保证等级

**原文保留**：以 request 累计所有角色和重试；子预算不能绕过全局余量；并行先预留后对账；unknown 不能补零；原始计量以稳定 ID 去重；币种分开；不可硬限金额时如实说明观测预算。[^P07]

| 维度 | 定义建议 | 保证与限制 |
|---|---|---|
| `dispatches` / 受控调用准入数 | 受控边界接纳一次模型 run 记一次；首期从 handoff 记保守值 | 可机械限制本调度器的新准入，不等于远端实际调用次数 |
| `provider_calls` | 可核对的独立供应商模型请求数 | CLI 内部多轮、压缩、辅助模型不可见时为 partial/unknown |
| `attempts_total` | 稳定 task 的累计尝试 | 不因 plan_version/CLI 改变重置 |
| `request_elapsed` | request 开始后到固定截止的历时 | 包含等待/复审；重启不重置截止 |
| `run_elapsed` / `active_runtime_sum` | 单次运行时长、所有运行时长之和 | 并行两次各 10 秒，累计运行量为 20 秒，墙钟可能仅约 10 秒 |
| `concurrency` | 已预留/启动/启动不明的占用数 | 清理未证实前不轻易释放；具体任务/进程槽分开 |
| token 各维度 | 输入/输出/缓存/思考等原始观察 | 依 04 的包含关系，不能把已包含的子项再次相加 |
| `charge[currency]` | 按账户/币种/来源范围可归属的金额 | 供应商未硬限时只是观测和准入预算，不保证最终账单绝不超额 |

“启动一个 CLI”与“产生一个供应商请求”不是同一单位。能够限 CLI 启动次数，不意味着已限制一个 agent 内部自动发起的全部模型调用。生产准入应保存计数覆盖边界；需要硬限制远端调用数量时，必须有已验证的 CLI/网关控制，不能靠运行时长换算。

当前主会话若无法读取实际用量，记录 `unmetered_supervisor` 与 coverage 缺口，不伪造零，也不声称已测出总体成本节省比例。它不免除所有可观测 run 的归集义务。[^P01][^P04]

#### 4.4.2 子预算与总预算：限额不是已拨付额度

建议区分：request 授权总上限、task 局部上限、单次 reservation、运行中的已知消耗、未结敞口。配置 task 上限不等于已把该额度拨给它；实际每次领取必须同时检查 request 和 task。

子预算若采用硬分配模式，分配之和不得超过可分配总额。首期原型采用**局部上限 + 按需预留**：每个 task 的 cap 不高于 request cap，但多个 task cap 的和不表示可同时消费；每次预留仍受全局剩余约束。正式合同需明确采用哪一种模式，不能混用两者的“余量”含义。

planner 尚未生成正式执行合同时，可在该 request 下使用明确的 planning task/scope 记账。图级规划没有具体 task 时使用稳定的 request 级 planning scope；不得为避免 schema 要求而新造另一个预算根。

#### 4.4.3 金额表示与维度隔离

公共金额采用十进制字符串，带明确币种和来源；禁止使用二进制 float 做金额累加。数据库可使用“币种 + 经批准小数精度 + 整数单位”，或者有明确精度/范围的十进制实现。参考原型以 `usd_micro` 等维度演示 6 位小数，**不是所有币种统一规定为 6 位，也不是货币的法定最小单位声明**。

`1.000001` 在 scale=6 时转换为 1,000,001 单位；scale=2 时收到 `0.001` 应拒绝或采用明确的额外精度规则，不静默四舍五入。计数必须排除 bool、负值、不安全大整数；所有求和同样检查溢出。

USD、EUR 等分别累计。换算需要受审汇率来源、时间、方向、舍入与适用对象；没有这些内容就不生成一个看似精确的统一总额。退款/贷项另保留原始事实；是否允许退款恢复可用预算应由策略明确，不自动放大调用额度。

#### 4.4.4 预留与消耗的计算，避免双算

对维度 `d`，定义：

- `K_d`：每个经济调用当前有效观察的已知小计，不含重复镜像或旧修订。
- `H_d`：活动操作的剩余预留。
- `U_d`：已结束但计量未闭合操作的剩余风险预留；它不是已知费用。
- `L_d`：当前授权限额。

```text
每操作初始预留 = R(o,d)
每操作当前已知观察 = A(o,d)；未知时只能为“小计计算”暂不加值，不能认定其费用为 0

如果尚未最终闭合：remaining_hold(o,d) = max(R(o,d) - known(A(o,d)), 0)
如果已可信最终闭合：remaining_hold(o,d) = 0

Exposure_d = K_d + H_d + U_d
raw_remaining_d = L_d - Exposure_d
可新增预留只在 raw_remaining_d >= new_reservation_d 时成立

未知金额没有可靠上界时，即使预留数值为 0，也必须保留 unknown 标识和停止条件。
```

附录原型把 `H+U` 统一显示为 `held`，另用 `unknown_operations` 区分未知结束/启动。不能把 `held` 与 `U` 再次相加。已知小计、预留和覆盖率必须分别展示。

若实际费用大于预留，`K` 仍记录真实值；预留不能作为裁剪账单的上限。`raw_remaining` 允许负数，以说明已经超出；展示用的可用额度可以取 `max(0, raw_remaining)`，但不能隐藏负差额。

#### 4.4.5 并行预留算例（人工合成，不是价格预测）

假设 request 的观测金额上限为 USD 10；A 预留 USD 6，B 预留 USD 4。

| 时点 | 已知小计 K | 活动剩余 H | 未结剩余 U | 敞口 | 行为 |
|---|---:|---:|---:|---:|---|
| A/B 同时获准后 | 0 | 10 | 0 | 10 | 第三次预留无金额余量 |
| A 回报累计 2，尚未最终闭合 | 2 | 8 | 0 | 10 | 不把 2 再加到原始 10 之上 |
| A 最终确认 3，B 仍运行 | 3 | 4 | 0 | 7 | 释放 A 剩余的 3 |
| B 结束但没有费用 | 3 | 0 | 4 | 7 | 默认停止新调用；known subtotal 不是总费用 |
| B 后来确认最终 5 | 8 | 0 | 0 | 8 | 计量闭合，但不自动解除已登记 stop |
| B 再由可信账单更正为 8 | 11 | 0 | 0 | 11 | 保留超额 1，停止并升级，不拒收账单 |

上限为观测金额时，供应商迟报或无法硬限可能导致实际超额。准入预留能防本地并发“重复花同一余额”，不能凭空给远端账单建立硬上限。

#### 4.4.6 稳定调用键、镜像、累计值与更正

建议分三层身份：

| 层次 | 建议键 | 用途 |
|---|---|---|
| 本地调用 | request/run + call_scope + adapter raw anchor | 04 无供应商 ID 时的可追溯临时身份 |
| 经济调用 | provider + 安全账户/endpoint scope + provider request/charge ID | 防同一费用跨 run/角色/摘要重复入账 |
| 观察修订 | 经济调用 + metric + source scope + revision/observation ID | 保留 provisional/final/correction 历史 |

上述键的编码必须版本化、长度有界、无凭据，不拼接有歧义的字段；vendor session ID 常可容纳多次调用，不能单独作费用唯一键。缺稳定 ID 时保留去重置信度与未解决归属，不通过正文相同或金额相同来自动合并两次真实调用。

**消费规则建议**：

| 输入 | 账本动作 |
|---|---|
| 相同 observation ID、相同载荷 | 幂等返回，不增加费用 |
| 相同 ID、不同载荷 | 冲突留证与隔离；不能后写覆盖 |
| 累计 token/费用快照 | 替换该调用的当前观察或按差额更新聚合，不逐条求和 |
| 明确标记的增量 | 按稳定事件 ID 去重后累加；缺口保留 incomplete |
| final 晚于 provisional | 保留两条事实，当前值改为 final，不把两者相加 |
| 较旧修订晚到 | 保存历史，不能覆盖较新的有效当前值 |
| final 后更正/下降 | 有明确可信更正来源与替代关系才变更当前值；原记录保留 |
| CLI estimate + provider charge | 分成不同指标/来源，不作为两笔同类费用相加 |
| summary/status/brief 中重复展示 | 只引用账本观察，不写第二笔费用 |

04 增强版已区分 message 完成观察、镜像摘要、CLI 估算、供应商报告、缓存/思考 token 包含关系；07 的计费消费继续使用其来源信息，不删除来源再重新猜测。[^P04E]

最终账单可能聚合多次请求。无法将账单行精确分配到 call scope 时，不要既加总账单又保留逐调用同类费用重复求和；建立明确覆盖组、分摊策略或待对账差异。跨来源的“优先级”必须按账户/协议版本登记，不能总是假设金额最大的或最新到达的就是最终事实。

附录账本原型只支持**一个 operation/一个维度对应一条受信累计计量序列**，可处理幂等、旧修订、final 和 correction；没有实现生产经济调用 alias 合并、发票分摊、多个隐式供应商调用或价格表。这些必须作为真实接线项目单独验收。

#### 4.4.7 Unknown 与启动不明的默认策略

建议首期采用保守默认：

| 未知状态 | 金额处理 | 后续派遣 |
|---|---|---|
| 正常活动调用暂未回报 | 保留该调用预留，不称已经花费 | 其他调用仅在剩余额度/并发允许时可启动 |
| 已结束但未最终闭合 | 保留未结预留与未知操作数 | 默认阻止新的付费调用，等待对账/明确处置 |
| START_UNKNOWN | 保留调用占用、预留、相关资源与恢复阻塞 | 禁止盲目重试 |
| 无费用能力但该工作已获明确次数/时限授权 | 金额 coverage=unknown；有限调用数等仍执行 | 只有已受审 `bounded_unknown` 策略才允许，不无限继续 |
| 当前 supervisor 费用不可见 | 作为独立不可计量缺口展示 | 不回填零、不假称完整控制主会话成本 |

`bounded_unknown` 应明示最大未结操作数、最大累计受控调用数、时限、估计额度来源、最迟对账时间和超限动作；它是风险接受策略，不是“已精确知道费用”。原型没有该宽松策略，只实现默认停止路径。

#### 4.4.8 预算与真实事实的事务接口

建议业务服务分为：`reserve_for_operation`、`record_usage_observation`、`settle_operation`、`release_proven_unstarted`、`amend_budget_policy`。这些是拟议接口名，不代表现有 CLI 已支持。

`reserve` 与领取同事务；`record_usage` 在接到晚到事实时仍可执行，即使 task 已接受、request 已停止、controller 已换代。计量入口必须验证来源、归属与修订，不以旧 owner 仍持有执行权为前提。

预算更正要同时更新当前计量指针、重算受影响 request/task 投影、追加 outbox，并判断新停止原因。只要实际事实合法，就不能因“会导致预算超限”拒绝它。预算 head 更新则需要主模型/用户现有授权与 CAS；提高、降低、换币种或改变 unknown 策略都生成新策略版本。

降低 cap 至低于已知消耗时，保留负余量和 stop；不删除历史费用。增加 cap 后也不清空已用额度、unknown 或 retry 次数；恢复必须重新检查全部守卫。

#### 4.4.9 停止、取消、收尾和恢复开放

`stop` 首先是持久的“不得再启动新受影响操作”状态。建议原子推进 request 控制代际，记录首因及后续原因，取消未 handoff 的准入。已运行任务依据预先受审策略：

| 策略 | 行为 | 不允许的隐含行为 |
|---|---|---|
| `cancel_running` | 通过 05 请求取消、等待、采集、清理核对 | 直接把 PID kill 成功当所有后代与费用都结束 |
| `drain_current` | 允许当前已准入操作在既定时限/边界内收尾 | 开启下一阶段模型、继续返工或启动新节点 |
| `preserve_for_review` | 封存可得产物、运行状态和缺口，待主模型决定 | 自动接受未验证候选 |

清理、对账与审计查询不应被同一 stop 一刀切断。若某个“收尾”步骤本身会再次调用模型或付费服务，它必须有独立授权及预留，不能借 cleanup 名义绕过额度。可预先划出有限的清理/恢复操作配额，但这不自动允许新的业务执行。

`resume` 建议要求：当前权限有效、request 代际匹配、未知启动和关键账目已解决或风险已明确批准、锁与基线/审核仍有效、额度及并发满足、保留全部历史。仅修改数据库 `stopped=NULL` 不是合规恢复步骤。参考原型故意不实现 `resume` 或任意上调额度的入口。

#### 4.4.10 预算快照与可观测性

状态至少展示：request/task/role 分组的受控调用数、attempt 数、活动数量、各币种已知小计/剩余预留/未知计量覆盖、stop 原因、剩余任务、等待主模型决定、账本高水位和投影滞后。

建议监控指标：`claim_conflict_count`、`dispatch_deduplicated_count`、`start_unknown_count`、`reservation_age_seconds`、`usage_unknown_operations`、`budget_exposure_over_limit`、`outbox_lag`、`review_pending_age`、`reconciliation_mismatch_count`、`resource_hold_without_live_owner`。这些是待实施的指标定义，不是本次真实监控结果。

金额/用量标签不能包含明文账户、凭据或任意用户正文。高基数 run ID 用于事件查询，不建议无界写入所有指标标签。10 的 brief 必须注明游标和 coverage；brief 过期不会改变账本或授权事实。

以下 **30 个场景全部为待执行的生产/真实集成验收**。参考测试可能覆盖类似逻辑，但不能把该结果直接填入本表为 PASS。

### 7.4 结果状态约定

验收使用 `PASS / FAIL / NOT_RUN / BLOCKED / WAIVED`；豁免必须有明确批准人、范围、风险和期限，不能把“没有 Windows 机器”自动算通过。每项绑定代码版本、平台、命令、日志、输入与输出哈希。

原型结果统一标为 `REFERENCE_ONLY`，其中合成裁决使用 `fixture_verdict`，不当成真实主模型认证或 G0–G6 的 PASS。

## 8. 兼容与恢复

### 8.1 原文兼容约束

单任务旧入口继续使用既有流程；新工作流可把正式任务投影成单节点图，但不为旧合同补写虚构 v2 审核。新图和旧 attempt 状态分别保留。工作流变更发布新版本，活动节点继续引用启动时输入，受影响的待运行节点重新审核。[^P07]

回退只切换明确获准的代码/入口路径，不删新账本、不改写历史哈希，不把新版草稿删字段伪装成 v1。冻结的预算根、真实消耗和未知费用必须在回退时继续保留；不能换旧入口就绕过已经生效的 request stop。

### 8.2 崩溃窗口与恢复决策表

| 崩溃位置 | 可能留下的事实 | 恢复动作 | 禁止行为 |
|---|---|---|---|
| 文件封存前 | 临时文件，无正式引用 | 保留诊断，重建新候选 | 把临时文件当批准对象 |
| 资源已封存、领取未提交 | 孤儿资源，无权威 operation | 核验后由原幂等请求继续或回收孤儿 | 文件存在就推断曾获准启动 |
| 领取事务未提交 | 原数据仍有效 | 数据库恢复后重查同键 | 仅凭异常判断此前从未提交 |
| 领取已提交，尚未 handoff | RESERVED、额度与资源占用 | 核验代际/授权；继续原操作或证明未启动后取消 | 新 run 重复预留 |
| handoff 已提交，启动未知 | HANDOFF_ACCEPTED/START_UNKNOWN | 调用 05 状态与身份核对；隔离重复派遣 | 租约到期直接重新启动 |
| 已启动，账本缺 STARTED | OS/日志可能有运行事实 | 比对 operation/run/boot/PID 创建标记/plan | PID 单独匹配就接管或 kill |
| 进程退出，采集/清理未完成 | 主进程退出，EOF/后代未知 | 05 排空和清理；不释放全部占用 | exit 0 自动接受 |
| 候选已封存，verdict 未提交 | 固定 candidate，无接受事实 | 对精确候选复审/补交原幂等裁决 | 自动推断主模型已接受 |
| 接受已提交，outbox 未送出 | 权威接受存在，读模型落后 | 重放相同事件 ID，重建游标 | 再次接受或新记费用 |
| 用量记录已提交，响应丢失 | 唯一 observation 已存在 | 同键返回原结果 | 用同金额另造新 ID 再记账 |
| 图/账本损坏 | 输入/投影不可信 | STOP/RECOVERING，核对证据与高水位 | 用空对象或零余额替代错误 |
| 旧备份恢复 | 可能缺后来撤销、费用与启动记录 | 核对可信高水位和外部事实，未解风险留 unknown | 恢复文件后直接 resume |

### 8.3 操作人员逐步恢复流程

以下是**生产实施后的操作规范**；命名服务接口是拟议能力，不是声称现有命令可直接使用。涉及用户仓库的动作必须受现有维护授权约束。

| 步骤 | 操作 | 成功判据 | 失败升级 |
|---|---|---|---|
| R1 冻结新派遣 | 使用受控 `stop_request/enter_recovery`，记录事故 ID；先阻断新 handoff | request/controller 高水位可读，新准入被拒绝 | 权威账本不可写则隔离调度入口，不继续运行 |
| R2 保全现场 | 保存数据库一致备份、日志尾部、当前 refs、工作目录与进程身份列表 | 原文件未被覆盖；备份来源/时间/完整性可核对 | 不能取一致副本时保持服务冻结，不直接复制活跃主文件冒充完成 |
| R3 核对账本 | 校验数据库结构、外键、当前 heads、幂等记录、活动唯一性 | 无孤立关系与重复活动 scope；或有逐项待决列表 | 发现矛盾进入人工恢复，不自动删除多余行 |
| R4 核对运行 | 对 RESERVED、HANDOFF、START_UNKNOWN、RUNNING 调用 05 查询 | 确认 started true/false/null 和 cleanup 范围 | 身份不明不 kill、不释放、不重复外发 |
| R5 核对预算 | 对比 reservation、原始调用、当前计量、迟到账单与投影游标 | 每笔可归属；未知负债完整保留 | 无法对账就继续停止，不能补 0 |
| R6 核对候选/接受 | 比对固定候选、检查集、verdict、输出、基线授权 | 每个可消费输出都有完整来源链 | 来源缺失由主模型重新复审，不倒推批准 |
| R7 修复/补偿 | 在维护事务下补投影/索引，关闭已证明未启动的占用，追加恢复事实 | 原证据未改写，每个补偿可重放/幂等 | 无法证明的 case 标 START_UNKNOWN/UNRESOLVED |
| R8 重算就绪 | 03 当前校验 + 06 锁 + 07 依赖/预算/冲突 | 所有待运行节点有最新理由和固定绑定 | 有差异则新版本/新审核，不强行沿用 |
| R9 明确恢复 | 主模型按当前授权提交带 expected generation 的 resume | 不重置累计/尝试；只开合法新准入 | 守卫再次变化即拒绝，回到 R8 |

数据库备份建议采用 SQLite 官方备份接口或已验证的一致快照机制；不要只复制正在写入的 `.sqlite` 主文件。WAL 模式时 journal/WAL 与主文件一致性尤其重要。官方备份 API 提供在线一致备份的专门机制，具体文件持久性与断电恢复仍须实际演练。[^W13]

### 8.4 可执行的参考账本检查 SQL

以下 SQL 对应附录原型表名，可在它的测试副本中运行；生产表结构不同则应由实施合同提供对应查询。所有查询都是只读，不能拿结果替代 03 授权和 05 进程事实。

```sql
PRAGMA integrity_check;
PRAGMA foreign_key_check;

-- 同一 task 存在多个活动尝试属于异常；正常应无行。
SELECT request_id, task_id, COUNT(*) AS active_count
FROM operations
WHERE state IN ('RESERVED','HANDOFF_ACCEPTED','RUNNING','START_UNKNOWN','REVIEW_PENDING')
GROUP BY request_id, task_id
HAVING COUNT(*) > 1;

-- 看未解决启动与待复审，不能据此直接终止进程。
SELECT operation_id, request_id, task_id, plan_version, state,
       owner, generation, lease_until
FROM operations
WHERE state IN ('HANDOFF_ACCEPTED','RUNNING','START_UNKNOWN','REVIEW_PENDING')
ORDER BY request_id, task_id, operation_id;

-- 不存在操作的资源占用：正常应无行。
SELECT h.repo_id, h.resource_key, h.operation_id
FROM resource_holds h
LEFT JOIN operations o ON o.operation_id = h.operation_id
WHERE o.operation_id IS NULL;

-- 查看计量历史与当前指针，不能把 observations 所有累计值直接 SUM。
SELECT operation_id, dimension, call_key, revision, amount, is_final
FROM usage_current
ORDER BY operation_id, dimension;

-- 事件高水位仅用于投影重建，不证明外部状态完成。
SELECT MAX(seq) AS outbox_high_water FROM outbox;
```

`integrity_check=ok` 只能说明相应数据库内部完整性检查结果，不能证明备份没有丢失后来已发生的撤销、消费或启动事实。账本恢复高水位与业务事实对账必须另做。

### 8.5 恢复的完成标准

恢复完成至少要求：当前权威版本可核验；无未处置的可能重复启动；未知费用和实际超额完整可见；无隐性重复活动 scope；必要原始证据和引用可读；接受/基线链正确；请求继续运行获得当前准入；10 的状态显示已追上或明确标记滞后。

不能因为表里没有 RUNNING、图上所有节点标终态、或数据库能打开，就宣布所有外部进程、费用和集成动作均已完成。

"""Offline scheduling contracts. This module is NOT an authorization service."""
from __future__ import annotations

import hashlib
import heapq
import json
import re
from pathlib import PurePosixPath
from typing import Any

from jsonschema import Draft202012Validator

MAX_INT = 2**53 - 1
ID = re.compile(r"^[a-z][a-z0-9-]{0,63}$")


class ContractError(ValueError):
    def __init__(self, code: str, location: str = "") -> None:
        self.code, self.location = code, location
        super().__init__(f"{code}: {location}")


def exact_int(value: Any, location: str = "") -> int:
    if type(value) is not int or not 0 <= value <= MAX_INT:
        raise ContractError("E_INTEGER", location)
    return value


def strict_load(raw: bytes, limit: int = 1_048_576) -> Any:
    if not isinstance(raw, bytes) or len(raw) > limit:
        raise ContractError("E_JSON_LIMIT")
    if raw.startswith(b"\xef\xbb\xbf"):
        raise ContractError("E_JSON_BOM")

    def pairs(items: list[tuple[str, Any]]) -> dict[str, Any]:
        result: dict[str, Any] = {}
        for key, value in items:
            if key in result:
                raise ContractError("E_JSON_DUPLICATE_KEY")
            result[key] = value
        return result

    def nonfinite(_: str) -> None:
        raise ContractError("E_JSON_NUMBER")

    try:
        text = raw.decode("utf-8", errors="strict")
        # Bound nesting before recursion; ignore bracket characters inside strings.
        depth, quoted, escaped = 0, False, False
        for char in text:
            if quoted:
                if escaped:
                    escaped = False
                elif char == "\\":
                    escaped = True
                elif char == '"':
                    quoted = False
            elif char == '"':
                quoted = True
            elif char in "[{":
                depth += 1
                if depth > 64:
                    raise ContractError("E_JSON_DEPTH")
            elif char in "]}":
                depth -= 1
        value = json.loads(text, object_pairs_hook=pairs, parse_constant=nonfinite)
        check_json(value)
        return value
    except ContractError:
        raise
    except (UnicodeError, ValueError, RecursionError) as exc:
        raise ContractError("E_JSON_SYNTAX") from exc


def check_json(value: Any) -> None:
    if value is None or type(value) is bool:
        return
    if type(value) is str:
        if any(0xD800 <= ord(c) <= 0xDFFF for c in value):
            raise ContractError("E_JSON_UNICODE")
    elif type(value) is int:
        if not -MAX_INT <= value <= MAX_INT:
            raise ContractError("E_JSON_NUMBER")
    elif type(value) is float:
        # This reference profile has no floating-point fields. Amounts are strings.
        raise ContractError("E_JSON_FLOAT")
    elif type(value) is list:
        for item in value:
            check_json(item)
    elif type(value) is dict:
        for key, item in value.items():
            if type(key) is not str:
                raise ContractError("E_JSON_KEY")
            check_json(key)
            check_json(item)
    else:
        raise ContractError("E_JSON_TYPE")


def canonical(value: Any) -> bytes:
    check_json(value)
    return (json.dumps(value, ensure_ascii=False, sort_keys=True,
                       separators=(",", ":"), allow_nan=False) + "\n").encode("utf-8")


def digest(value: Any) -> str:
    return hashlib.sha256(canonical(value)).hexdigest()


def reference(raw: bytes, kind: str, identity: str, path: str) -> dict[str, str]:
    return {"kind": kind, "id": identity, "sha256": hashlib.sha256(raw).hexdigest(), "path": path}


def ref_type(ref: dict[str, str]) -> tuple[str, str, str]:
    return ref["kind"], ref["id"], ref["sha256"]


def safe_path(value: str) -> tuple[str, ...]:
    if (not value or value.startswith("/") or "\\" in value or ":" in value
            or any(ord(c) < 32 for c in value)):
        raise ContractError("E_PATH")
    parts = value.split("/")
    if any(x in ("", ".", "..") for x in parts):
        raise ContractError("E_PATH")
    # Lexical validation only; the platform resolver still owns symlink/case checks.
    return tuple(PurePosixPath(value).parts)


def path_conflict(a: dict[str, str], b: dict[str, str]) -> bool:
    pa, pb = safe_path(a["path"]), safe_path(b["path"])
    if pa == pb:
        return True
    return ((a["kind"] == "tree" and pb[:len(pa)] == pa)
            or (b["kind"] == "tree" and pa[:len(pb)] == pb))


def topological(items: list[dict[str, Any]], location: str = "nodes") -> list[str]:
    by_id: dict[str, dict[str, Any]] = {}
    for item in items:
        identity = item["id"]
        if identity in by_id:
            raise ContractError("E_DAG_DUPLICATE", f"{location}/{identity}")
        by_id[identity] = item
    indegree = {key: 0 for key in by_id}
    children: dict[str, list[str]] = {key: [] for key in by_id}
    for item in items:
        seen: set[str] = set()
        for dependency in item["depends_on"]:
            if dependency in seen:
                raise ContractError("E_DAG_DUPLICATE_EDGE", item["id"])
            seen.add(dependency)
            if dependency not in by_id:
                raise ContractError("E_DAG_DANGLING", f"{item['id']}<-{dependency}")
            indegree[item["id"]] += 1
            children[dependency].append(item["id"])
    ready = [key for key, count in indegree.items() if count == 0]
    heapq.heapify(ready)
    result: list[str] = []
    while ready:
        key = heapq.heappop(ready)
        result.append(key)
        for child in sorted(children[key]):
            indegree[child] -= 1
            if indegree[child] == 0:
                heapq.heappush(ready, child)
    if len(result) != len(items):
        # These are blocked nodes, not necessarily the minimal cycle witness.
        blocked = sorted(key for key, value in indegree.items() if value)
        raise ContractError("E_DAG_CYCLE", ",".join(blocked))
    return result


def ancestors(items: list[dict[str, Any]]) -> dict[str, set[str]]:
    by_id = {x["id"]: x for x in items}
    result: dict[str, set[str]] = {}
    for key in topological(items):
        result[key] = set()
        for dependency in by_id[key]["depends_on"]:
            result[key].add(dependency)
            result[key].update(result[dependency])
    return result


def validate_workflow(value: dict[str, Any], schema: dict[str, Any]) -> list[str]:
    """Validate the restricted reference profile, not the user's actual contracts."""
    check_json(value)
    errors = sorted(Draft202012Validator(schema).iter_errors(value), key=lambda e: str(e.path))
    if errors:
        raise ContractError("E_SCHEMA", "/".join(map(str, errors[0].path)))
    result = topological(value["nodes"])
    nodes = {node["id"]: node for node in value["nodes"]}
    for node in value["nodes"]:
        if not set(node["input_bindings"]).issubset(node["inputs"]):
            raise ContractError("E_INPUT_UNKNOWN", node["id"])
        for port, spec in node["inputs"].items():
            binding = node["input_bindings"].get(port)
            if binding is None:
                if spec["required"]:
                    raise ContractError("E_INPUT_MISSING", f"{node['id']}/{port}")
                continue
            if binding["kind"] == "task-output":
                parent = binding["task_id"]
                if parent not in node["depends_on"]:
                    raise ContractError("E_INPUT_EDGE", f"{node['id']}/{port}")
                parent_spec = nodes[parent]["outputs"].get(binding["port"])
                if parent_spec is None:
                    raise ContractError("E_OUTPUT_MISSING", f"{parent}/{binding['port']}")
                actual_type = parent_spec["schema_ref"]
            else:
                actual_type = binding["schema_ref"]
            if ref_type(actual_type) != ref_type(spec["schema_ref"]):
                raise ContractError("E_TYPE_UNPROVEN", f"{node['id']}/{port}")
        stages = node["stages"]
        previous = ancestors(stages)
        groups = {kind: [x["id"] for x in stages if x["kind"] == kind]
                  for kind in ("execute", "freeze", "check", "verdict")}
        if not (groups["execute"] and groups["check"] and len(groups["freeze"]) == 1
                and len(groups["verdict"]) == 1):
            raise ContractError("E_STAGE_PROFILE", node["id"])
        freeze, verdict = groups["freeze"][0], groups["verdict"][0]
        if not set(groups["execute"]).issubset(previous[freeze]):
            raise ContractError("E_STAGE_ORDER", freeze)
        for check in groups["check"]:
            if freeze not in previous[check] or check not in previous[verdict]:
                raise ContractError("E_STAGE_ORDER", check)
        for output in node["outputs"].values():
            if output["stage_id"] not in previous:
                raise ContractError("E_OUTPUT_STAGE", node["id"])
        for scope in node["write_scope"]:
            safe_path(scope["path"])
        exact_int(node["retry_policy"]["max_attempts_total"])
    return result


def readiness(facts: dict[str, bool]) -> dict[str, Any]:
    """Facts must be trusted observations. The reference does not obtain or authenticate them."""
    names = ("inputs_accepted", "baseline_present", "baseline_authorized",
             "contract_current", "approval_current", "locks_match", "capabilities_ok",
             "authorization_ok", "budget_ok", "conflicts_clear", "request_open")
    if set(facts) != set(names) or any(type(v) is not bool for v in facts.values()):
        raise ContractError("E_FACT_SHAPE")
    can_refine = all(facts[x] for x in names[:3])
    return {"can_refine": can_refine, "can_execute": all(facts.values()),
            "reasons": ["WAIT_" + key.upper() for key in names if not facts[key]]}


def to_units(amount: str, scale: int) -> int:
    """Exact nonnegative decimal conversion; no float, rounding, exponent or implicit currency."""
    exact_int(scale)
    if scale > 9 or type(amount) is not str or len(amount) > 64 or not re.fullmatch(r"(?:0|[1-9][0-9]*)(?:\.[0-9]+)?", amount):
        raise ContractError("E_AMOUNT")
    whole, _, fraction = amount.partition(".")
    if len(fraction) > scale:
        raise ContractError("E_AMOUNT_PRECISION")
    units = int(whole) * 10**scale + int((fraction + "0" * scale)[:scale] or "0")
    return exact_int(units)


def pointer_get(value: Any, pointer: str) -> Any:
    """RFC 6901 syntax only. Not enabled for workflow bindings in the reference profile."""
    if pointer == "":
        return value
    if not pointer.startswith("/"):
        raise ContractError("E_POINTER")
    for raw in pointer[1:].split("/"):
        if re.search(r"~(?![01])", raw):
            raise ContractError("E_POINTER")
        token = raw.replace("~1", "/").replace("~0", "~")
        if type(value) is dict:
            if token not in value:
                raise ContractError("E_POINTER_MISSING")
            value = value[token]
        elif type(value) is list:
            if not re.fullmatch(r"0|[1-9][0-9]*", token) or int(token) >= len(value):
                raise ContractError("E_POINTER_MISSING")
            value = value[int(token)]
        else:
            raise ContractError("E_POINTER_MISSING")
    return value

"""Single-host SQLite reference ledger using DELETE journal mode.

No OS processes, approvals, live provider calls, full stage scheduler, or recovery
adoption are implemented. Callers in tests supply trusted synthetic observations.
"""
from __future__ import annotations

from contextlib import contextmanager
import json
from pathlib import Path
import re
import sqlite3
import uuid
from typing import Any, Iterator

from workflow_ref import ContractError, canonical, digest, exact_int

DDL = """
PRAGMA foreign_keys=ON;
CREATE TABLE IF NOT EXISTS controller (
    singleton INTEGER PRIMARY KEY CHECK(singleton=1),
    generation INTEGER NOT NULL CHECK(generation>=1)
);
INSERT OR IGNORE INTO controller VALUES(1,1);
CREATE TABLE IF NOT EXISTS requests (
    request_id TEXT PRIMARY KEY,
    repo_id TEXT NOT NULL,
    caps_json TEXT NOT NULL,
    max_concurrency INTEGER NOT NULL CHECK(max_concurrency>0),
    stopped TEXT
);
CREATE TABLE IF NOT EXISTS tasks (
    request_id TEXT NOT NULL REFERENCES requests(request_id),
    task_id TEXT NOT NULL,
    caps_json TEXT NOT NULL,
    max_attempts INTEGER NOT NULL CHECK(max_attempts>0),
    guard_version INTEGER NOT NULL DEFAULT 1,
    fixture_eligible INTEGER NOT NULL DEFAULT 1 CHECK(fixture_eligible IN(0,1)),
    PRIMARY KEY(request_id,task_id)
);
CREATE TABLE IF NOT EXISTS operations (
    operation_id TEXT PRIMARY KEY,
    request_id TEXT NOT NULL,
    task_id TEXT NOT NULL,
    plan_version INTEGER NOT NULL CHECK(plan_version>0),
    guard_version INTEGER NOT NULL,
    idempotency_key TEXT NOT NULL,
    request_digest TEXT NOT NULL,
    owner TEXT NOT NULL,
    generation INTEGER NOT NULL,
    lease_until INTEGER NOT NULL,
    state TEXT NOT NULL CHECK(state IN(
      'RESERVED','HANDOFF_ACCEPTED','RUNNING','START_UNKNOWN','REVIEW_PENDING',
      'ACCEPTED','REJECTED','CANCELLED_NOT_STARTED')),
    reservation_json TEXT NOT NULL,
    candidate_hash TEXT,
    FOREIGN KEY(request_id,task_id) REFERENCES tasks(request_id,task_id),
    UNIQUE(request_id,idempotency_key)
);
CREATE UNIQUE INDEX IF NOT EXISTS one_active_task
ON operations(request_id,task_id)
WHERE state IN('RESERVED','HANDOFF_ACCEPTED','RUNNING','START_UNKNOWN','REVIEW_PENDING');
CREATE TABLE IF NOT EXISTS resource_holds (
    repo_id TEXT NOT NULL,
    resource_key TEXT NOT NULL,
    operation_id TEXT NOT NULL REFERENCES operations(operation_id),
    PRIMARY KEY(repo_id,resource_key)
);
CREATE TABLE IF NOT EXISTS observations (
    observation_id TEXT PRIMARY KEY,
    operation_id TEXT NOT NULL REFERENCES operations(operation_id),
    dimension TEXT NOT NULL,
    call_key TEXT NOT NULL,
    revision INTEGER NOT NULL CHECK(revision>=1),
    amount INTEGER CHECK(amount>=0),
    is_final INTEGER NOT NULL CHECK(is_final IN(0,1)),
    correction INTEGER NOT NULL CHECK(correction IN(0,1)),
    evidence_hash TEXT NOT NULL,
    payload_digest TEXT NOT NULL,
    UNIQUE(call_key,dimension,revision),
    UNIQUE(operation_id,dimension,revision)
);
CREATE TABLE IF NOT EXISTS usage_current (
    operation_id TEXT NOT NULL REFERENCES operations(operation_id),
    dimension TEXT NOT NULL,
    call_key TEXT NOT NULL,
    revision INTEGER NOT NULL,
    amount INTEGER,
    is_final INTEGER NOT NULL,
    PRIMARY KEY(operation_id,dimension),
    UNIQUE(call_key,dimension)
);
CREATE TABLE IF NOT EXISTS outbox (
    seq INTEGER PRIMARY KEY AUTOINCREMENT,
    operation_id TEXT,
    event_type TEXT NOT NULL,
    payload_json TEXT NOT NULL
);
"""
LIVE = ("RESERVED", "HANDOFF_ACCEPTED", "RUNNING", "START_UNKNOWN")
UNRESOLVED = ("START_UNKNOWN", "REVIEW_PENDING", "ACCEPTED", "REJECTED")
HASH = re.compile(r"^[0-9a-f]{64}$")


class Ledger:
    def __init__(self, path: str | Path) -> None:
        self.db = sqlite3.connect(str(path), isolation_level=None, timeout=5.0)
        self.db.row_factory = sqlite3.Row
        self.db.execute("PRAGMA foreign_keys=ON")
        self.db.execute("PRAGMA synchronous=FULL")
        self.db.execute("PRAGMA busy_timeout=5000")
        # Initialization is separate from business transactions. No WAL claim is made.
        mode = self.db.execute("PRAGMA journal_mode").fetchone()[0]
        if mode not in ("delete", "memory"):
            self.db.close()
            raise ContractError("E_DB_MODE", mode)
        self.db.executescript(DDL)

    def close(self) -> None:
        self.db.close()

    @contextmanager
    def tx(self) -> Iterator[None]:
        self.db.execute("BEGIN IMMEDIATE")
        try:
            yield
            self.db.execute("COMMIT")
        except BaseException:
            if self.db.in_transaction:
                self.db.execute("ROLLBACK")
            raise

    def _emit(self, operation: str | None, kind: str, payload: Any) -> None:
        self.db.execute("INSERT INTO outbox(operation_id,event_type,payload_json) VALUES(?,?,?)",
                        (operation, kind, canonical(payload).decode()))

    def generation(self) -> int:
        return self.db.execute("SELECT generation FROM controller").fetchone()[0]

    def _epoch(self, expected: int) -> None:
        if exact_int(expected) != self.generation():
            raise ContractError("E_FENCED")

    def _operation(self, operation: str) -> sqlite3.Row:
        row = self.db.execute("SELECT * FROM operations WHERE operation_id=?", (operation,)).fetchone()
        if row is None:
            raise ContractError("E_OPERATION_UNKNOWN")
        return row

    def _owned(self, operation: str, owner: str, generation: int) -> sqlite3.Row:
        self._epoch(generation)
        row = self._operation(operation)
        if row["owner"] != owner or row["generation"] != generation:
            raise ContractError("E_FENCED")
        return row

    @staticmethod
    def _caps(caps: dict[str, int]) -> None:
        if type(caps) is not dict or "dispatches" not in caps or not caps:
            raise ContractError("E_BUDGET_SHAPE")
        for key, value in caps.items():
            if not re.fullmatch(r"[a-z][a-z0-9_-]{0,63}", key):
                raise ContractError("E_BUDGET_DIMENSION")
            exact_int(value)

    def seed_request(self, request: str, repo: str, caps: dict[str, int], concurrency: int = 2) -> None:
        self._caps(caps)
        if not exact_int(concurrency):
            raise ContractError("E_CONCURRENCY")
        with self.tx():
            self.db.execute("INSERT INTO requests VALUES(?,?,?,?,NULL)",
                            (request, repo, canonical(caps).decode(), concurrency))

    def seed_task(self, request: str, task: str, caps: dict[str, int], max_attempts: int = 3) -> None:
        self._caps(caps)
        if not exact_int(max_attempts):
            raise ContractError("E_ATTEMPTS")
        root = self.db.execute("SELECT caps_json FROM requests WHERE request_id=?", (request,)).fetchone()
        if root is None:
            raise ContractError("E_REQUEST_UNKNOWN")
        root_caps = json.loads(root[0])
        if set(caps) != set(root_caps) or any(caps[k] > root_caps[k] for k in caps):
            raise ContractError("E_SUBBUDGET")
        with self.tx():
            self.db.execute("INSERT INTO tasks(request_id,task_id,caps_json,max_attempts) VALUES(?,?,?,?)",
                            (request, task, canonical(caps).decode(), max_attempts))

    def _snapshot(self, request: str, task: str | None = None) -> dict[str, Any]:
        if task is None:
            row = self.db.execute("SELECT caps_json FROM requests WHERE request_id=?", (request,)).fetchone()
        else:
            row = self.db.execute("SELECT caps_json FROM tasks WHERE request_id=? AND task_id=?",
                                  (request, task)).fetchone()
        if row is None:
            raise ContractError("E_SCOPE_UNKNOWN")
        caps = json.loads(row[0])
        totals = {d: {"limit": cap, "known": 0, "held": 0, "unknown_operations": 0}
                  for d, cap in caps.items()}
        sql = "SELECT * FROM operations WHERE request_id=? AND state!='CANCELLED_NOT_STARTED'"
        params: tuple[Any, ...] = (request,)
        if task is not None:
            sql += " AND task_id=?"
            params += (task,)
        for op in self.db.execute(sql, params).fetchall():
            reserve = json.loads(op["reservation_json"])
            current = {x["dimension"]: x for x in self.db.execute(
                "SELECT * FROM usage_current WHERE operation_id=?", (op["operation_id"],)).fetchall()}
            for dimension, reserved in reserve.items():
                observation = current.get(dimension)
                known = observation["amount"] if observation is not None and observation["amount"] is not None else 0
                complete = observation is not None and observation["amount"] is not None and observation["is_final"] == 1
                hold = 0 if complete else max(reserved - known, 0)
                total = totals[dimension]
                total["known"] += known
                total["held"] += hold
                if not complete and op["state"] in UNRESOLVED:
                    total["unknown_operations"] += 1
        for total in totals.values():
            total["exposure"] = exact_int(total["known"] + total["held"])
        return totals

    def snapshot(self, request: str, task: str | None = None) -> dict[str, Any]:
        # One read snapshot for all component SELECTs. Not a writable business transaction.
        self.db.execute("BEGIN")
        try:
            result = self._snapshot(request, task)
            self.db.execute("COMMIT")
            return result
        except BaseException:
            if self.db.in_transaction:
                self.db.execute("ROLLBACK")
            raise

    def claim(self, request: str, task: str, plan: int, key: str, owner: str,
              generation: int, guard_version: int, reservation: dict[str, int],
              resource_keys: list[str], now: int = 0, lease: int = 30,
              fail_before_commit: bool = False) -> dict[str, Any]:
        self._caps(reservation)
        for x in (plan, guard_version, generation, now, lease):
            exact_int(x)
        if not plan or not guard_version or not lease or reservation["dispatches"] != 1:
            raise ContractError("E_CLAIM_SHAPE")
        if (type(resource_keys) is not list or len(set(resource_keys)) != len(resource_keys)
                or any(type(k) is not str or not k or len(k) > 200 for k in resource_keys)):
            raise ContractError("E_RESOURCE_KEYS")
        intent = {"request": request, "task": task, "plan": plan, "owner": owner,
                  "generation": generation, "guard": guard_version, "reservation": reservation,
                  "resources": sorted(resource_keys), "lease": lease}
        fingerprint = digest(intent)  # now is observation time, not a new logical request.
        with self.tx():
            old = self.db.execute("SELECT * FROM operations WHERE request_id=? AND idempotency_key=?",
                                  (request, key)).fetchone()
            if old:
                if old["request_digest"] != fingerprint:
                    raise ContractError("E_IDEMPOTENCY_CONFLICT")
                return {"operation_id": old["operation_id"], "state": old["state"], "replayed": True}
            self._epoch(generation)
            root = self.db.execute("SELECT * FROM requests WHERE request_id=?", (request,)).fetchone()
            item = self.db.execute("SELECT * FROM tasks WHERE request_id=? AND task_id=?", (request, task)).fetchone()
            if root is None or item is None:
                raise ContractError("E_SCOPE_UNKNOWN")
            if root["stopped"]:
                raise ContractError("E_STOPPED")
            if item["guard_version"] != guard_version or item["fixture_eligible"] != 1:
                raise ContractError("E_GUARD_STALE")
            active_task = self.db.execute(
                "SELECT 1 FROM operations WHERE request_id=? AND task_id=? AND state IN (?,?,?,?,?)",
                (request, task, *LIVE, "REVIEW_PENDING")).fetchone()
            if active_task:
                raise ContractError("E_ACTIVE_TASK")
            attempts = self.db.execute("SELECT COUNT(*) FROM operations WHERE request_id=? AND task_id=?",
                                       (request, task)).fetchone()[0]
            if attempts >= item["max_attempts"]:
                raise ContractError("E_ATTEMPTS")
            active = self.db.execute("SELECT COUNT(*) FROM operations WHERE request_id=? AND state IN (?,?,?,?)",
                                     (request, *LIVE)).fetchone()[0]
            if active >= root["max_concurrency"]:
                raise ContractError("E_CONCURRENCY")
            for scope in (None, task):
                totals = self._snapshot(request, scope)
                if set(reservation) != set(totals):
                    raise ContractError("E_BUDGET_DIMENSION")
                if any(t["unknown_operations"] for t in totals.values()):
                    raise ContractError("E_USAGE_UNKNOWN")
                if any(t["exposure"] + reservation[d] > t["limit"] for d, t in totals.items()):
                    raise ContractError("E_BUDGET_INSUFFICIENT")
            for resource in resource_keys:
                conflict = self.db.execute("SELECT 1 FROM resource_holds WHERE repo_id=? AND resource_key=?",
                                           (root["repo_id"], resource)).fetchone()
                if conflict:
                    raise ContractError("E_RESOURCE_BUSY")
            operation = "op-" + uuid.uuid4().hex
            try:
                self.db.execute("""INSERT INTO operations VALUES(?,?,?,?,?,?,?,?,?,?,?,?,NULL)""",
                                (operation, request, task, plan, guard_version, key, fingerprint, owner, generation,
                                 exact_int(now + lease), "RESERVED", canonical(reservation).decode()))
            except sqlite3.IntegrityError as exc:
                # This prototype intentionally does not return another key's attempt as a successful claim.
                raise ContractError("E_ACTIVE_TASK") from exc
            for resource in sorted(resource_keys):
                self.db.execute("INSERT INTO resource_holds VALUES(?,?,?)", (root["repo_id"], resource, operation))
            self._emit(operation, "scheduler.claimed", intent)
            if fail_before_commit:
                raise ContractError("E_SYNTHETIC_FAILPOINT")
            return {"operation_id": operation, "state": "RESERVED", "replayed": False}

    def _insert_observation(self, operation: str, dimension: str, call_key: str, revision: int,
                            amount: int | None, final: bool, evidence_hash: str,
                            correction: bool = False) -> str:
        exact_int(revision)
        if not revision or type(final) is not bool or type(correction) is not bool or not HASH.fullmatch(evidence_hash):
            raise ContractError("E_OBSERVATION_SHAPE")
        if amount is not None:
            exact_int(amount)
        if final and amount is None:
            raise ContractError("E_UNKNOWN_FINAL")
        op = self._operation(operation)
        if op["state"] == "CANCELLED_NOT_STARTED" or dimension not in json.loads(op["reservation_json"]):
            raise ContractError("E_OBSERVATION_SCOPE")
        payload = {"operation": operation, "dimension": dimension, "call": call_key, "revision": revision,
                   "amount": amount, "final": final, "correction": correction, "evidence": evidence_hash}
        fingerprint = digest(payload)
        observation_id = digest({"call": call_key, "dimension": dimension, "revision": revision})
        duplicate = self.db.execute("SELECT payload_digest FROM observations WHERE observation_id=?", (observation_id,)).fetchone()
        if duplicate:
            if duplicate[0] != fingerprint:
                raise ContractError("E_USAGE_CONFLICT")
            return "REPLAY"
        existing_call = self.db.execute("SELECT * FROM usage_current WHERE call_key=? AND dimension=?",
                                        (call_key, dimension)).fetchone()
        if existing_call is not None and existing_call["operation_id"] != operation:
            raise ContractError("E_USAGE_SCOPE")
        current = self.db.execute("SELECT * FROM usage_current WHERE operation_id=? AND dimension=?",
                                  (operation, dimension)).fetchone()
        if current is not None and current["call_key"] != call_key:
            raise ContractError("E_USAGE_KEY")
        newer = current is None or revision > current["revision"]
        if newer and current is not None:
            regression = current["amount"] is not None and (amount is None or amount < current["amount"])
            changed_final = current["is_final"] == 1 and (amount != current["amount"] or not final)
            if (regression or changed_final) and not correction:
                raise ContractError("E_USAGE_CORRECTION_REQUIRED")
        self.db.execute("INSERT INTO observations VALUES(?,?,?,?,?,?,?,?,?,?)",
                        (observation_id, operation, dimension, call_key, revision, amount, int(final),
                         int(correction), evidence_hash, fingerprint))
        if newer:
            self.db.execute("""INSERT INTO usage_current VALUES(?,?,?,?,?,?)
                ON CONFLICT(operation_id,dimension) DO UPDATE SET
                revision=excluded.revision,amount=excluded.amount,is_final=excluded.is_final""",
                            (operation, dimension, call_key, revision, amount, int(final)))
        self._emit(operation, "usage.observed", payload)
        return "APPLIED" if newer else "HISTORICAL_ONLY"

    def _enforce(self, request: str, task: str) -> None:
        reason = None
        for scope in (None, task):
            totals = self._snapshot(request, scope)
            if any(t["exposure"] > t["limit"] for t in totals.values()):
                reason = "BUDGET_EXCEEDED"
                break
            if any(t["unknown_operations"] for t in totals.values()):
                reason = "USAGE_UNKNOWN"
        if reason:
            # Preserve the first stop cause. All subsequent causes remain in outbox facts.
            self.db.execute("UPDATE requests SET stopped=COALESCE(stopped,?) WHERE request_id=?", (reason, request))
            self._emit(None, "request.stop_observed", {"request_id": request, "reason": reason})

    def handoff(self, operation: str, owner: str, generation: int, now: int = 0) -> None:
        exact_int(now)
        with self.tx():
            op = self._owned(operation, owner, generation)
            if op["state"] != "RESERVED" or now >= op["lease_until"]:
                raise ContractError("E_HANDOFF_STATE")
            stopped = self.db.execute("SELECT stopped FROM requests WHERE request_id=?", (op["request_id"],)).fetchone()[0]
            if stopped:
                raise ContractError("E_STOPPED")
            guard = self.db.execute("SELECT guard_version,fixture_eligible FROM tasks WHERE request_id=? AND task_id=?",
                                    (op["request_id"], op["task_id"])).fetchone()
            if guard is None or guard["guard_version"] != op["guard_version"] or guard["fixture_eligible"] != 1:
                raise ContractError("E_GUARD_STALE")
            for scope in (None, op["task_id"]):
                totals = self._snapshot(op["request_id"], scope)
                if any(t["unknown_operations"] or t["exposure"] > t["limit"] for t in totals.values()):
                    raise ContractError("E_BUDGET_GUARD")
            self.db.execute("UPDATE operations SET state='HANDOFF_ACCEPTED' WHERE operation_id=?", (operation,))
            self._insert_observation(operation, "dispatches", "local:" + operation, 1, 1, True, digest({"fixture": "local-handoff", "operation": operation}))
            self._emit(operation, "scheduler.handoff_accepted", {"generation": generation})

    def mark_running(self, operation: str, owner: str, generation: int) -> None:
        with self.tx():
            op = self._owned(operation, owner, generation)
            if op["state"] != "HANDOFF_ACCEPTED":
                raise ContractError("E_START_STATE")
            self.db.execute("UPDATE operations SET state='RUNNING' WHERE operation_id=?", (operation,))
            self._emit(operation, "fixture.started", {})

    def renew(self, operation: str, owner: str, generation: int, now: int, extension: int) -> None:
        exact_int(now)
        if not exact_int(extension):
            raise ContractError("E_LEASE")
        with self.tx():
            op = self._owned(operation, owner, generation)
            if op["state"] not in LIVE[:-1] or now >= op["lease_until"]:
                raise ContractError("E_LEASE")
            self.db.execute("UPDATE operations SET lease_until=? WHERE operation_id=?",
                            (max(op["lease_until"], exact_int(now + extension)), operation))

    def observe(self, operation: str, dimension: str, call_key: str, revision: int,
                amount: int | None, final: bool, evidence_hash: str,
                correction: bool = False) -> str:
        # Evidence ingestion remains available after cancellation/stop/generation changes.
        if dimension == "dispatches":
            raise ContractError("E_LOCAL_METRIC_RESERVED")
        with self.tx():
            status = self._insert_observation(operation, dimension, call_key, revision, amount, final,
                                               evidence_hash, correction)
            op = self._operation(operation)
            self._enforce(op["request_id"], op["task_id"])
            return status

    def finish(self, operation: str, owner: str, generation: int, candidate_hash: str,
               cleanup_verified: bool) -> None:
        if not HASH.fullmatch(candidate_hash) or cleanup_verified is not True:
            raise ContractError("E_CLEANUP_OR_CANDIDATE")
        with self.tx():
            op = self._owned(operation, owner, generation)
            if op["state"] != "RUNNING":
                raise ContractError("E_FINISH_STATE")
            self.db.execute("UPDATE operations SET state='REVIEW_PENDING',candidate_hash=? WHERE operation_id=?",
                            (candidate_hash, operation))
            self.db.execute("DELETE FROM resource_holds WHERE operation_id=?", (operation,))
            self._emit(operation, "fixture.finished_for_review", {"candidate": candidate_hash})
            self._enforce(op["request_id"], op["task_id"])

    def fixture_verdict(self, operation: str, candidate_hash: str, accepted: bool,
                        evidence_hash: str) -> None:
        """Synthetic verdict injection only; real identity/G0-G6 checks are NOT implemented."""
        if type(accepted) is not bool or not HASH.fullmatch(evidence_hash):
            raise ContractError("E_VERDICT_SHAPE")
        with self.tx():
            op = self._operation(operation)
            if op["state"] != "REVIEW_PENDING" or candidate_hash != op["candidate_hash"]:
                raise ContractError("E_VERDICT_CANDIDATE")
            state = "ACCEPTED" if accepted else "REJECTED"
            self.db.execute("UPDATE operations SET state=? WHERE operation_id=?", (state, operation))
            self._emit(operation, "fixture.verdict", {"state": state, "evidence": evidence_hash})

    def unknown(self, operation: str, owner: str, generation: int) -> None:
        with self.tx():
            op = self._owned(operation, owner, generation)
            if op["state"] not in ("HANDOFF_ACCEPTED", "RUNNING"):
                raise ContractError("E_UNKNOWN_STATE")
            self.db.execute("UPDATE operations SET state='START_UNKNOWN' WHERE operation_id=?", (operation,))
            self.db.execute("UPDATE requests SET stopped=COALESCE(stopped,'START_UNKNOWN') WHERE request_id=?",
                            (op["request_id"],))
            self._emit(operation, "scheduler.start_unknown", {})

    def cancel_unstarted(self, operation: str, generation: int) -> None:
        with self.tx():
            self._epoch(generation)
            op = self._operation(operation)
            if op["state"] != "RESERVED":
                raise ContractError("E_CANNOT_PROVE_UNSTARTED")
            if self.db.execute("SELECT 1 FROM observations WHERE operation_id=?", (operation,)).fetchone():
                raise ContractError("E_UNSTARTED_EVIDENCE_CONFLICT")
            self.db.execute("UPDATE operations SET state='CANCELLED_NOT_STARTED' WHERE operation_id=?", (operation,))
            self.db.execute("DELETE FROM resource_holds WHERE operation_id=?", (operation,))
            self._emit(operation, "scheduler.cancelled_before_handoff", {})

    def stop(self, request: str, reason: str = "OPERATOR_STOP") -> None:
        with self.tx():
            cur = self.db.execute("UPDATE requests SET stopped=COALESCE(stopped,?) WHERE request_id=?", (reason, request))
            if cur.rowcount != 1:
                raise ContractError("E_REQUEST_UNKNOWN")
            self._emit(None, "request.stopped", {"request_id": request, "reason": reason})

    def rollover(self) -> int:
        with self.tx():
            self.db.execute("UPDATE controller SET generation=generation+1")
            self.db.execute("UPDATE requests SET stopped=COALESCE(stopped,'RECOVERY_REQUIRED')")
            generation = self.generation()
            self._emit(None, "controller.fenced", {"generation": generation})
            return generation

"""Extract the named artifact blocks from this document; does not run extracted code."""
from __future__ import annotations
import argparse
from pathlib import Path
import re

PATTERN = re.compile(
    r'^<!-- artifact-file: (?P<name>[^\r\n]+) -->\n'
    r'(?P<fence>`{3,}|~{3,})[^\r\n]*\n(?P<body>.*?)^(?P=fence)[ \t]*$',
    re.MULTILINE | re.DOTALL,
)


def extract(document: Path, destination: Path) -> list[str]:
    if destination.exists() and any(destination.iterdir()):
        raise ValueError('Destination must be absent or empty; no overwrite is allowed.')
    text = document.read_bytes().decode('utf-8')
    files: dict[str, bytes] = {}
    for match in PATTERN.finditer(text):
        name = match.group('name')
        if ('\\' in name or ':' in name or name.startswith('/')
                or any(part in ('', '.', '..') for part in name.split('/'))):
            raise ValueError('Unsafe artifact path')
        if name in files:
            raise ValueError('Duplicate artifact path')
        files[name] = match.group('body').encode('utf-8')
    if not files:
        raise ValueError('No named artifact blocks were found')
    destination.mkdir(parents=True, exist_ok=True)
    for name, raw in files.items():
        target = destination / name
        target.parent.mkdir(parents=True, exist_ok=True)
        target.write_bytes(raw)
    return sorted(files)


def main() -> int:
    parser = argparse.ArgumentParser(description=__doc__)
    parser.add_argument('document', type=Path)
    parser.add_argument('destination', type=Path)
    args = parser.parse_args()
    files = extract(args.document, args.destination)
    print(f'Extracted {len(files)} files')
    return 0


if __name__ == '__main__':
    raise SystemExit(main())
