## 0. 审阅结论与采用规则

### 0.1 原文已经建立的正确边界

原文的重点不是“允许任意切换模型”，而是把 **CLI 的运行方式、模型/profile、角色职责** 分开，同时保留独立的允许列表、环境过滤、worktree 和保护路径规则。配置不能授权自己，角色选择不能扩大权限，主会话监督不能被解释为配置已改变当前会话模型。[^P02]

原文还明确要求：本机文件只能覆盖白名单中的路径；临时参数只能选择已存在 profile；语义快照与机器环境分离；正式合同不得重新跟随同名 profile；v1 兼容必须显式；迁移只能先产出待审建议。上述要求在本版中全部保留。[^P02]

### 0.2 需要补齐的实施缺口

| 编号 | 原文已有要求 | 本版新增细化 | 不补齐的风险 |
|---|---|---|---|
| R02-01 | 配置分层 | 字段类型、必填性、空值、默认值、角色组合、命名规则 | 不同入口各自解释配置 |
| R02-02 | 按层解析 | 将处理顺序与覆盖权限分开；给出确定性流水线 | “后读优先”变成任意深层覆盖 |
| R02-03 | 只允许本机路径覆盖 | 精确可写字段与替换粒度，禁止修改参数尾部 | 路径配置夹带模型、endpoint 或权限选项 |
| R02-04 | adapter 注入 Schema | 核心与扩展字段的封闭边界、离线引用、描述符绑定 | 验证一个 Schema，却用另一个适配器执行 |

| R02-08 | 锁定 profile | 已固定字节、当前撤销检查、启动前交接约束 | 同名 profile、缓存或旧权限复活 |

## 1. 目标与非目标

### 1.1 目标（保留原文并细化）

本模块建立以下明确关系：

```text
role（此次承担什么职责）
  → profile（使用哪组固定模型与适配器选项）
    → runtime（由哪个已登记 adapter 解释，使用何种命令模板）
      → environment（本机解析出的入口、工具、版本及指纹）

独立策略贯穿以上关系；不由任意一层自行授予权限。
```

同一个任务可以由不同 runtime/profile 承担规划与执行；同一个 profile 可以被多个获准角色引用。解析结果应可解释、可固定为资源、可追溯到输入，并可在不启动模型的情况下完成结构与语义检查。

**完成 02 的定义**：能够可靠产出“尚未获准执行的有效配置候选”、语义快照候选、环境预检需求和结构化诊断，并通过静态 adapter fixture 独立验收。完成 02 不要求 04 的真实 CLI 接线已完成。[^P02]

### 1.2 非目标（原文保留）

不实现 CLI 协议、不加载插件、不编排项目工作流；分别交给 04、06、07。不自动挑选模型、不安装 CLI、不登录或迁移凭据、不把示例写成当前运行配置。不改变现有允许列表、环境过滤、worktree、受保护路径和 Step/high 选择。

`supervisor.mode = current_session` 只登记监督来源，不启动一个新的 supervisor CLI，也不宣称修改了当前主会话的模型、系统指令、工具权限或费用归属。

### 1.3 必须保持的安全不变量（新增建议）

| 不变量 | 实施含义 |
|---|---|
| I02-01 配置不授权自己 | 项目文件、local 文件和 CLI 选择均不能放宽独立策略 |
| I02-02 不隐式选择模型 | 无 profile、无 model、未知模型或未知 adapter 时拒绝，不找替代模型 |
| I02-03 一个语义快照对应一组固定行为输入 | 模型、选项、参数尾部、角色、能力契约或相关策略变化必须可检测 |
| I02-04 同一 locator 不代表同一入口 | 本机路径变化或入口内容变化都须由环境预检识别 |
| I02-05 解析成功不等于启动许可 | 02 的成功结果不得包含可直接当作授权使用的布尔值 |
| I02-06 说明不参与执行 | 只有经过验证和规范化的对象可交给下游，不再读取原始说明字段 |
| I02-07 旧锁不冻结撤销 | 当前安全策略或授权撤销仍可阻止使用历史配置 |
| I02-08 证据不被迁移改写 | v1 attempt、旧合同、审核记录和历史哈希保持原解释 |

## 2. 依赖与输入输出

### 2.1 输入契约

| 输入 | 提供方/来源 | 02 的检查 | 不允许的替代 |
|---|---|---|---|
| 项目配置字节 | 受控读取 `.agent/dispatch.config.json` | 编码、重复键、版本、结构、引用 | 用空对象代替读取失败 |
| local 配置字节或明确缺失 | `.agent/dispatch.local.json` | 版本、字段白名单、覆盖目标、路径词法 | 任意 deep merge；忽略“存在但无权读取” |
| 角色范围与 profile 选择 | 明确调用参数 | 只选已声明角色/profile；拒绝重复/冲突参数 | CLI 临时提供 model/provider/thinking |
| 目标平台 | 05 的规范化平台结果或离线 fixture | 只接受 `linux`、`macos`、`windows` | 从机器路径、文件后缀或 `os.name` 猜平台 |
| adapter 描述符注册表 | 受信注入；真实接线归 04 | ID、Schema、能力契约及依赖身份一致 | 项目配置指定可执行 Python 类或下载 Schema URL |
| 现有独立策略视图 | 现有策略入口/受信封装 | 保留旧允许列表、环境、worktree 与保护规则 | 用新 `policies` 取代旧策略 |
| 01 公共协议实现 | 01 已确认版本或静态 fixture | ResourceRef、序列化、错误家族 | 另写不兼容的“近似相等”哈希 |
| v1 基线 fixtures | 01 的取证结果 | 显式旧分支回归 | 猜测真实 Pi 输出或旧默认值 |

`request_id`、`task_id`、`plan_version`、`run_id` 属于任务/合同/调用上下文，不是配置 ID；不能用 `planner` 或 `executor` 替代。配置快照通常不应包含每次调用的 `run_id`、时间戳或机器名，否则相同语义无法复用。[^P01][^P02]

### 2.2 输出与状态分离

| 输出 | 最低内容 | 能证明什么 | 不能证明什么 |
|---|---|---|---|
| `EffectiveConfig` | 所选角色、profile、模型、选项、runtime、策略依赖 | 静态解析得到确定结果 | 入口可用、运行获准 |
| `ConfigSemanticSnapshot` | 有效配置的确定性语义投影 | 被审核的配置内容是什么 | 机器路径对应可信程序 |
| `EnvironmentPlan` | 待解析的入口/工具 locator 与待检查清单 | 后续预检需要什么 | 真实 CLI 版本、指纹、模型或认证状态 |
| `EnvironmentRecord` | 实测路径、版本、指纹、能力与认证绑定证据 | 此次预检观察到的环境 | 永久有效或自动获得审核 |
| `ProvenanceReport` | 字段来源、覆盖链、适用分支和默认来源 | 结果为什么如此 | 原始配置可以无脱敏公开 |
| `DependencyManifest` | 所选依赖闭包、Schema/策略版本、源证据引用 | 哪些变更需要重新评估 | 一切未列明依赖都一定无关 |
| `Diagnostics` | 稳定 code、字段路径、来源、修复方向 | 哪个阶段拒绝以及如何修复 | 可以通过自动重试换模型解决 |

其中 `EnvironmentRecord` 的具体取得和环境锁发布由 04/05 与 03 配合；02 可以定义消费接口和 fixture，但不能假造实测值。

建议解析状态为：

```text
UNREAD → PARSED → STRUCTURE_VALID → RESOLVED → SEMANTICS_VALID
       → SNAPSHOT_CANDIDATE → SNAPSHOT_PUBLISHED → HANDOFF_TO_03

任一阶段失败 → REJECTED（保留安全诊断；不产生新的进程启动）
```

成功返回建议使用 `status = RESOLVED_UNAPPROVED`。参考实现固定 `launchable = false`；该字段只防止误用，正式系统仍应通过类型/接口隔离避免把解析结果传入启动授权接口。

### 2.3 版本轴

| 版本轴 | 示例 | 改变的对象 |
|---|---|---|
| 项目配置 Schema | `schema_version: 2` | `.agent/dispatch.config.json` 字段合同 |
| local Schema | 本建议也为 `2` | 仅本机覆盖文件的字段合同 |
| 语义快照 Schema | 建议 `schema_version: 1` | 核心生成的新资源形状，不等于配置版本 |
| 投影规则 | `config-projection-1` | 默认展开、字段分类、集合排序等行为 |
| adapter 描述符版本/摘要 | 独立值 | 模型 Schema、选项、能力、参数合同 |
| 环境记录 Schema | 独立版本 | 机器预检与指纹事实 |
| 合同/审核 Schema | 由 01/03 确定 | 任务授权记录 |
| 工具软件版本 | 原文提及的现有工具版本轴 | 实现包/调度器自身 |

版本同为数字 `2` 不意味着这些协议是同一个协议。读取器只按资源家族和已支持版本分派。

### 3.2 推荐的职责拆分

`config.py` 应以纯函数和不可变输入为中心，负责结构、选择、投影和诊断；现有策略应通过窄接口注入，不复制一套“简化安全策略”。文件读取、环境探测、adapter 加载、资源发布、审核和启动分别保留在各自负责模块。

初期允许一个兼容 facade 调用旧函数，但不允许 v2 校验失败后调用旧模型解析作为补救。兼容 facade 必须先确定分支，再执行该分支，不在异常处理里重新决定版本。

### 3.3 缺少的基线不应被新增 Schema 掩盖

原文没有列出全部旧配置字段、旧环境变量名称、`allowed_executors` 的精确键结构及 Step/high 的配置来源。迁移前应形成逐字段映射表，未确认项记为 `UNKNOWN_BASELINE`，而不是把它们当作可以删除的遗留噪声。

## 4. 接口和行为约束

### 4.1 配置层次

#### 4.1.1 文件位置与配置发现

**原文保留**：项目配置沿用 `.agent/dispatch.config.json`；v2 显式声明 `schema_version: 2`。新增 `.agent/dispatch.local.json` 只保存本机路径覆盖，并在获准实施时加入忽略规则。[^P02]

**新增建议**：仓库根由受信上下文提供，不由模型输出任意路径决定；默认只读取这两个明确位置，不自动向父目录寻找“另一个可用配置”，不自动读取 `.env`、个人全局配置或网络配置。允许自定义入口时，也须在正式合同与受控读取器中登记。

缺失 local 文件是一个明确的合法状态；local 文件存在但不可读、解析失败、越界或类型不符时必须报错。不能把这些情况都折叠成“无覆盖”。

忽略规则不能使已经被 Git 跟踪的文件自动停止跟踪；迁移时应先检查是否已入库，不能仅添加 `.gitignore` 后就宣称机器路径或秘密已从历史中清除。[^R07]

#### 4.1.2 顶层字段建议

| 字段 | 类型/必填 | 规则 | 默认行为 |
|---|---|---|---|
| `schema_version` | 整数；必填 | 本版为 `2`；建议拒绝 `2.0`、`true`、字符串 `"2"` | 无默认 |
| `runtimes` | ID→Runtime；必填 | 至少一个；禁止未登记 adapter | 无默认 |
| `profiles` | ID→Profile；必填 | 至少一个；runtime 引用必须存在 | 无默认 |
| `roles` | RoleBindings；必填 | 本建议要求 supervisor/planner/executor；observer 可省略 | observer 缺省为 disabled |
| `policies` | 项目追加限制；可选 | 只收紧受信策略，不能替代或扩大它 | 不新增限制；旧策略始终存在 |
| `platforms` | 平台→平台声明；可选 | 只声明 shell/工具选择，不授予模型工具能力 | 不自动创造 shell 或工具 |
| `_...` | 经登记位置上的说明字符串；可选 | 见 4.2.3，不能充当行为配置 | 不进入规范化语义 |

ID 建议使用 `^[a-z][a-z0-9-]{0,63}$`，区分大小写，不自动改写。模型 ID 不套用这一简化正则：模型名称的字符集、provider 需求和合法值由 adapter Schema 定义；核心只要求非空明确标识。

本版为避免旧协议被意外收紧，只把“整数 token 必须是整数表示”作为新配置建议。JSON Schema 的 `integer` 本身可能接受数值等于整数的 `2.0`，因此严格表示约束需要解析后/应用层额外检查。[^R08]

#### 4.1.3 Runtime 字段

| 字段 | 类型/必填 | 语义与限制 |
|---|---|---|
| map key | 稳定 runtime ID | 不是路径，不重复写另一份可冲突的 `id` |
| `adapter` | ID；必填 | 只能引用受信注册表中的已有适配器，不是包名、URL 或任意类名 |
| `command` | 非空字符串数组；必填 | 命令模板；不得用一个 shell 命令字符串代替 |
| `command_by_platform` | 平台→非空字符串数组；可选 | 某个平台存在时整段选择该分支；不存在时使用已声明的 `command` |
| `_...` | 说明字符串 | 只在 Runtime 记录本身允许，不改变运行行为 |

**命令数组不是“免审通道”。** `command[0]` 是待定位入口，`command[1:]` 是固定参数。adapter 应定义允许的固定参数与归属，核心不能允许重复的 `--model`、`--provider`、权限开关、认证值、endpoint 或后置参数把锁定 profile 覆盖掉。

参数按来源建议分成：核心控制参数、profile 模型参数、受审固定参数、任务输入。每类由唯一组件生成，出现重复 ownership 或无法解释的冲突时拒绝；不能简单按“最后一个参数有效”处理。

本建议的最小实现只允许直接入口或已登记的受信 launcher。`sh -c`、`cmd /c`、PowerShell 动态脚本、下载后执行、`npx` 即时安装等不属于默认支持范围。新增支持必须由 04/05 描述完整入口链、代码身份和参数边界。

Python 文档说明，普通 `subprocess` 调用不会隐式选择 shell，但 Windows 的 `.bat`/`.cmd` 仍可能经系统 shell 解析。因此，“使用 argv 数组”和“`shell=False`”不能作为 Windows 所有 launcher 的完整安全证明。[^R02]

#### 4.1.4 Profile 字段

| 字段 | 类型/必填 | 核心职责 | adapter 职责 |
|---|---|---|---|
| map key | profile ID | 稳定引用；角色只引用已存在 ID | 不根据 ID 猜模型 |
| `runtime` | ID；必填 | 验证引用存在 | 不擅自换 runtime |
| `model` | 对象；必填 | 至少有非空 `id` | 完整字段、provider 必填性、允许值、模型证据要求 |
| `options` | 对象；可选 | 省略展开为 `{}` 后仍必须校验 | 思考级别、输出模式等选项，不强制采用 Pi 字段 |
| `credential_refs` | 引用数组；可选 | 只准引用形状，不存认证值 | 认证名称、绑定方式、获取与使用由所选 CLI 管理 |
| `_...` | 说明字符串 | 限定在 Profile 记录本身处理 | model/options 内的说明规则须由 adapter 单独登记 |

核心不为 model/provider/thinking 填默认值。Schema 中的 `default` 只是描述性注解，并不会在标准验证过程中自动填入字段；默认展开必须是显式、已版本化的解析规则。[^R04]

本版只建议少量结构默认：`options={}`、`credential_refs=[]`、observer disabled、未声明项目追加限制。若 adapter 必须提供 `thinking`，空 options 仍然失败；不能把 `{}` 解释成“请 CLI 自己挑选”。

不引入 `extends`、profile 继承、动态模板变量、任意插值、通配模型选择或自动 fallback 链。未来需要这些功能时，应独立设计循环检测、冲突优先级、默认来源与新的快照版本。

#### 4.1.5 角色绑定与能力

| 角色 | 本建议形状 | 必须检查 | 不得推导 |
|---|---|---|---|
| supervisor | `{"mode":"current_session"}` | 当前监督方式可登记 | 当前主会话模型已被配置改变 |
| planner | `{"profile":"planning"}` | profile 存在、策略允许、adapter 满足规划能力 | planner 自动有受保护文件写权限 |
| executor | `{"profile":"implementation"}` | profile 存在、策略允许、执行能力与合同要求匹配 | executor 自动获准启动或集成代码 |
| observer | `{"mode":"disabled"}` 或 `{"mode":"external","profile":"..."}` | disabled 不发起调用；external 独立校验与记账 | “observer”名字本身保证只读 |

`current_session` 以外的 supervisor 模式不在本次最小建议中开放。observer 的只读性应由实际工具授权、工作区/路径控制和执行边界共同落实，不能只靠一个角色字段。

能力声明和权限不同：adapter 的 `structured-events` 或 `model-identity` 说明它能提供什么协议证据；独立策略决定是否可用；合同和审核决定本次是否获准。三者缺一不得启动。

同一 profile 同时被多个角色引用时，配置内容可以去重，但每个角色仍须单独检查允许条件；后续每次调用生成独立 `run_id`，预算根仍归同一 `request_id`。[^P01]

#### 4.1.6 独立策略与项目追加限制

原文没有规定新策略字段的精确 JSON 键。本版提出 `policies` 作为**新建议字段**，其作用仅为追加限制，不替代既有配置中已实现的策略。正式字段映射以旧基线取证与批准后的 Schema 为准。

| 约束类别 | 合成示例字段 | 合并规则 | 空集合含义 |
|---|---|---|---|
| 模型允许列表 | `allowed_models` | 与受信策略取交集，按 adapter/provider/model 身份比较 | 禁止任何模型，不是 unrestricted |
| 角色可选 profile | `role_profiles` | 对指定角色取交集 | 该角色不能选择 profile |
| 可传入环境名 | `environment_allow_names` | 允许名取交集，拒绝项仍优先 | 不允许传递任何非必要登记变量 |
| 额外保护路径 | `protected_paths` | 与既有保护路径取并集 | 不新增保护；不能删掉既有保护 |
| 必需能力/审核要求 | 来自受信策略 | 项目只能更严格，不能声明无需审核 | 不以缺字段关闭要求 |

形式化地，02 可做的静态允许判断为：

```text
static_allowed = legacy_or_host_policy(selection)
                 AND project_restrictions(selection)
                 AND adapter_static_contract(selection)
```

启动阶段仍须叠加合同范围、当前授权、撤销状态、预算、环境锁和实际能力核验。`static_allowed` 不能作为这些控制的替代。

最小策略实现不能只比对 `model.id`：两个 adapter/provider 下的同名模型不是当然相同。若模型还依赖部署、区域或 endpoint 身份，adapter 应在完整模型身份或安全语义绑定中明确表达，不能被当作机器噪声删除。

#### 4.1.7 平台声明与本机覆盖白名单

`platforms.<platform>.shell` 建议声明 shell kind 与命令数组；`tools.<tool_id>` 声明工具命令数组。声明 shell 只告诉 05 如何准备相应工具，不表示该角色已经拥有执行 shell 命令的权限。

建议 local 只开放以下字段：

| local 字段路径 | 允许操作 | 前提 |
|---|---|---|
| `/runtimes/<id>/executable_by_platform/<platform>` | 替换选中 runtime 命令的第 0 个元素 | runtime 已存在；平台有效；路径校验通过 |
| `/platforms/<platform>/shell_executable` | 替换已声明 shell 的入口位置 | 项目已声明相同平台及 shell |
| `/platforms/<platform>/tools/<tool_id>` | 替换已声明工具的入口位置 | 项目已声明该平台与工具 |
| `/schema_version` | 明确 local 版本 | 必须匹配支持版本 |
| 顶层说明字段 | 保留本机说明 | 只作为说明；不参与语义 |

local **不得新增 runtime/profile/role，不得替换整个 command 数组，不得改变参数顺序或尾部，不得改 model/options/policies/capabilities/plugin trust/审核要求/环境允许列表**。无论该条目是否被此次选择，越界覆盖都应拒绝。

local 路径建议要求显式绝对路径，不展开 `~`、`${VAR}`、`%VAR%` 或相对当前目录。Windows `C:tool.exe` 是本建议拒绝的驱动器相对形式；UNC、网络盘、设备路径和可变 launcher 默认不开放，确有需求时由 05 增加经过审核的平台规则。词法检查不能代替真实文件系统、符号链接、junction、权限及入口身份核验。

#### 4.1.8 凭据与环境变量

仅建议两种引用形状：

```json
{
  "credential_refs": [
    {"kind": "env", "name": "FIXTURE_A_TOKEN"},
    {"kind": "cli_store", "binding_id": "fixture-account-binding"}
  ]
}
```

这是**引用结构示意**，不是推荐使用两个认证来源，也不是已存在的账号。引用数组必须拒绝重复；是否允许多个凭据源、其选择顺序以及账户/endpoint 绑定，由 adapter 明确规定。没有明确策略时禁止自动尝试多个账号。

`env` 引用只记录变量名，不读取或保存变量值；02 可以要求后续检查是否存在，认证仍由 CLI 管理。`cli_store` 使用受控逻辑绑定，不是令牌、用户名密码组合、任意文件路径或带认证参数的 URL。安全账号范围可用受控 binding/version 标识表达，不能把低熵秘密的普通 SHA-256 当作公开脱敏形式。[^P01R]

严禁直接把父进程环境整体交给 CLI。05 应按既有过滤规则构造子进程环境，特别检查加载器、代理、CLI 全局配置、自动更新、工作目录、认证目录和模型覆盖变量。必要的安全行为值必须显式纳入语义或安全绑定，不是把所有环境值一概删掉。

Windows 环境名应按平台语义处理大小写冲突；Python 的 Windows `os.environ` 会把键转成大写，因此不能把 `Path` 与 `PATH` 当作两个独立授权槽位。这个规则不扩展到 model/profile ID 的任意大小写改写。[^R06]

闭合字段和引用类型可以阻止已知内联凭据入口，但不能数学上识别任意字符串是否为秘密。说明文本、模型名、参数和 URL 还应经过受控泄密检测；发现疑似秘密时拒绝发布相关输出，且不在错误中回显。参考实现只证明特定非法字段/值的拒绝与不回显，不声称实现完整秘密扫描。

### 4.2 解析与校验

#### 4.2.1 顺序不等于覆盖权限

保留原文“项目配置 → 本机路径覆盖 → 明确 profile 选择 → 平台选择”的处理关系。实际实现应区分**声明验证、角色选择、平台实例化**：local 可先解析为受限补丁集，再在选定平台分支上只替换入口位置。不能把这个顺序实现为四次通用字典合并。[^P02]

| 层/输入 | 可以影响 | 不能影响 |
|---|---|---|
| 项目配置 | 已批准 Schema 内的声明与追加限制 | 独立策略的最低安全边界 |
| local | 预定义入口/工具定位 | 模型、角色、固定参数、信任与权限 |
| 显式选择 | 指定角色选择哪个现有 profile | 构造临时 profile 或替换 profile 字段 |
| 平台选择 | 选择声明的命令分支和工具定义 | 自动创造新 adapter 或解释未知 platform |
| 环境预检 | 确认定位到的实际事实 | 反过来用“机器上可用的模型”改掉语义快照 |

#### 4.2.2 确定性流水线

| 阶段 | 操作 | 失败例 | 成功产物 |
|---|---|---|---|
| P00 | 固定输入字节与受信上下文 | 读取越界、输入代际不一致 | 不可变输入集合 |
| P01 | 限额、UTF-8、JSON 文法、重复键、数值/Unicode 检查 | 重复键、NaN、超大/超深输入 | 严格解析对象 |
| P02 | 明确配置家族与版本 | v2 调用收到无版本或未知版本 | 固定版本分支 |
| P03 | 核心结构及说明字段资格检查 | 未知字段、null、不合法 ID | 已知结构 |
| P04 | 受限 local 验证与目标引用检查 | 新增 profile、整个 command 覆盖 | 位置补丁集 |
| P05 | adapter 注册与所有 profile 的扩展字段检查 | 缺 adapter、provider/选项不合法 | 全量静态有效声明 |
| P06 | 角色范围与显式 profile 选择 | 悬空引用、重复选择、disabled observer | 选中角色绑定 |
| P07 | 平台分支与本机位置实例化 | 未知平台、非法 locator、无必需声明 | 执行意图，不启动 |
| P08 | 对所选角色执行独立策略与能力检查 | 允许列表不命中、缺能力、凭据名未许可 | 受限静态有效配置 |
| P09 | 计算依赖闭包、默认来源和语义投影 | 无法分类的行为字段 | 语义候选与环境计划 |
| P10 | 按 01 固定序列化；生成候选字节及引用 | 序列化或存储失败 | 待 03 审核的资源 |

全量静态验证包含所有声明条目的结构、adapter/引用和模型选项合法性；未选择条目不做实际 CLI、路径存在性或认证探测。独立运行策略只对本次选中角色计算；可以另提供全量 lint 结果，但不得替未选择模型自动发起网络调用。

这解释了一个重要区别：**修改未选择且仍然合法的 profile 可以不改变当前语义快照；把未选择 profile 改成坏 JSON、未知字段或悬空引用仍可阻止新解析。** “依赖范围无关”不等于允许配置文档结构损坏。

#### 4.2.3 说明字段：允许位置、形状与处理时机

建议允许的说明名为 `^_[A-Za-z][A-Za-z0-9_]{0,63}$`，值为最多 4,096 个字符的字符串；只允许出现在附录 Schema 显式登记的对象记录上。数字 4,096 是本版建议的输入上限，不是既有项目参数。

| 位置 | 是否由核心处理 `_...` | 原因 |
|---|---|---|
| 项目根、Runtime/Profile 记录、角色记录、项目策略、平台/shell/工具记录 | 是，先验证再移除 | 已登记的配置说明位置 |
| `runtimes`、`profiles`、`tools` 等动态 ID 映射的键 | 否 | 这里的键是身份，不是任意说明槽位 |
| adapter 的 `model`、`options` 内 | 默认否 | 必须由 adapter Schema 独立决定，核心不递归猜测 |
| `ResourceRef`、合同、审核、插件 Manifest/lock | 否 | 原文明确不适用此例外 |

建议拒绝 `_model`、`_permissions`、`_policies`、`_command`、`_schema_version` 等冒充语义字段的说明名；具体保留名清单必须版本化。该清单只是辅助诊断，不是安全的唯一保证：**下游必须只消费经过允许字段投影的规范化对象。**

顺序为：严格 JSON → 结构与说明形状校验 → 拒绝保留名冒充 → 按允许位置删除说明 → 校验 adapter 扩展对象 → 构造快照。不能先递归去掉下划线字段再做未知字段检查。[^P01R]

#### 4.2.4 adapter Schema 的注入与信任

每个受信描述符建议至少携带：adapter ID、描述符/协议版本、model Schema、options Schema、能力声明、固定参数合同、规范化行为版本，以及这些内容的固定资源身份。02 只消费注入对象，不从项目配置导入代码、执行探针、下载安装适配器或访问任意 Schema URL。

核心层可以只对 `model` 确保对象及 `id` 的最低约束，对 adapter 专有内容暂时开放；但这只是**委托验证的中间形态**，不能标记为完整通过。随后必须由该 profile 对应的 adapter Schema 完整校验并关闭未声明扩展字段。

若使用 `allOf` 组合封闭对象，需要注意 `additionalProperties` 只识别同一 subschema 中声明的字段；可选择分别验证核心壳与完整扩展，或在合适位置使用 `unevaluatedProperties`，不能以为组合后未知字段自然被关闭。[^R03]

Schema 引用只从固定本地 registry 解析，未知 `$ref` 拒绝；不得自动读取任意 `http`、`file` 或插件路径。`jsonschema` 的新 `referencing.Registry` 可采用受控注册资源，不自动抓取网络引用；显式添加网络 retrieve 会引入额外安全边界，本模块不需要该能力。[^R05]

adapter Schema 的 hash 相同不单独证明来源可信；注册表的发布、验证和受保护代码边界必须由 04/现有可信核心保证。描述符的能力也只是静态合同，真实 CLI 能力由预检及运行证据确认。

#### 4.2.5 严格输入与资源上限

原文要求拒绝未知 Schema、未知字段、非法模型、占位符、空命令及悬空引用；01 还要求拒绝重复 JSON 键和非有限数。[^P01][^P02]

本建议采用 1 MiB 输入、64 层容器深度、每组最多 256 个声明项、命令最多 64 个 token，作为最小实现的可审限制；需要提高时修改明确的限制版本并增加负载测试，不偷偷放开。文件读取器应在读入内存之前限额，参考函数还会对已传入 bytes 做二次限额。

Python 默认 JSON 解码可能保留重复字段的最后一个值，也接受非有限数；输出 `allow_nan=False` 不能保护输入端。应使用重复键检查、非有限常量拒绝及解析后溢出/Unicode 检查。[^R01]

多重损坏输入不承诺所有实现返回相同的“第一错误”。验收使用单一故障夹具，检查稳定错误家族与字段归属。空白字符串不等同于缺失，`null` 不等同于结构默认；模型 ID 不自动 trim/大小写折叠/Unicode 归一化后接受。

#### 4.2.6 字段来源报告

完整实现应为每个最终叶字段或明确的整体原子对象保留来源：`source_kind`、源资源引用、JSON Pointer、覆盖链、选中平台分支、默认规则版本和输出字段位置。来源报告不进入配置语义快照，否则显式选择同一 profile、调整注释或源文件格式都会导致无谓失效。

示意来源记录：

```json
{
  "output_field": "/runtime_locators/coding-cli/requested_executable",
  "source_kind": "local",
  "input_field": "/runtimes/coding-cli/executable_by_platform/linux",
  "overrides": [
    {"source_kind": "project", "input_field": "/runtimes/coding-cli/command/0"}
  ],
  "classification": "environment_locator",
  "value_visibility": "restricted_environment_record"
}
```

字段位置建议采用 RFC 6901 JSON Pointer；键中的 `~`、`/` 要正确编码为 `~0`、`~1`，不能用无法解析的随意点分路径。[^R09] 原始解析器不能精确提供位置时，报告文档根或已知父对象并标明定位粒度，不捏造行列。

#### 4.2.7 诊断与错误家族

| 错误/家族 | 典型触发 | 修复方向 |
|---|---|---|
| `E_JSON_*` | 编码、重复键、溢出、深度、文法 | 修正源文件，不默认替换为空对象 |
| `E_CFG_VERSION` | 版本缺失、未知或调用分支不符 | 明确采用已支持版本/显式兼容入口 |
| `E_CFG_UNKNOWN_FIELD` / `E_CFG_SCHEMA` | 未声明字段、必填项或类型不符 | 检查字段路径；不是让 local 改更深一层 |
| `E_CFG_NOTE_SHADOW` | 说明冒充模型/权限/命令 | 把真正语义放入已定义字段，重新审核 |
| `E_CFG_REFERENCE` / `E_CFG_ADAPTER` | 悬空 profile/runtime 或缺 adapter | 补齐登记；不要猜 CLI |
| `E_CFG_ADAPTER_SCHEMA` | provider、模型或选项不合 adapter 合同 | 使用该 adapter 的真实受信 Schema |
| `E_CFG_COMMAND_ARGS` | 固定参数包含冲突或未支持选项 | 移到正确拥有者或提出 Schema 变更 |
| `E_CFG_PATH` / `E_CFG_PLATFORM` | 路径词法、平台或覆盖目标错误 | 修正路径/平台，后续仍须真实预检 |
| `E_CFG_POLICY` / `E_CFG_CAPABILITY` | 允许列表拒绝、角色能力不足 | 走正式策略/能力变更，不临时绕过 |
| `E_CFG_LEGACY_ENV` | v2 环境存在旧 Pi 覆盖变量 | 使用明确清洁的 v2 启动环境 |
| `E_SCHEMA_REFERENCE` | adapter Schema 依赖无法离线解析 | 在受信 registry 中提供固定依赖 |
| 建议集成家族 `E_CFG_DRIFT` / `E_CFG_POLICY_REVOKED` | 输入或当前安全状态变化 | 重新解析/预检/审核；不能使用缓存成功结果 |

诊断遵循 01 的 `code`、`message`、`details`、`retryable` 结构。新增 code 须与公共错误注册表协调，不能改变旧 CLI 退出码含义。静态配置错误一般 `retryable=false`；即使外部瞬态错误可重试，也不表示允许自动发起模型调用。[^P01]

**禁止直接输出验证库的原始 `ValidationError.message`、instance、schema dump 或完整 traceback。** 这些内容可能包含被拒绝的令牌、URL 或模型字符串。对未知字段只报告已知父对象与安全字段类别；如未知键自身可能含秘密，展示 `unknown-field` 而非原始键。oneOf 分支错误应定位到匹配 kind/mode 的分支，不能给出另一个无关分支的修复建议。

#### 4.2.8 输入一致性、并发和缓存

解析函数应接收一次捕获的不可变输入集合，不在解析中反复读取磁盘、`os.environ` 或 registry。正式系统需要明确配置读取与发布的一致性机制，例如单写者锁或固定 generation manifest。简单“再读一遍没有变化”能发现部分竞争，但不能被描述为多个文件的原子快照。

配置缓存只能缓存已验证对象、已编译 Schema 或已发布不可变资源；缓存键至少绑定输入身份、投影版本、所选角色/profile、平台、adapter 描述符和策略身份。仅以文件 mtime、路径或 profile 名为键不够。机器预检缓存另按入口指纹、环境/认证绑定及有效期管理。

新配置加载失败时，旧成功记录保留为历史证据，但不能冒充当前有效配置来启动新 run。已经运行的 run 是否继续、取消或停止扩展权限，由 03/07 的安全状态决定，不由 02 擅自杀进程或热替换模型。

### 4.3 快照和环境分离

#### 4.3.1 字段分类规则

| 字段/内容 | 语义快照 | 环境记录/其他证据 | 处理原则 |
|---|---|---|---|
| 所选 role/profile/runtime/adapter 身份 | 保留 | 可重复作为关联 | 不运行时重新跟随名称 |
| model、provider、思考与其他行为选项 | 保留完整验证后值 | 实际模型证据另存 | 不由 CLI 默认覆盖 |
| `command[0]` 机器 locator | 不保留路径本身 | 保留请求位置、实际入口及指纹 | 只删除已分类定位信息，不删除命令身份约束 |
| `command[1:]` 固定参数 | 按原顺序保留 | 可供运行核对 | 参数变更不能因 command 属于环境而被忽略 |
| 选中平台与 shell kind/工具语义 | 保留 | 实际工具位置另存 | 本建议保守地把目标平台纳入语义 |
| 核心 Schema 与 adapter Schema/能力/参数合同引用 | 保留固定身份 | 实现 build/入口指纹另存 | 规则或描述符变更必须可检测 |
| 相关允许列表、环境名、保护路径 | 保留 | 当前策略判定与撤销证据另存 | 不能冻结旧允许决定 |
| endpoint、部署、账户范围的安全绑定 | 保留安全语义或引用 | 实际认证绑定另存 | 不因为是 URL 就当成机器路径 |
| 原始凭据值、密码、令牌 | 禁止 | 不进入普通环境锁/报告 | 仅由凭据/CLI 认证系统管理 |
| 注释、说明、输入格式、键排列 | 去除/规范化 | 安全源证据可留存 | 不直接作为语义门禁 |
| 时间戳、运行 ID、源文件行号 | 不保留 | 报告、RunContext、来源记录 | 避免每次解析产生新语义 |
| 未选择且静态合法的 profile 内容 | 不保留 | 完整源证据可追溯 | 不以其内容变化自动影响当前闭包 |

**重要限定**：若 command 使用解释器加脚本，例如 `python /path/agent.py`，脚本并非当然可删除的机器噪声。最小实现应拒绝未登记的 wrapper；扩展实现必须记录解释器、脚本、模块/包等完整入口链的逻辑身份、内容指纹和受审参数。不能仅指纹 `python` 可执行文件就说已锁定 agent 行为。

#### 4.3.2 依赖闭包算法

从调用明确要求的角色集合开始，不自动把所有已声明 profile 放进快照。建议如下：

```text
1. 验证整份项目/local 的静态合法性。
2. 固定 role_scope 及显式 profile 选择。
3. 加入核心 Schema/投影规则身份；对每个选中 role：加入 role binding → profile → runtime → adapter descriptor。
4. 对选中平台：加入实际被选择的命令参数分支和所声明工具语义。
5. 加入适用于这些角色的策略输入、环境名与凭据/目标安全绑定。
6. 对所有引用资源展开受信依赖；用 visited 集合去重，用 active 集合检测环。
7. 形成可解释的闭包与字段分类，再生成语义快照。
8. 源文件整体字节 hash、解析时间、原始位置等进入来源报告，不混入语义。
```

最小安全实现可以保守地绑定全部**共享策略对象**；不能确定一个策略子项是否无关时，宁可重新审核。本版参考实现对共享 host/project 策略整体绑定，对未选 profile 和未选平台命令分支做裁剪。更细粒度的策略依赖投影是后续优化，不是假定已经实现。

对于旧合同已经显式锁定“整个配置原文件 hash”的情况，仍按该合同执行：注释或无关 profile 变化也可能导致旧合同失效。本建议的细粒度失效规则不能悄悄削弱既有更严格锁定。

#### 4.3.3 确定性序列化与哈希

复用 01 的确切表达式，不另造 JCS 或语言无关“语义相同”算法：[^P01]

```python
snapshot_bytes = (
    json.dumps(
        semantic_projection,
        ensure_ascii=False,
        sort_keys=True,
        separators=(",", ":"),
        allow_nan=False,
    ) + "\n"
).encode("utf-8")
snapshot_sha256 = hashlib.sha256(snapshot_bytes).hexdigest()
```

输出 UTF-8、无 BOM、结尾一个 LF；字符串不做 Unicode 归一化。对象键排序；命令与其他有序数组保持顺序。明确声明为集合的字段，如允许列表、保护路径、环境名、凭据引用，先拒绝重复，再按本投影版本规定的确定性键排序；不能把所有数组都排序。

本版参考集合顺序采用 `stable_bytes(item)` 的字节序；角色到 profile 的字符串集合采用字符串顺序。正式实现需锁定这些规则，不在库升级后默默改变。跨语言实现必须通过同一黄金向量，而不是只比较解析后的 JSON 对象。

资源文件不内嵌自己的 hash。独立 `ResourceRef` 使用 01 的 `kind`、`id`、`sha256`，文件资源还需 `path`。本版提出的 `config-snapshot`、`environment-plan`、`adapter-descriptor` 等 kind 要在资源注册表中正式登记；示例 hash 只用于人工合成字节。[^P01][^P01R]

#### 4.3.4 环境计划不等于环境锁

`EnvironmentPlan` 只能记录“打算使用哪里”。`EnvironmentRecord` 至少应由负责模块实际确认：目标平台、真实解析路径、入口链、CLI 版本原始证据、入口指纹、协议能力、工具/认证绑定以及与哪个配置快照关联。路径不可读、指纹未知或不能证明模型控制能力时，不填猜测值并标为 PASS。

环境预检须区分静态文件检查与可能启动 CLI 的探测。运行 `--version` 也在执行目标程序；02 的静态 validate 不自动触发。探测权限、网络范围和预算责任由正式合同与 03/04/05 明确，不借预检名义绕过授权。

同一语义快照下改变路径，至少需要新的环境预检。是否复用原审核由 03 的锁策略决定；不能从“配置 hash 没变”推导“无需重新审核”。同一路径但文件内容、链接目标、插件加载路径或账号范围变化同理。

#### 4.3.5 变更与失效矩阵

| 变化 | 语义引用 | 环境动作 | 审核/运行行为 |
|---|---|---|---|
| 合法说明字段或 JSON 排版变化 | 本建议不变 | 无须仅因排版预检 | 原文件锁另有要求时从其要求 |
| 显式重新选择同一 profile | 不变，来源不同 | 不因选择来源重复探测 | 不生成虚假的新模型决定 |
| 所选 model/options/固定参数变化 | 改变 | 按新意图预检 | 新候选；原审核不得复用为新语义 |
| local 入口位置变化 | 不变 | 必须预检并记录新环境 | 03 判定环境锁是否允许迁移 |
| CLI 同路径升级或被替换 | 通常不变 | 指纹/能力改变，旧环境锁不可冒用 | 重新预检，必要时重新审核 |
| 核心 Schema 或所选 adapter 描述符变化 | 改变 | 核对实际实现能力 | 不仅按相同 ID/版本号继续 |
| 未选 profile 内容改变且全量静态有效 | 不变 | 不探测该 profile | 按依赖范围处理 |
| 未选条目变成非法配置 | 不生成新的合法结果 | 不启动新 run | 保留旧证据但不以缓存成功兜底 |
| 共享策略收紧、模型撤销 | 可能改变；当前拒绝优先 | 不靠旧环境锁绕过 | 阻止新启动；在途处置归 03/07 |
| 凭据轮换、绑定身份未变 | 凭据明文不入语义 | 核验新的安全绑定/版本 | 03 决定是否重新授权 |
| 账号、租户、endpoint 或外发范围变化 | 安全语义/绑定应改变或判漂移 | 重新核对认证和目标 | 不得把它当纯路径迁移 |
| 从 linux 改为 windows | 本建议改变 | 进行 Windows 实测 | 不以 Linux 词法测试代替平台验收 |

#### 4.3.6 固定快照的消费规则

正式合同保存 profile 逻辑引用及**解析后快照 ResourceRef**。启动时校验固定资源的完整字节，使用已固定对象；不得读取当前同名 profile 再生成另一组参数。引用的 `path` 仅用于定位，不能代替 hash 或来源验证。[^P02]

推荐交接顺序：

```text
02：验证并封存配置语义候选
  → 04/05：按明确授权取得环境/能力证据
  → 03：将配置、环境、合同与其他 input_refs 作为审核输入
  → 启动前：核验固定资源、当前策略/撤销、环境锁及批准的启动条件
  → 04/07：按同一固定输入创建 run，不重新解析可变 profile 名
```

检查与使用之间的竞争不能只靠“启动前又看了一次 hash”完全解决。03 应定义启动准入的线性化点、撤销 epoch/版本与在途处理；04/05 应降低路径被替换的窗口并按平台能力验证同一入口对象。数据库批准与操作系统创建进程不是天然原子事务；具体保障及残余风险必须由负责模块的实现与故障测试证明。

静态描述符或 CLI 自报的模型名并不是对远端实际权重的密码学证明；系统只能按所获得的可靠协议证据与供应方信任边界报告。缺少实际模型确认能力时应明确阻塞或限制用途，不伪称完成模型锁定。

#### 4.3.7 发布、缓存与失败补偿

| 失败窗口 | 处理 | 禁止行为 |
|---|---|---|
| 解析/校验失败 | 只输出安全诊断，保留上次历史证据 | 发布部分新快照 |
| 临时快照写入失败 | 标记候选失败，清理自己的临时文件 | 使用截断文件生成引用 |
| 文件已封存，引用登记失败 | 作为未引用候选保留，幂等补偿 | 先发出一个尚不可读取的引用 |
| 环境预检失败 | 保留失败证据，不生成有效环境锁 | 更换一个“能运行”的模型继续 |
| 审核前配置/策略变化 | 按固定候选与当前守卫重新评估 | 修改已审核文件内容来保持原路径 |
| 核验后资源消失或 hash 不符 | 拒绝消费，重新取证 | 从可变配置重建“差不多相同”内容 |
| 缓存命中但当前配置加载失败 | 阻止新启动 | last-known-good 自动兜底 |

文件发布应遵循 01 的不可变对象约定。原子替换与断电/崩溃后的持久性是不同保证，平台验证不能省略。[^P01R]

### 4.4 v1 边界

#### 4.4.1 显式版本分派

| 调用模式 | 配置情况 | 应采取的行为 |
|---|---|---|
| 明确 v2 | `schema_version: 2` 且合法 | 仅 v2 解析 |
| 明确 v2 | 缺文件、无版本、旧版本、未知版本或损坏 | 拒绝；不回落 v1 |
| 明确 v1 兼容 | 符合已取证 v1 形状 | 调用保留的 v1 路径，保持旧冲突/默认规则 |
| 明确 v1 兼容 | v2 文件 | 报版本不匹配；不忽略新字段 |
| 没有指定模式且配置也不足以判定 | 基线尚未确认 | 保持已取证的旧入口行为或要求明确选择，不能猜模型 |
| 读取历史合同/attempt | 旧 schema | 只按原 schema 解释，不倒写 v2 字段 |

“缺配置时旧工具是否有默认行为”属于待取证项；本文不编造答案。允许继续保留旧入口的无配置行为，不代表 v2 可以复制同样默认。

#### 4.4.2 旧环境变量

**原文保留**：`PI_EXEC_*` 与 `PI_DISPATCH_PI_CMD` 只在显式 v1 兼容路径读取；v2 不得用它们改写锁定值，潜在冲突要有可操作诊断。[^P02]

**新增建议的严格模式**：v2 入口只检查这些名称是否存在，不读取/比较其值；一旦存在就阻止该次 v2 解析，并提示采用明确清洁的子环境。空字符串也视为存在。这样无需为了判断“是否恰好相同”而暴露或解释旧模型配置。本规则比“只对不同值报错”更严格，应经批准后用于 v2，不能倒改 v1。

正式实现需按目标平台规范化变量名称后检查；Windows 的名称大小写处理归 05。参考代码接收调用者提供的规范化名称列表，不读取真实环境，不能把该局部测试视为 Windows 环境过滤完成。

清理只能作用于经过授权创建的子进程环境，不应由配置解析器偷偷修改用户 shell 或当前主会话。诊断不打印任何 `PI_EXEC_*` 值。

#### 4.4.3 只生成建议的迁移

迁移分为“提取旧事实”“生成映射建议”“人工审核”“获准应用”，不能合并成启动时自动升级。

| 旧事实 | 建议映射 | 必须保持 | 不能自动完成 |
|---|---|---|---|
| 已确认 provider/model/thinking | 对应 adapter 的 profile 字段 | 原值、字段意义与来源 | 从旧值推断一个看起来相似的新模型 |
| 旧 Pi 命令 | runtime 命令/兼容 locator 建议 | 原命令的解释方式及平台 | 无平台上下文地拆 shell 字符串 |
| `allowed_executors` | 保留的策略桥接/审核后映射 | 既有允许范围 | 变成“任意新 profile 都可用” |
| worktree、环境过滤、保护路径 | 保留策略依赖及现有入口 | 路径与限制的有效性 | 仅因迁移就删除旧检查 |
| Step/high | 原规则来源与拟映射记录 | 未获准前不改变选择 | 自动认定某个新 profile 等价 |
| 未识别旧字段 | `UNMAPPED` 项 | 原始来源与人工说明 | 丢掉未知字段后继续宣称等价 |

建议迁移输出包含 `source_refs`、`proposed_config_ref`、安全差异、保留字段映射、未决项、验证覆盖、`writes_performed=false` 和 `approval_required=true`。缺少真实 adapter 或旧字段事实时返回 `BLOCKED_MANUAL_MAPPING`；仍可给出可审草稿，但不能标为可直接执行配置。

迁移产物写到新的待审位置，不能覆盖当前 `.agent/dispatch.config.json`。原配置可能包含秘密时先按受控流程隔离；迁移报告不复制秘密值或未知敏感字段，不以回显旧配置实现 diff。

#### 4.4.4 应用与回退边界

实际应用必须另有明确授权，并绑定旧配置的预期身份、获准新候选、写入范围、备份/回退入口和执行人。应用前 compare-and-swap 检查不匹配即停止，不能覆盖刚被其他人修改的文件。

受保护调度器、AGENTS 和 `.agents/skills/` 的迁移仍由主模型在实施授权下直接完成；普通执行器不能通过扩大 Scope 获得写权限。历史合同和审核记录不能随配置迁移重写。[^P02]

## 6. 实施步骤

### 6.1 阶段 0：确认授权与基线

先确认实际 HEAD、工作区变化、允许文件、当前规则与测试环境；调查用旧提交不能直接视为实施基线。列出未提供的旧配置/策略/协议事实，把它们与新增设计项分别登记。[^P01]

只读调查命令示意：

```sh
git rev-parse --show-toplevel
git rev-parse --verify HEAD
git status --porcelain=v1
git ls-files --error-unmatch .agent/dispatch.local.json
git check-ignore -v .agent/dispatch.local.json
```

这些是实施时的取证命令，**本次没有在用户项目中运行**。`ls-files` 非零可表示未跟踪，`check-ignore` 非零可表示没有匹配忽略规则；不能把所有非零都当项目故障，也不能据此自动执行删除/停止跟踪。

### 6.2 阶段 1：冻结 v1 可观察行为

为缺配置、坏配置、模型来源、provider/thinking、`PI_EXEC_*` 冲突、命令覆盖、允许列表拒绝、保护路径、worktree 和环境过滤逐项取得基线。每项记录输入来源、调用命令、退出码、安全输出和预期判断。

旧入口回归命令沿用原文依赖 01 的 `python tests/test_dispatch.py`，实际解释器与执行范围由合同确定。未知项记 `NOT_RUN` 或 `UNKNOWN_BASELINE`，不编写一个新 fixture 后反过来声称它就是旧行为。

### 6.3 阶段 2：实现纯解析与限制合并

先实现闭合结构、严格 JSON、局部路径补丁、显式 profile 选择、模型/选项委托验证和安全诊断。用两个不同的合成 adapter 证明：一个要求 provider/thinking，另一个拒绝这些字段并使用不同选项；不能通过给所有 CLI 强加 Pi 参数达成所谓通用化。

每个失败用例必须证明没有调用进程启动接口、没有网络获取 Schema、没有修改原配置。复杂策略通过旧策略 facade 注入，不从头实现一份更弱的允许逻辑。

### 6.4 阶段 3：投影、来源与资源交接

生成固定语义字节及独立环境计划；对选中/未选字段变更分别验证 hash 行为。来源报告记录字段覆盖链，不进入语义摘要。接入 01 的资源发布/引用，不在配置模块临时实现另一个不兼容哈希算法。

交给 03 的接口只使用固定资源引用，不要求 03 认识具体厂商选项。交给 04 的是已固定 profile/runtime 与环境预检需求，真实 Schema/能力接线由 04 提供；02 的独立验收依然可使用 fixture。

### 6.5 阶段 4：迁移建议与差异报告

迁移只读旧配置，输出待审候选、保留行为映射和未决项。先证明 `writes_performed=false`，再验证敏感字段不外泄。无法可靠转换的命令或模型保持阻塞，不用宽泛 CLI 默认值“补全”。

建议未来 CLI 界面如下，**这些是接口草案，不是当前项目已存在命令**：


`validate` 默认不得启动 CLI。`explain` 默认脱敏；机器实际路径的完整展示只在有权环境报告中开放。`snapshot` 不自动审核，`migrate-v1` 不自动应用。任何实际执行入口另属于受控命令，不与配置解析混用。

### 6.6 阶段 5：获准接线、兼容与恢复演练

只有在授权明确后才调整受保护调度器、现行配置、忽略规则、AGENTS 与源技能。接线后分别运行旧回归、02 测试和 03/04/05 的交接测试；不要因新增测试通过而删除旧回归。

## 8. 兼容与恢复

### 8.1 兼容承诺的粒度

兼容不是一个总布尔值。至少分别记录：配置读取、模型选择、环境变量冲突、命令解释、策略判断、旧合同恢复、历史证据 hash、退出码及受保护文件权限。某项未取证不能因其他项通过而标记兼容。

v1 配置和历史合同继续按旧 schema 读取，v2 不倒写旧 attempt。无配置、错配置和旧环境变量须有明确版本分支；任何失败都不能静默降级到另一个模型。[^P02]

### 8.2 故障恢复决策

| 情况 | 操作人员动作 | 成功判据 | 失败升级 |
|---|---|---|---|
| 新配置语法/字段错误 | 修正待审文件，重新 validate | 结构/语义检查均通过且来源明确 | 交配置维护者，不切模型绕过 |
| local 覆盖越权 | 移除违规覆盖；保留安全诊断 | local 只包含白名单位置 | 交策略/平台负责人 |
| 找不到 CLI 或入口指纹不符 | 核对已获准入口，重新预检 | 与允许身份和协议能力一致 | 不自动安装，交 04/05 处理 |
| 模型不在允许列表 | 检查选错 profile 或发起正式变更 | 独立策略明确允许 | 不把允许列表改为空“恢复” |
| 存在旧 Pi 环境覆盖 | 用明确受控子环境重试 v2 | 变量名称检查通过，不改用户全局环境 | v1 需求走显式兼容入口 |
| 快照/引用损坏 | 隔离当前候选，保留证据 | 新资源字节与引用一致并重新交审 | 交资源/审核负责人 |
| 审核失效或策略撤销 | 停止新启动，重新提请审核 | 当前授权与环境一致 | 不恢复旧缓存授权 |
| 迁移失败 | 保留原配置与待审差异 | 原入口仍按基线可解释运行 | 受保护改动由授权主体处理 |

### 8.3 回退流程

先停止新增 v2 启动或切换到已批准的维护状态；记录在途 run，由 07 处理继续/取消边界。保留新配置候选、环境记录、失败诊断和审核记录，不清空 evidence 目录。

核对获准的旧入口、旧配置版本、原规则与当前策略，显式切回兼容路径。验证旧路径的实际基线后恢复工作，不借回退恢复已经撤销的模型或权限。回退完成后记录原因、涉及的资源引用、操作者、检查命令与结果。

回退不删除新审核记录、不重写历史 hash、不对 v1 原始证据重新格式化。未经授权，不覆盖现行配置、AGENTS、调度器或源技能。[^P02]

### 8.4 保留与清理

未引用候选、失败的临时文件和已发布快照需分别管理；只有确认为本次测试/任务创建、未被有效引用且满足保留策略的对象才能清理。不能把用户仓库或历史证据当测试临时目录。具体 GC、保留期和授权由对应资源管理模块定义，02 不自定“失败即全删”。

### A.2 Schema bundle 使用方法

### B.1 实现范围与明确缺项

本代码实现严格 JSON、v2 结构验证、限定位置说明清理、adapter 字段验证、引用与静态限制、路径覆盖词法、角色闭包、语义/环境计划分离及部分来源记录。输出为不可变字节，`launchable` 固定为 false。

下列事项仍是正文要求或后续模块责任，**不由该参考代码证明**：

| 未实现部分 | 仍需交付的保障 |
|---|---|
| 实际文件读取与源输入一致性 | 受控路径、文件身份、输入 generation、并发读写与缓存失效 |
| 完整逐字段来源 | 全叶子覆盖链、源文档引用、真实行列位置；示例仅输出选中角色/profile/入口的部分来源 |
| 真实平台环境预检 | realpath、symlink/junction、权限、入口链、版本与指纹、Windows 实际进程行为 |
| 任意 shell/工具参数解释 | 所有工具参数 ownership/安全合同；环境计划中保留 `tool_arg_contracts` 待检查 |
| 任意形态的秘密识别 | 全链脱敏和日志审计；闭合字段与 canary 不等于完整秘密检测器 |

| 资源封存与消费 | 文件持久化、不可变发布、资源注册、审核签发、原子准入与 TOCTOU 处理 |
| v1 与迁移工具 | 实际旧字段/冲突回归、只读建议、CAS 应用与回退 |
| 所有未选分支的物理有效性 | 纯静态配置不能探测各平台实际入口；不把本次未访问路径记为存在或可用 |

`core_schema_ref` 与 `descriptor_ref` 对应由 01 序列化表达式生成的**候选资源字节**，不是下方带缩进的 fixture 源文件原始字节。它们目前是尚未发布的内存候选身份；正式作为文件资源发布时，须补全受控 `path`、登记 kind 并固定完整快照，随后才能交给审核。不得把缺少文件定位的候选引用冒充已发布的文件 ResourceRef，也不得在审核后再修改快照中的引用。

本版保守绑定整份核心 Schema bundle 与所选 adapter 描述符；即使只改 bundle 的 `$comment`，引用也会变化。这是**Schema 资源版本策略**，不同于项目配置说明字段不参与语义的规则。未来缩小 Schema 依赖时须单独版本化，不能在同一投影版本里偷换 hash 域。

```python
def strict_load(data: bytes, source: str = 'project') -> dict[str, Any]:
    if type(data) is not bytes or len(data) > MAX_BYTES:
        fail('E_JSON_LIMIT', source=source)
    try:
        if data.startswith(b'\xef\xbb\xbf'):
            fail('E_JSON_ENCODING', source=source)
        text = data.decode('utf-8', errors='strict')
    except UnicodeError:
        fail('E_JSON_ENCODING', source=source)
    # A bounded lexical depth check prevents deep input reaching the recursive decoder.
    depth = 0
    in_string = escaped = False
    for char in text:
        if in_string:
            if escaped:
                escaped = False
            elif char == '\\':
                escaped = True
            elif char == '"':
                in_string = False

            in_string = True
        elif char in '{[':
            depth += 1

                fail('E_JSON_LIMIT', source=source)
        elif char in '}]':
            depth -= 1

        result: dict[str, Any] = {}
        for key, value in items:
            if key in result:
                fail('E_JSON_DUPLICATE_KEY', source=source)
            result[key] = value
        return result

        fail('E_JSON_NUMBER', source=source)
    try:
        value = json.loads(text, object_pairs_hook=pairs, parse_constant=constant)
    except (json.JSONDecodeError, RecursionError, ValueError) as exc:
        if isinstance(exc, ConfigError):
            raise
        fail('E_JSON_SYNTAX', source=source)
    stack = [value]

        item = stack.pop()
        if isinstance(item, dict):

            stack.extend(item.values())
        elif isinstance(item, list):
            stack.extend(item)

            or placeholder(value) or value.startswith('~') or '$' in value or '%' in value):
        fail('E_CFG_PATH', base, source)
    if not absolute and re.fullmatch(r'[A-Za-z0-9][A-Za-z0-9._+-]{0,127}', value):
        return
    path = PureWindowsPath(value) if platform == 'windows' else PurePosixPath(value)
    if (not path.is_absolute() or '..' in path.parts
            or (platform != 'windows' and '\\' in value)
            or (platform == 'windows' and (str(path.drive).startswith('\\\\') or '/' in value))):
        fail('E_CFG_PATH', base, source)


def command_check(argv: list[str], descriptor: dict[str, Any], base: str) -> None:
    if any(not x.strip() or any(ord(c) < 32 or ord(c) == 127 for c in x) for x in argv):
        fail('E_CFG_COMMAND', base)
    if any(placeholder(x) for x in argv):
        fail('E_CFG_PLACEHOLDER', base)
    if argv[1:] not in descriptor['fixed_arg_tails']:
        fail('E_CFG_COMMAND_ARGS', base)


def model_key(adapter: str, model: dict[str, Any]) -> tuple[str, Any, str]:
    return adapter, model.get('provider'), model['id']


def allowed_keys(policy: dict[str, Any]) -> set[tuple[str, Any, str]]:
    return {model_key(item['adapter'], item) for item in policy['allowed_models']}


@dataclass(frozen=True)
class Resolution:
    snapshot_bytes: bytes
    snapshot_sha256: str
    environment_plan_bytes: bytes
    provenance_bytes: bytes
    launchable: bool = False


def resolve(project_bytes: bytes, local_bytes: bytes | None, *,
            schema_bundle: dict[str, Any], adapters: Mapping[str, dict[str, Any]],
            host_policy: dict[str, Any], platform: str,
            requested_roles: Sequence[str] = ('planner', 'executor'),
            selections: Mapping[str, str] | None = None,
            legacy_environment_names: Sequence[str] = ()) -> Resolution:
    """Resolve an unapproved synthetic plan; caller cannot turn this into launch permission."""
    if platform not in PLATFORMS:
        fail('E_CFG_PLATFORM', '/platform', 'selection')
    if any(k.startswith('PI_EXEC_') or k == 'PI_DISPATCH_PI_CMD' for k in legacy_environment_names):
        fail('E_CFG_LEGACY_ENV', '', 'environment_names')
    raw = strict_load(project_bytes)
    bundle_check(raw, schema_bundle, 'Project', 'project')
    project = normalize_project(raw)
    local_raw = strict_load(local_bytes, 'local') if local_bytes is not None else {'schema_version': 2}
    bundle_check(local_raw, schema_bundle, 'Local', 'local')
    local = clean_record(local_raw, '', 'local')
    # In this reference host_policy is a trusted synthetic fixture, not arbitrary user JSON.
    check_schema(host_policy, {**schema_bundle, '$ref': '#/$defs/HostPolicyFixture'}, source='host_policy')
    host, limits = normalize_policy(host_policy), normalize_policy(project['policies'])
    for pol, src in ((host, 'host_policy'), (limits, 'project')):
        for path in pol.get('protected_paths', []):
            protected_path(path, '/protected_paths', src)
    runtimes, profiles = project['runtimes'], project['profiles']
    for runtime_id, runtime in runtimes.items():
        aid = runtime['adapter']
        if aid not in adapters or adapters[aid]['adapter_id'] != aid:
            fail('E_CFG_ADAPTER', f'/runtimes/{runtime_id}/adapter')
        desc = adapters[aid]
        command_check(runtime['command'], desc, f'/runtimes/{runtime_id}/command')
        for p, argv in runtime.get('command_by_platform', {}).items():
            base = f'/runtimes/{runtime_id}/command_by_platform/{p}'
            command_check(argv, desc, base)
            locator(argv[0], p, base + '/0', 'project', False)
    for pid, profile in profiles.items():
        if profile['runtime'] not in runtimes:
            fail('E_CFG_REFERENCE', f'/profiles/{pid}/runtime')
        if any(placeholder(str(v)) for v in profile['model'].values()):
            fail('E_CFG_PLACEHOLDER', f'/profiles/{pid}/model')
        desc = adapters[runtimes[profile['runtime']]['adapter']]
        for part in ('model', 'options'):
            check_schema(profile[part], desc[part + '_schema'], source='project',
                         base=f'/profiles/{pid}/{part}', code='E_CFG_ADAPTER_SCHEMA')
    for role, binding in project['roles'].items():
        if 'profile' in binding and binding['profile'] not in profiles:
            fail('E_CFG_REFERENCE', '/roles/' + role + '/profile')
    for rid, override in local.get('runtimes', {}).items():
        if rid not in runtimes:
            fail('E_CFG_REFERENCE', '/runtimes/' + rid, 'local')
        for p, executable in override['executable_by_platform'].items():
            locator(executable, p, f'/runtimes/{rid}/executable_by_platform/{p}', 'local', True)
    for p, override in local.get('platforms', {}).items():
        if p not in project['platforms']:
            fail('E_CFG_REFERENCE', '/platforms/' + p, 'local')
        declared = project['platforms'][p]
        if 'shell_executable' in override:
            if 'shell' not in declared:
                fail('E_CFG_REFERENCE', '/platforms/' + p + '/shell_executable', 'local')
            locator(override['shell_executable'], p, '/platforms/' + p + '/shell_executable', 'local', True)
        for tool_id, executable in override.get('tools', {}).items():
            if tool_id not in declared['tools']:
                fail('E_CFG_REFERENCE', f'/platforms/{p}/tools/{tool_id}', 'local')
            locator(executable, p, f'/platforms/{p}/tools/{tool_id}', 'local', True)
    roles = list(requested_roles)
    chosen = dict(selections or {})
    if (not roles or len(set(roles)) != len(roles) or not set(roles) <= RUN_ROLES
            or not set(chosen) <= set(roles)):
        fail('E_CFG_ROLE_SELECTION', '/roles', 'selection')
    snapshots, runtime_snapshots = {}, {}
    role_bindings = {'supervisor': {'mode': 'current_session'}}
    locators, provenance = {}, {}
    env_allowed = set(host['environment_allow_names'])
    if 'environment_allow_names' in limits:
        env_allowed &= set(limits['environment_allow_names'])
    for role in sorted(roles):
        binding = project['roles'][role]
        if role == 'observer' and binding.get('mode') != 'external':
            fail('E_CFG_ROLE_SELECTION', '/roles/observer', 'selection')
        pid = chosen.get(role, binding.get('profile'))
        if pid not in profiles:
            fail('E_CFG_ROLE_SELECTION', '/roles/' + role, 'selection')
        profile = deepcopy(profiles[pid])
        rid = profile['runtime']
        runtime, desc = runtimes[rid], adapters[runtimes[rid]['adapter']]
        key = model_key(runtime['adapter'], profile['model'])
        if (pid not in host['role_profiles'].get(role, []) or key not in allowed_keys(host)
                or ('allowed_models' in limits and key not in allowed_keys(limits))
                or (role in limits.get('role_profiles', {}) and pid not in limits['role_profiles'][role])):
            fail('E_CFG_POLICY', '/roles/' + role, 'policy')
        if not set(host['required_capabilities'].get(role, [])) <= set(desc['capabilities']):
            fail('E_CFG_CAPABILITY', '/roles/' + role, 'adapter_registry')
        for cred in profile['credential_refs']:
            if cred['kind'] == 'env' and cred['name'] not in env_allowed:
                fail('E_CFG_POLICY', f'/profiles/{pid}/credential_refs', 'policy')
        branch = platform in runtime.get('command_by_platform', {})
        argv = list(runtime['command_by_platform'][platform] if branch else runtime['command'])
        origin = f'/runtimes/{rid}/command_by_platform/{platform}' if branch else f'/runtimes/{rid}/command'
        override = local.get('runtimes', {}).get(rid, {}).get('executable_by_platform', {}).get(platform)
        locator_source = 'local' if override is not None else 'project'
        if override is not None:
            argv[0] = override
        locator(argv[0], platform, origin + '/0', locator_source, override is not None)
        if platform == 'windows' and argv[0].lower().endswith(('.bat', '.cmd')):
            fail('E_CFG_LAUNCHER_UNSUPPORTED', origin + '/0', locator_source)
        descriptor_ref = {'kind': 'adapter-descriptor', 'id': desc['adapter_id'],
                          'sha256': digest(stable_bytes(desc))}
        runtime_snapshots[rid] = {'adapter': runtime['adapter'], 'descriptor_ref': descriptor_ref,
                                  'argv_tail': argv[1:]}
        locators[rid] = {'requested_executable': argv[0]}
        snapshots[pid] = profile
        role_bindings[role] = {'profile': pid, **({'mode': 'external'} if role == 'observer' else {})}
        provenance['/roles/' + role] = {'source': 'selection' if role in chosen else 'project',
                                         'field': '/roles/' + role + '/profile'}
        provenance['/runtime_locators/' + rid] = {'source': locator_source,
            'field': f'/runtimes/{rid}/executable_by_platform/{platform}' if override is not None else origin + '/0'}
        for part in ('model', 'options', 'credential_refs'):
            provenance[f'/profiles/{pid}/{part}'] = {
                'source': 'project' if part in raw['profiles'][pid] else 'normalized_default',
                'field': f'/profiles/{pid}/{part}'}
    platform_semantics, platform_locations = {}, {}
    platform_config = project['platforms'].get(platform, {})
    platform_local = local.get('platforms', {}).get(platform, {})
    if 'shell' in platform_config:
        shell = platform_config['shell']
        command = shell['command']
        exe = platform_local.get('shell_executable', command[0])
        locator(exe, platform, '/platforms/' + platform + '/shell', 'project', False)
        platform_semantics['shell'] = {'kind': shell['kind'], 'argv_tail': command[1:]}
        platform_locations['shell_executable'] = exe
    platform_semantics['tools'], platform_locations['tools'] = {}, {}
    for tool_id, tool in platform_config.get('tools', {}).items():
        exe = platform_local.get('tools', {}).get(tool_id, tool['command'][0])
        locator(exe, platform, f'/platforms/{platform}/tools/{tool_id}', 'project', False)
        platform_semantics['tools'][tool_id] = {'argv_tail': tool['command'][1:]}
        platform_locations['tools'][tool_id] = exe
    semantic = {'schema_version': 1, 'kind': 'config-semantic-snapshot',
                'config_schema_version': 2, 'projection_version': 'config-projection-1',
                'core_schema_ref': {'kind': 'config-schema', 'id': 'config-bundle-v2',
                                    'sha256': digest(stable_bytes(schema_bundle))},
                'platform': platform, 'roles': role_bindings, 'profiles': snapshots,
                'runtimes': runtime_snapshots, 'platform_tools': platform_semantics,
                'policy_view': {'host': host, 'project_restrictions': limits}}
    snapshot = stable_bytes(semantic)
    sha = digest(snapshot)
    environment_plan = {'schema_version': 1, 'kind': 'environment-plan',
                        'status': 'PENDING_PREFLIGHT', 'platform': platform,
                        'config_snapshot_sha256': sha, 'runtime_locators': locators,
                        'platform_locators': platform_locations,
                        'pending_checks': ['locator_realpath', 'entry_fingerprints',
                            'cli_protocol', 'actual_model', 'tool_arg_contracts',
                            'credential_binding', 'current_policy', 'approval', 'budget']}
    return Resolution(snapshot, sha, stable_bytes(environment_plan), stable_bytes(provenance))
```

```python
"""Recompute synthetic vectors from adjacent files. Never discovers or runs a CLI."""
from __future__ import annotations

from copy import deepcopy
import json
from pathlib import Path

from config_reference import resolve, stable_bytes, digest

ROOT = Path(__file__).parent


def read(name: str) -> dict:
    return json.loads((ROOT / name).read_text(encoding='utf-8'))


def vectors() -> tuple[dict, object]:
    project = read('project.fixture.json')
    schema = read('config-bundle.schema.json')
    adapters = read('adapters.fixture.json')
    host = read('host-policy.fixture.json')
    local = read('local.fixture.json')
    rows = []

    def run(label: str, *, p=None, s=None, a=None, h=None, l=None,
            platform='linux', selections=None):
        result = resolve(stable_bytes(project if p is None else p),
                         None if l is None else stable_bytes(l),
                         schema_bundle=schema if s is None else s,
                         adapters=adapters if a is None else a,
                         host_policy=host if h is None else h,
                         platform=platform, selections=selections)
        rows.append({'id': label, 'snapshot_sha256': result.snapshot_sha256,
                     'snapshot_bytes': len(result.snapshot_bytes),
                     'environment_plan_sha256': digest(result.environment_plan_bytes),
                     'provenance_sha256': digest(result.provenance_bytes),
```

### E.1 从 Markdown 提取到全新隔离目录

可以手工把 13 个带 `artifact-file` 标记的代码块保存为对应文件，或把以下脚本另存为 `extract_reference.py`。脚本只允许固定文件名，拒绝重复或缺失项目，要求输出目录原先不存在，不执行提取内容，不写入项目配置。

```python
from __future__ import annotations
import argparse
from pathlib import Path
import re

EXPECTED = {
    "config-bundle.schema.json", "adapters.fixture.json", "host-policy.fixture.json",
    "project.fixture.json", "local.fixture.json", "config_reference.py",
    "test_config_reference.py", "golden-vectors.json", "verify_examples.py",
    "semantic-baseline.json", "semantic-baseline.ref.json",
    "environment-plan-baseline.json", "provenance-baseline.json",
}
PATTERN = re.compile(
    r"<!-- artifact-file: ([A-Za-z0-9_.-]+) -->\n"
    r"```(?:json|python)\n(.*?)^```[ \t]*$", re.MULTILINE | re.DOTALL
)

def main() -> None:
    parser = argparse.ArgumentParser(description="Extract only the isolated review fixtures.")
    parser.add_argument("markdown", type=Path)
    parser.add_argument("output", type=Path)
    args = parser.parse_args()
    text = args.markdown.read_bytes().decode("utf-8", errors="strict")
    if "\r" in text:
        raise SystemExit("Expected the supplied LF-only Markdown; preserve its original bytes.")
    records = {}
    for name, body in PATTERN.findall(text):
        if name not in EXPECTED or name in records:
            raise SystemExit("Unexpected or duplicate artifact name.")
        records[name] = body.encode("utf-8")
    if set(records) != EXPECTED:
        raise SystemExit("Missing artifact blocks; no files were written.")
    args.output.mkdir(parents=True, exist_ok=False)
    for name in sorted(records):
        target = args.output / name
        with target.open("xb") as handle:
            handle.write(records[name])
    print(f"Extracted {len(records)} files. No code was executed.")

if __name__ == "__main__":
    main()
```
